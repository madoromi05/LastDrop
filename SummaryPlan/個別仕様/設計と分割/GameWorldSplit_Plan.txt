0. 今の GameWorld（ヘッダ 292 行・実装 754 行）が持っている仕事
 ① 世界の状態（町・地面・建物・名簿 2 つ・飛ぶ弾・物の並び・ゾンビの群れ）
 ② 1 ティックの順番（入力 → 弾 → 命中 → エフェクト → ゾンビ → Late → flush → 湧かせる）
 ③ 組み立て（place・placeBuildings・placeMissionObjects・placeEscapeCar・placeFuelStation・placeFuel・createProp）
 ④ 命中（hitZombie・severLimb・dropAmmo、updateZombies の中の「腕が当たったら体力を減らす」）
 ⑤ エフェクトの寿命（弾痕・砂ぼこり・血しぶき・千切れた部位）
 ⑥ 使う物を探す（findInteractable・resolveInteractable・死体と弾の組・removeTakenPickups・appendPickupColliders）
 ⑦ 描く（drawStatic・drawFirstPerson・drawCharacters・drawShadowCasters・drawZombies・drawPlayer・
    drawBulletHoles・drawImpactDust・drawBloodSpray・drawMuzzleFlash・muzzleLight・mBuildingDrawOrder）
 → 直す理由が 7 つある。分けた後の GameWorld は ①② だけ（＋今回の依頼に無いゾンビの群れ。7 章）。

1. 分けた後の形（誰が誰を持つか）

   GameScene ──持つ──→ GameWorld（Model：状態と 1 ティックの順番）
       │                  ├─ WorldBuilder      … place の中身（どこに何を置くか）
       │                  │    └─ PropFactory  … 置物の部品の並び（何で出来ているか）★5
       │                  ├─ EffectManager     … 弾痕・砂ぼこり・血しぶき・千切れた部位の寿命と描画
       │                  ├─ CombatResolver    … 弾の命中・ゾンビの腕の命中を解決し、出来事を出す
       │                  └─ InteractionSystem … 見た先の使える物を探す・拾われた物を消す
       └──持つ──→ WorldRenderer（View：const GameWorld& を読んで描く）★4

  依存は一方通行：WorldRenderer → GameWorld → (Builder / Combat / Interaction) → EffectManager・PropFactory。
  EffectManager は誰も知らない（言われた所に出して、時間で消すだけ）。

2. 1 つずつの仕様

 2-1 WorldRenderer（Scene/Game/WorldRenderer.h）
  ・持つ物：const GameWorld* ／ 建物を近い順に並べる作業領域（mBuildingDrawOrder。mutable を無くせる）
  ・移す関数：drawStatic・drawFirstPerson・drawCharacters・drawShadowCasters・drawZombies・drawPlayer・
             drawMuzzleFlash・muzzleLight（銃口の光は「自キャラの銃の部品を読んで描く」だけなので View 側）
             drawBulletHoles・drawImpactDust・drawBloodSpray は EffectManager の draw を呼ぶ形で残す
  ・GameWorld に足す読み取り口：buildings()・bullets()・effects()（描くだけの物）
  ・コンポーネント指向：ゾンビ・置物は今までどおり forEach< 部品 > で「その部品を持つ物」を描く（種類で分岐しない）
  ・const の扱い：弾痕・粒の draw は並べ替えで中身を書くので const でない。GameWorld::effects() は
    描画のためだけの非 const の口にする（GameScene が持つ GameWorld は非 const なので渡せる）

 2-2 WorldBuilder（Scene/Game/WorldBuilder.h）＋ PropFactory（Interaction/PropFactory.h）
  ・WorldBuilder：「どこに置くか」。TownMap の置き場所を読み、地面・建物・車・置き場・ガソリンを置き、最後に NavMesh を作る
    コンストラクタで建物の形の読み込みを頼む（今の GameWorld のコンストラクタと同じく非同期）
    build( 置き先 ) の置き先は構造体 WorldBuildTarget にまとめる（地面・建物の並び・名簿 2 つ・物の並び・NavMesh。
    引数が 6 個並ぶのを避ける。コメント方針の「設定が複数あるなら構造体」）
    建物の並び（mBuildings）の持ち主は GameWorld のまま（状態なので）。Builder は詰めるだけで覚えない
  ・PropFactory：「何で出来ているか」。PlayerFactory・ZombieFactory と同じ形
    spawnEscapeCar・spawnFuelStation・spawnFuel・spawnAmmoDrop（createProp は private）
    車・缶・落ちた弾の形とファイル名・材質・名前・kRequiredFuel などの定数はここへ
    WorldBuilder（最初に置く）と CombatResolver（倒したら弾を落とす）の両方が使うので、GameWorld が 1 つ持って貸す
  ・GameWorld::place は「自キャラ（PlayerFactory）・確認用のゾンビ・mBuilder.build」を呼ぶだけになる

 2-3 EffectManager（Scene/Game/EffectManager.h）
  ・持つ物：BulletHoleList・ImpactDustList・BloodSprayList・SeveredLimbList・切れた瞬間の姿勢の作業領域
  ・頼み方（「出して」と言うだけ。寿命は知らなくてよい）：
     spawnSurfaceImpact( point, normal, blocker )   … 弾痕＋砂ぼこり
     spawnBloodHit( point, direction, part )        … 部位で量を変える（頭は 1.5 倍）。倍率の定数はここへ
     spawnSeveredLimb( zombieMesh, cut, data, direction ) … 切り口の血しぶき＋千切れた部位
     detach( blocker )                              … 消える物に付いた弾痕を外す（今の removeAttachedTo）
     update( ground ) ／ drawDecals・drawDust・drawBlood・drawSeveredLimbs
  ・材質・部位の伝え方は ★2

 2-4 CombatResolver（Scene/Game/CombatResolver.h）
  ・移す関数：update の「mImpacts を回して blocker なら着弾・target なら hitZombie」・hitZombie・severLimb・dropAmmo
             ★3 で updateZombies の「腕が当たったら体力を減らし ZombieAttackEvent を出す」も
  ・持つ物：このティックの出来事 3 つ（ZombieHit・SurfaceHit・ZombieAttackEvent。型も GameWorld から移す）・
            弾を落とすかの乱数・確率などの定数
  ・借りる物：GameObjectWorld（find< HitboxComponent >・部品へダメージを渡す）・EffectManager・PropFactory・ZombieModel（切り口の形）
  ・部品への権限：体力は ZombieHealthComponent::applyDamage（IDamageable）だけを通す。体力の数字を直接書かない
    （デメリットの「直接触る権限」は、今もある applyDamage の入口だけに絞る）
  ・GameScene の音・画面の赤みは world.combat().zombieHitsThisTick() などから読む（ZombieHitSounds などの引数の型名が変わる）

 2-5 InteractionSystem（Scene/Game/InteractionSystem.h）
  ・移す関数：findInteractable・resolveInteractable・interactableOf・removeTakenPickups・appendPickupColliders
  ・借りる物：HitWorld・GameObjectWorld・自キャラの部位の箱（自分を見ない）・EffectManager（拾われた物の弾痕を外す）
  ・死体と弾の組は ★1

3. ★ 決めてほしいこと（おすすめが先）

 ★1 死体と、その死体が落とした弾の組をどこに持つか（11-09 に死体を漁る仕組みごと消した。今は無い）
   A（おすすめ）死体の物に部品 CorpseLootComponent（落とした弾の GameObjectHandle だけ持つ）を後から付ける
       → 見た死体から getComponent でたどるだけ。並び mCorpseDrops と、毎ティック捨てる掃除が無くなる
       → 10-31 の「ゾンビは落とした物を知らずに済むよう組はここで持つ」は守れる（ゾンビの部品はこの部品を知らない。
         付けるのも読むのも CombatResolver と InteractionSystem だけ）
   B 今の並びのまま InteractionSystem へ移す（CombatResolver が link を頼む）

 ★2 命中の結果をエフェクトへ伝える方法
   A（おすすめ）CombatResolver が EffectManager の spawn〜 を直接呼ぶ（材質・部位は引数）
       → 「何が起きたか」の出来事は既に CombatResolver の 3 つの並びがあり、音・画面はそれを読む。二重にしない
   B 出来事の並びをエフェクトも読む（イベントキュー。CombatResolver は EffectManager を知らなくなるが、
       切れた部位の姿勢など出来事に載せる物が増える）

 ★3 ゾンビの腕が自キャラに当たる処理も CombatResolver へ移すか
   A（おすすめ）移す（ダメージを決めて渡すのは全部 CombatResolver。updateZombies は Think を回すだけに近づく）
   B 移さない（依頼は弾の命中だけ）

 ★4 WorldRenderer の持ち主
   A（おすすめ）GameScene が持つ（GameWorld は描き方を知らない。Model が View を知らない形）
   B GameWorld が持ち、今の draw〜 を転送する（GameScene は変えなくてよいが、GameWorld が View を知ったまま）

 ★5 置物の組み立てを PropFactory へ出すか
   A（おすすめ）出す（11-02 の PlayerFactory の分け方「何で出来ているか／どこに置くか」にそろう。
       11-02 の ★2「置物は GameWorld のまま」は、使う所が 2 つ（Builder と Combat）になるので見直す）
   B WorldBuilder に置き、CombatResolver は Builder の関数を借りる

4. 配線（デメリットへの対処）
  ・新しいクラスは参照を「コンストラクタで 1 回だけ」受け取り、ポインタを持つ（nullptr 不可・所有しない）。
    持ち主は全部 GameWorld で、宣言の順で「借りる物が先に生まれ後に死ぬ」を守る（今のコメントの決まりと同じ）
  ・共有の棚（GameObjectWorld::provide）には入れない：部品が引く物ではなく、世界の係どうしの配線なので
    （棚に置くと、誰が使っているか引数でたどれなくなる。10-12 の GameResources と同じ考え）

5. 変わらないこと
  ・遊び方・描く順・1 ティックの段の順・出来事の順番・計測の印の名前（World.player・World.bullets・World.effects・
    World.zombies、gpuMark の Buildings・Props・Ground・Player・Zombies）
  ・ユーザーが手で変えた定数（弾を落とす確率 0.5・コメント）はそのまま PropFactory／CombatResolver へ移す

6. 進め方（段ごとに 3 構成のビルド。VS を閉じてから vcxproj へ登録する）
  段1 EffectManager（他の全部が使う）
  段2 PropFactory ＋ WorldBuilder
  段3 CombatResolver（★1 の部品もここで）
  段4 InteractionSystem
  段5 WorldRenderer と GameScene の呼び替え
  最後に、遊んで確かめる項目：撃つ（弾痕・砂ぼこり・着弾音）・頭を撃つ（血の量）・脚を切る・倒して弾を拾う（死体を見ても）・
  ガソリンを運んで脱出・噛まれる・影・F6 の物の一覧

7. 今回やらないこと（候補）
  ・ゾンビの群れ（ZombieModel・ZombieFactory・ZombieSpawner・TickContext・updateZombies・alertZombiesToGunshot・spawnZombie）。
    分けると GameWorld はもう一段小さくなる（ZombieDirector の案）。依頼に無いので残す
