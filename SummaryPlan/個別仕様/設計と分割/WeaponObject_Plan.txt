0. 何が問題か
 銃 1 丁が、世界の中で 2 つの物に分かれている。
   ・銃の物（タグ Weapon。名前 "AK47"・"Pistol"）… GunComponent・WeaponModelComponent・LightComponent・MuzzleFlashComponent。
     自キャラと一緒に 1 種類 1 丁ずつ作り、消えない。手に持っていない間は、どこにも見えない
   ・落ちている銃（タグ WeaponDrop）… Transform・StaticModel（寝かせた形）・BoxCollider・Item・Pickup。
     カバンから捨てるたびに PropFactory が新しく作り、拾うと消える
 捨てた銃の弾倉の数・懐中電灯の付け消しは「銃の物」の方が持っていて、地面に見えている「落ちている銃」は中身の無い別物。
 画像の AK47 は、1 つの物に Gun と Item と Collider が付いている。今の形は
   ・「この銃」を指す物が 2 つあり、どちらを読めばよいかを読む側が知っている必要がある（弾倉の数は種類で引き直している）
   ・部品を付け外しして物の役割を変える、という部品指向の使い方が 1 か所も無い（removeComponentLater を使う所が無い）

1. 今の流れ
   始め     PlayerFactory::spawn が銃の物を 1 種類 1 丁ずつ作り、HoldComponent へ渡す。カバンに銃があれば持つ（syncWithInventory）
   捨てる   BagController::dropFromBag → GameWorld::dropItem → PropFactory::spawnDroppedItem → spawnWeaponDrop（新しい物）
            次のティックで HoldComponent が「カバンに無い」のに気付いて素手になる
   拾う     PickupComponent が取られた印を付ける → InteractionSystem::removeTakenPickups が物ごと destroyLater
            素手ならその次のティックで HoldComponent が持つ
   町のライフル  木箱の中のアイテム（物ではない）。カバンへ入れると、始めからある銃の物を持つ

2. 分けた後の形（★1 が A のとき）
 2-1 銃の物（タグ Weapon のまま。1 種類 1 丁・消えない）
   いつも付いている 4 つ … GunComponent・WeaponModelComponent・LightComponent・MuzzleFlashComponent（今と同じ）
   地面にある間だけ付く 5 つ … TransformComponent・StaticModelComponent（寝かせた形）・BoxColliderComponent（WalkThrough）・
                               ItemComponent（その銃・1 丁）・PickupComponent
   捨てる＝5 つを付ける。拾う＝5 つを外す。物は同じ物のまま（弾倉の数・懐中電灯の付け消しは、ずっと同じ GunComponent・LightComponent が持つ）
   タグ WeaponDrop は無くす

 2-2 5 つを付ける・外す所（★2）
   PropFactory::layWeaponOnGround( world, id, position, yawDegree ) → bool
      id の銃の物を引き（GunComponent::find）、5 つを付ける。地面の形（mWeaponDropShapes）は今と同じ物を使う
      付ける順は Transform → StaticModel → BoxCollider → Item → Pickup
      （spawn の後に付けた部品は、付けたときにすぐ awake・start するので、借りる相手を先に付ける）
      その銃の物にもう TransformComponent が付いていれば（地面にある・外す印が付いてまだ外れていない）置かずに false（★4）
   PropFactory::liftFromGround( weapon )（static）
      5 つに removeComponentLater で外す印を付ける（実際に外れるのは次の flush＝次のティックの終わり。今の destroyLater と同じ時）
   PropFactory::spawnDroppedItem の ITEM_KIND_WEAPON は layWeaponOnGround を呼ぶ（GameWorld::dropItem・BagController は変えない）
   PropFactory::spawnWeaponDrop は消す
   createProp の中の「Transform・StaticModel・BoxCollider を付ける」所は、物を作らずに付けるだけの private 関数に分けて、両方から使う

 2-3 拾われた後（InteractionSystem::removeTakenPickups）
   PickupComponent に「拾われた後に物を残すか」を作るときに渡す
      enum class PickupComponent::AfterTaken{ DestroyObject, LeaveObject }
      ガソリン・弾・包帯は DestroyObject（今と同じ）、銃は LeaveObject
   removeTakenPickups：DestroyObject は今と同じ destroyLater。LeaveObject は PropFactory::liftFromGround
   どちらも、先に弾痕・血の跡を外す（EffectManager::detach。今と同じ）

 2-4 銃の物を種類で引く所
   GunComponent::find( objects, item )（static。const と書ける方の 2 つ）を作り、MagazineSync の中の同じループ 2 つと、
   layWeaponOnGround が使う（今は MagazineSync に「銃の物を種類で引くのはここだけ」と書いてある。引く所を 1 つの関数にする）

 2-5 土台（GameObject）：要る部品を、要った部品と一緒に外せるようにする
   今：ほかの部品が requireComponent した部品は、印が付いて外せない（どの部品が要ったかは覚えない。印は消えない）
       地面の 5 つは互いに requireComponent している（StaticModel → Transform、BoxCollider → StaticModel、Pickup → Item・StaticModel）ので、
       今のままでは 1 つも外せない
   後：「どの部品が要ったか」を覚える（Entry::required の bool → 要った部品の種類の並び requiredBy）
       ・removeComponentLater は印を付けるだけ。flush で外す直前に、要った部品が全部同じ flush で外れることを ASSERT で確かめる
       ・要った部品が外れたら、要られた側の requiredBy からも消える（今は残り続ける）
       ・自分で自分を requireComponent した部品（PlayerFootprintComponent・ZombieStateComponent）は、今と同じく外せない
         （Entry::locked。形のポインタを CharacterCollider に渡してあるため）
       ・Component::requireComponent は、要った部品（this）を GameObject へ渡す
   外す順は今と同じ（付けたのと逆の順。Pickup → Item → BoxCollider → StaticModel → Transform）

 2-6 懐中電灯（★3）
   地面の銃に TransformComponent が付くので、LightComponent が「socket が無ければ Transform から照らす」ままだと、
   懐中電灯を付けたまま捨てた銃が地面から照らしてしまう（今は照らさない）
   → LightPresets::needsSocket( preset ) を足す（Flashlight は true）。true の種類は、socket が無ければ照らさない
   付け消しは今と同じく銃の LightComponent が覚えている（拾い直すと、捨てたときのまま）

 2-7 組み立て（画像の並びに当たる所）
   PlayerFactory::spawnWeapon（今と同じ 4 行）
      obj->addComponent< WeaponModelComponent >( … );
      obj->addComponent< GunComponent >( spec );
      obj->addComponent< LightComponent >( LightPreset::Flashlight );
      obj->addComponent< MuzzleFlashComponent >();
   PropFactory::layWeaponOnGround（捨てたとき。同じ物へ足す 5 行）
      weapon->addComponent< TransformComponent >( position, yawDegree );
      weapon->addComponent< StaticModelComponent >( shapes, kMetalMaterial, DrawCulling::Target::Small );
      weapon->addComponent< BoxColliderComponent >( BoxColliderComponent::Mode::WalkThrough );
      weapon->addComponent< ItemComponent >( weaponSpec( id ).item, kOneWeapon );
      weapon->addComponent< PickupComponent >( PickupComponent::AfterTaken::LeaveObject );

3. 依存の向き（一方通行のまま）
   GameWorld::dropItem ─→ PropFactory::spawnDroppedItem ─→ layWeaponOnGround ─→ GunComponent::find・地面の 5 つの部品
   InteractionSystem ─→ PickupComponent（AfterTaken を読む）・PropFactory::liftFromGround（static）
   MagazineSync ─→ GunComponent::find
   ・GunComponent・HoldComponent は、地面の 5 つを知らない（持つ・撃つ側は今のまま）
   ・PickupComponent は銃を知らない（「物を残すか」だけを持つ）

4. 手を付けない所
   ・HoldComponent（持てる銃の並び・syncWithInventory・equip）。銃の物は今も 1 種類 1 丁で、自キャラと一緒に作る
   ・MagazineSync の store・restore の呼ぶ所（カバンのマスへ弾倉の数を写す流れ）
   ・木箱の中のライフルは、アイテムのまま（物にしない。カバンへ入れると銃の物を持つ、は今と同じ）
   ・ガソリン・弾・包帯の落ちた物（今と同じく、拾うと物ごと消える）

5. 外から読む所
   ・F6 のエディタの物の一覧（EditorWindow.cpp）：タグ WeaponDrop の名前の行を消す
   ・InteractionSystem::collectNearby・findInteractable・appendPickupColliders は部品（StaticModel・Pickup）で引いているので変えない
   ・WorldRenderer は StaticModelComponent を全部たどって描くので、地面の銃はそのまま描かれる

6. 変わってしまう所
   ・F6 の Objects の欄：WeaponDrop の物が出なくなり、捨てている間は銃の物（AK47・Pistol）の部品の数が 4 → 9 になる
   ・同じ種類の銃を、地面にあるのにもう 1 回捨てようとしたとき（★4。RaidParams::rifleCount を 2 以上にして 2 丁目を拾ったときだけ起きる。
     初期値 1 では起きない）：今は落ちている銃が 2 つになる。後は捨てられず、カバンに戻る
   ・拾った直後（次のティックが来る前）に同じ銃を捨てようとしたときも、同じく捨てられずカバンに戻る
     （外す印が付いた 5 つがまだ付いているため。カバンは閉じてから開き直すので、ふつうは 1 ティック以上経っている）
   ・requireComponent の印が、要った部品を外すと消えるようになる（今は残り続ける）。今のゲームでは部品を外す所が無いので、動きは変わらない
   ・処理の順番・数値・計測の印・ログの文字・保存ファイルは変えない

7. 決めてほしい所（★）
 ★1 1 つの物にするやり方
     A（おすすめ）捨てるとき 5 つを付け、拾うとき 5 つを外す。StaticModel・BoxCollider・Pickup は「置いたら動かない」のまま使える。
       土台に「要った部品と一緒に外す」を足す（2-5）。部品の付け外しをゲームで初めて使う所になる
     B 9 つを始めから全部付けておき、「地面にある・無い」を切り替える（画像の並びに一番近い）。
       StaticModel・BoxCollider・Pickup を「動かせる・隠せる」に作り替え、描く所・視線・マークに「隠れているか」の確かめを足す。触る所が多い
 ★2 5 つを付ける・外す関数の置き場所
     A（おすすめ）PropFactory（地面の物の部品の並びを決めている所。地面の形もここが持っている）。銃を作るのは PlayerFactory のまま
     B WeaponFactory を作り、銃を作る（PlayerFactory::spawnWeapon）・地面へ置く・地面から外すを全部移す。
       GameWorld が WeaponFactory を持ち、作った銃を PlayerFactory::spawn へ渡す形になる（触るファイルが 4 つほど増える）
 ★3 懐中電灯を付けたまま捨てた銃
     A（おすすめ）照らさない（今と同じ）。付け消しは覚えている
     B 地面から照らす（遊びが変わる。銃は寝かせた形なので、足元の高さから水平に照らす）
 ★4 同じ種類の銃が地面にあるのに、もう 1 回捨てようとしたとき
     A（おすすめ）捨てられない（カバンに戻る。今の「置けなかったらカバンへ戻す」と同じ道）
     B 地面の銃を新しい場所へ移す（dropItem の中で flush を呼んで先に外す。ティックの外で flush を呼ぶ所が 1 つ増える）

8. 手順（1 つずつビルドする）
   1. GameObject に requiredBy と locked を入れ、flush で確かめる形にする（2-5）
   2. LightPresets::needsSocket を足す（2-6）
   3. GunComponent::find を作り、MagazineSync のループを置き換える（2-4）
   4. PickupComponent に AfterTaken を足す。PropFactory の今の 2 か所（ガソリン・落ちた物）は DestroyObject を渡す
   5. PropFactory に layWeaponOnGround・liftFromGround を作り、spawnDroppedItem の銃をつなぎ替え、spawnWeaponDrop を消す
   6. InteractionSystem::removeTakenPickups を AfterTaken で分ける
   7. タグ WeaponDrop と、F6 の名前の行を消す
   8. Debug・Profile・Release の 3 構成でビルド
   9. この仕様書の状態欄、GameChats/ComponentSystem.md、メモリ、コメント（PlayerFactory.h・HoldComponent.h の「別の置物」の説明）を更新

9. 画面で確かめる所
   ・カバンから銃を捨てると、足元の前に寝かせた形で出る。E で拾える・マークが出る
   ・捨てて拾い直しても、弾倉の数と懐中電灯の付け消しが元のまま
   ・手に持っている銃を捨てると素手になり、拾うとまた持つ
   ・懐中電灯を付けたまま捨てても、地面から照らさない
   ・捨てた銃を撃つと弾痕が付き、拾うと弾痕も消える
   ・F6 の Objects の欄で、捨てている間だけ銃の物の部品の数が 9 になり、拾うと 4 に戻る
   ・捨てる → 拾う → 捨てる を何回くり返しても落ちない
   ・ガソリン・弾・包帯は今までどおり拾える
