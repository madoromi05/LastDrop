0. コンポーネント指向をどこで使うか（この作り直しの考え方）
 このゲームの「部品を組み合わせて物を作る」は 3 つの層がある。分けた物は、どれもこのどこかへ入れる。
   ① 物の層（GameObject に付ける Component）
      … 1 つの物が持つ「できること」。自キャラ・ゾンビ・銃・置物。付け外しで物の性質が変わる
   ② 姿勢の層（BonePoseModifier を BonePoseModifierChain でつなぐ）
      … 1 体の骨の書き換えを、小さな段の組み合わせで作る。ゾンビ（のけぞり→潰す）で使っている形を自キャラにも使う
   ③ 世界・画面の係（普通のクラス。GameWorld や GameScene が持つ）
      … 物を何体もまとめて扱う仕事（湧かせる・音を知らせる）と、物ではない物（カメラ・画面・音・デバッグ）
 判断の決まり：
   ・1 つの物だけで完結する仕事 → ①（部品にする）
   ・何体もの物をまとめて扱う仕事 → ③（係にする）。部品からは共有の棚（shared< T >）で引く
   ・カメラ・UI・音・デバッグは GameObject にしない（描画ごとに動く物で、ティックで動く GameObjectWorld の外にあるため。
     世界（Model）は音を知らない、という今の決まりも守る）

2. 分けた後の形

   GameScene
     ├─ GameWorld（状態と 1 ティックの順番）
     │    ├─ TownEnvironment … 町（地図・地面・建物・NavMesh・見える範囲）を作って持つ ★1
     │    │    └─ WorldBuilder（今のまま）
     │    ├─ ZombieDirector  … ゾンビの数と周り（湧かせる・群れ・追う先・Think の前後）
     │    │    └─ ZombieHearing … 音をゾンビへ知らせる（共有の棚に置く）★2
     │    └─ （今のまま）EffectManager・CombatResolver・InteractionSystem・PropFactory・PlayerFactory
     ├─ PlayerFeedback   … このティックの出来事を自キャラの視点・音・画面へ返す ★5
     ├─ GameEditorBridge … ZF_EDITOR のときだけ。エディタ・確認用のキー・FireProbe ★5
     └─ FirstPersonControl（窓口。口は変えない）
          ├─ CommandReader … 操作を作る
          ├─ ViewEffects   … 反動・揺れ・ぶれ
          └─ LookPull      … 相手の顔へ向ける

   自キャラの GameObject（部品の並び。太字が新しい部品）
     Transform・SkinnedModel・FirstPersonBody・Hold・【ArmPose】・PlayerLocomotion・PlayerHealth・Hitbox・
     CharacterCollider・PlayerComponent・【PlayerNoise】
   FirstPersonBody の中（姿勢の層）
     ArmOverridePose → SpineBendPose → EyePoint → WeaponPlacePose → WeaponFeelPose → WeaponBounds（★3）

  依存は一方通行：
    GameScene → PlayerFeedback / GameEditorBridge → GameWorld → ZombieDirector → ZombieHearing
    PlayerNoiseComponent → ZombieHearing（棚から引く。GameWorld を知らない）

3. GameWorld を分ける

 3-1 TownEnvironment（Scene/Game/World/TownEnvironment.h）★1
  ・持つ物：TownMap・TownGround・建物の並び・NavMesh*（TownCache から借りる）・TownVisibility*（同じ）・WorldBuilder・
           脱出の車の置き場所の番号・TownCache*
  ・移す関数：buildTown・buildNavMesh・buildVisibility の中身（ロードの段は今のまま GameWorld の関数から呼ぶ。GameLoader は変えない）
  ・読み口：map()・ground()・buildings()・navMesh()・visibility()
  ・名簿 2 つ（CollisionWorld・HitWorld）と物の並びは GameWorld のまま（町だけの物ではないため）。作るときに引数で借りる
  ・NavMesh を棚へ置く（provide）のは GameWorld（棚の持ち主なので）

 3-2 ZombieDirector（Scene/Game/World/ZombieDirector.h）
  ・持つ物：ゾンビの形のデータ・ZombieModel・ZombieFactory・乱数・何体目か・ZombieSpawner・湧く予定の並び・
           群れ（ZombieCrowd）・追う先（ChaseTarget）・TickContext・PathBudget・アニメの間引きの視点・ZombieHearing
  ・アニメの名前の定数（walk・run・death1/2・gethit・idle1・atack3）も GameWorld.cpp から移す
  ・関数：
     setup( map )                    … placeActors のゾンビの所（設計図・作る係・湧かせる係）
     spawn( position, yaw )          … 今の spawnZombie（F9 の確認用からも呼ぶ）
     beginTick()                     … 道探しの回数を戻す
     setAnimationView( … )           … 今のまま
     prepareThink( player )          … 追う先・攻撃に行っている体・群れを作る（今の updateZombies の前半）
     finishThink( player )           … つかまれているかを自キャラへ（今の updateZombies の後半）
     spawnFromSpawner( player, yaw ) … 今のまま
     hearing()・spawner()
  ・GameWorld::update の順番は変えない（順番を持つのは GameWorld）：
     … → effects → director.prepareThink → objects.update( Think ) → combat.resolveZombieAttacks → director.finishThink → Late → flush → spawnFromSpawner
  ・TickContext・PathBudget を棚へ置くのは Director（ゾンビの部品しか使わないため）

 3-3 ZombieHearing（Zombie/Move/ZombieHearing.h）★2
  ・音を「何体ものゾンビ」へ知らせる係。共有の棚に置き、音を立てる側（部品・係）は shared< ZombieHearing >() で引く
  ・関数：hearGunshot( position )・hearNoise( position )（今の alertZombiesToNoise。銃声と同じ）・hearFootsteps( feet, range )
  ・銃声の届く距離 30m と雨の日の倍率はここ（世界の決まり）。歩き 5m・走り 18m と 0.3 秒の間隔は音を立てる側（3-4）

 3-4 PlayerNoiseComponent（Player/PlayerNoiseComponent.h。自キャラの部品）★2
  ・自キャラが立てる音（足音・銃声）をゾンビへ知らせる部品。Input の段で、PlayerComponent の後に動く
    （付ける順で段の中の順番が決まるので、PlayerFactory で PlayerComponent の後に付ける）
  ・足音：0.3 秒ごとに、歩き方（PlayerLocomotion の gait）の距離で hearFootsteps
  ・銃声：持っている銃がこのティックに撃ったら（HoldComponent::heldGun）、足元で hearGunshot
  ・外してよい部品にする（外すとゾンビが自キャラの音を聞かない。確認用）
  ・GameWorld に残るのは「弾を出す」だけ（BulletList は世界の物なので）

 3-5 死体は自分で消える
  ・ZombieCorpseComponent::update の最後で、沈み終えたら自分の物を destroyLater する（物の寿命は物が決める）
  ・GameWorld の「沈み終えた死体を探して消す」は無くなる。destroyLater は flush まで待つので、消える時刻は今と同じティック

 3-6 弾倉の数 ★6
  ・magazineRounds・setMagazineRounds の中身（forEach< GunComponent >）を MagazineSync へ移す
  ・そのために GameWorld に非 const の objects() を足す

 3-7 GameWorld に残るもの
  ・名簿 2 つ・飛ぶ弾・エフェクト・物の並び・命中・使う物・PlayerFactory・PropFactory・自キャラ・dropItem（PropFactory を使う 6 行なので残す）
  ・1 ティックの順番と、ロードの段（buildTown など。中身は TownEnvironment と ZombieDirector を呼ぶだけ）
  ・見込み：実装 463 → 約 200 行・メンバー約 40 → 約 15
