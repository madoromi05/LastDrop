 3. 同じマス目の移動を「元と先が同じ移動」として扱えるか
================================================================================
 答え：①②の段は扱える。入口はそのままでは扱えない（違いが 3 つ残る）。

 3-1. 段（①②）は扱える
   段の関数に「元の表」と「先の表」を別の引数で渡す形にして、同じマス目の移動では同じ表を 2 回渡す。
   このとき applyMoveBetween の①②の行は、applyMove の①②の行と 1 行ずつ同じ処理になる。理由：
   ・表の大きさを変える処理が無い（place・clear はマスを書き換えるだけ）。だから 2 つの引数が同じ表を指していても、
     途中で取った参照（重ねる先の into）は壊れない
   ・重ねる先 into は others の 1 つで、others は動かす物自身を含まない（2-2 の 5）。同じ表でも、足す先と引く元は別のマス
   ・処理の順番（others をどける → 動かす物をどける → 置く → 戻す）は 2 つの関数で同じ
   ・列の数は、同じマス目なら target.mColumns と mColumns が同じ値

 3-2. 入口は違いが残る
   ・同じ所へ動かしたら false（2-2 の 3）は、同じマス目のときだけの決まり
   ・ownersIn の except（2-2 の 5）は、同じマス目のときだけ source を渡す
   ・列が足りない確認（2-2 の 4）は、同じマス目に足しても結果は変わらない（必ず通る）が、要らない確認が増える
   入口も 1 つにすると（★1 案B）、上の 2 つが「sourceCells == targetCells なら」の分岐になる。
   おすすめは、入口を 2 つ残して違いをそこに書く形（★1 案A）。「同じマス目だけの決まり」が applyMove の 1 か所で読める。

   bool ItemGrid::applyMove( Cells* cells, int from, int to ) const {
       int source = ( *cells )[ from ].owner;
       ASSERT( source != kEmpty && "ItemGrid::applyMove : nothing to move." );
       ItemId item = ( *cells )[ source ].stack.item;
       int target = placementCell( item, to );
       if ( target == source ) {
           return false; // 同じ所（動かさない。画面では取りやめとして扱う）
       }
       std::vector< int > others = ownersIn( *cells, target, itemSpec( item ).cellSize, source );   // （今のコメントのまま）
       if ( tryStackInto( cells, source, cells, others ) ) {
           return true;
       }
       return swapAndRestore( cells, source, *this, cells, target, others );
   }

   bool ItemGrid::applyMoveBetween( Cells* sourceCells, int from, const ItemGrid& target, Cells* targetCells, int to ) const {
       int source = ( *sourceCells )[ from ].owner;
       ASSERT( source != kEmpty && "ItemGrid::applyMoveBetween : nothing to move." );
       ItemId item = ( *sourceCells )[ source ].stack.item;
       int size = itemSpec( item ).cellSize;
       int placed = target.placementCell( item, to );
       if ( !target.isInside( placed / target.mColumns, placed % target.mColumns, size ) ) {
           return false; // 列が足りない（1 列のマス目に 2 マスの物）
       }
       std::vector< int > others = ownersIn( *targetCells, placed, size, kEmpty );                  // （今のコメントのまま）
       if ( tryStackInto( sourceCells, source, targetCells, others ) ) {
           return true;
       }
       return swapAndRestore( sourceCells, source, target, targetCells, placed, others );
   }

 4-3. 切り出す 2 つ（中身は今の applyMoveBetween の①②の行をそのまま移す）

   bool ItemGrid::tryStackInto( Cells* sourceCells, int source, Cells* targetCells, const std::vector< int >& others ) {
       if ( others.size() != 1 ) {
           return false;
       }
       ItemStack& moving = ( *sourceCells )[ source ].stack;
       ItemStack& into = ( *targetCells )[ others[ 0 ] ].stack;
       int stackSize = itemSpec( moving.item ).stackSize;
       if ( into.item != moving.item || stackSize <= 1 || into.amount >= stackSize ) {
           return false;
       }
       int count = std::min( moving.amount, stackSize - into.amount );
       into.amount += count;
       moving.amount -= count;
       if ( moving.amount == 0 ) {
           clear( sourceCells, source );
       }
       return true;
   }

   bool ItemGrid::swapAndRestore( Cells* sourceCells, int source, const ItemGrid& target, Cells* targetCells, int placed,
                                  const std::vector< int >& others ) const {
       ItemStack moving = ( *sourceCells )[ source ].stack;   // どける前に写す
       int movingSize = itemSpec( moving.item ).cellSize;
       std::vector< ItemStack > otherStacks;
       for ( int other : others ) {
           otherStacks.push_back( ( *targetCells )[ other ].stack );
           clear( targetCells, other );
       }
       clear( sourceCells, source );
       if ( !target.isFree( *targetCells, placed, movingSize ) ) {
           return false;
       }
       place( targetCells, placed, moving );
       // どけた物は、置く先と同じ並び（ずれ）のまま元の場所へ。入らなければ、上の行・左の列から空いている所へ
       for ( size_t i = 0; i < others.size(); ++i ) {
           （今の 378〜390 行のまま）
       }
       return true;
   }

 5. 振る舞いが変わりうる所と、同じ結果になる理由
================================================================================
 5-1. 同じ表を 2 つの引数で渡す（同じマス目の移動）
   3-1 のとおり。段の関数は「2 つの表が別の物」を前提にした書き方をしない（表を入れ替える・大きさを変える・
   片方を全部読んでからもう片方へ書く、をしない）。処理の順番は今の applyMove と同じ。

 5-2. 動かす物の中身を読む時
   今：関数の始めに moving へ写し、①②はその写しを読む
   後：①は元のマスを直接読む（数を引く前に、足す数 count を決める。今と同じ順）。
       ②は元のマスをどける前に写す（今と同じく、どけた後は写しを置く）
   ①で足す数は「今の moving.amount」と「元のマスの amount」が同じ値のうちに決まるので、結果は同じ。

 5-3. ①の条件の書き方
   今：if ( others が 1 つ ) { if ( 同じ物 && 重ねられる && 空きがある ) { 足す; return true; } }
   後：当てはまらない場合を先に return false（早く返す形）。条件の中身は同じ 4 つで、当てはまるときだけ足す。

 5-4. 列の数を読む所（②の戻す所の計算）
   今の applyMove は全部 mColumns。後は「置く先のずれ」を target.mColumns で読む。
   同じマス目では target が *this なので同じ値。

 5-5. できなかったときの表
   false を返すときに写しが途中まで変わっているのは今も同じ（変わり方も同じ順なので同じ形）。呼ぶ側は写しを捨てる。

 5-6. 変わらない物
   ・public の関数の名前・引数・ASSERT の文字
   ・保存ファイルの形（マス目の中身の並びが同じなので、save.xml に書かれる物も同じ）
   ・速さ（others は参照で渡す。写しの数は今と同じ）

 9. 懸念点
================================================================================
 ・同じ表を 2 つの引数で渡すので、後で段の関数を直す人が「2 つは別の表」と思い込むと壊れる。
   ヘッダの宣言のコメントに「同じマス目の中の移動では同じ表を渡す」と書いて防ぐ（4-1）
 ・単体テストは GameLib の ASSERT を小さな代わりの物に差し替えてビルドする。ゲーム本体の ASSERT（halt）とは止まり方が違うが、
   ASSERT が外れる場合は今回のテストに無い（外れたら出力に出て、比べたときに分かる）
 ・画面を通した確認は自動ではできない。7-4 の遊んで見る所はユーザーにお願いする
