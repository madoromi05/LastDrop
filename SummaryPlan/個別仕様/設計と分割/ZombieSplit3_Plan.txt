--------------------------------------------------------------------------------
 ★ ユーザーに決めてもらうこと（おすすめを先に書く）
--------------------------------------------------------------------------------
 ★1 アニメの切り替えの部品（段階G）が、根の動きの区間も一緒に始めるか
     （おすすめ）案A：一緒に始める（部品が ZombieRootMotionSpan を借りる）
       ・攻撃・よろけ・倒れるアニメは、どれも「アニメ・始める時刻・繋ぐ長さ・根の動きの表・通り抜けの決まり」が必ず組で使われる。
         今は Zombie の 4 か所に組がばらばらに書いてあり、表 4 つもメンバとして持っている。組ごと 1 か所にまとまる
       ・Zombie は「よろけを流す（playStagger）」と 1 行呼ぶだけになる
     （別案）案B：アニメだけを流し、根の動きは今までどおり Zombie が始める
       ・部品は小さいが、Zombie に表 4 つと「どのアニメにどの表か」が残る

 ★2 体を引きずっている間の攻撃の時計（mAttackClock）をどこへ置くか
     （おすすめ）案A：ZombieAttack へ移す（updateWithoutAnimation を足す）
       ・時計は「アニメの代わりに攻撃の段階を進める時刻」なので、段階を持つ ZombieAttack の物。
         終わりの判定（時計 >= アニメの長さ）と、進める速さ（playbackRate）も ZombieAttack が知っている
     （別案）案B：Zombie に残す（今のまま）

 ★3 攻撃の間合い（段階H）を、状態を持たない関数の集まり（namespace）にするか、クラスにするか
     （おすすめ）案A：namespace ZombieAttackReach（AngleMath・FlatMath と同じ形）
       ・覚える値が無い（定数と、体の位置・向きから答えを出すだけ）。メンバにしなくてよいので Zombie のメンバも増えない
     （別案）案B：クラスにして Zombie のメンバにする（立っている・這うで定数の組を切り替える物として持つ）

--------------------------------------------------------------------------------
 決まっていること（1・2 回目と同じ方針）
--------------------------------------------------------------------------------
 ・動きは 1 つも変えない（式・呼ぶ順・定数をそのまま移す）
 ・Zombie の public の関数は変えない（GameWorld・確認用の表示・SeveredLimb はそのまま）。
   Zombie::Animations の名前もそのまま使える（中身を ZombieAnimationSet.h へ移し、Zombie の中で別名にする）
 ・部品は Zombie のメンバとして値で持つ。足元（mPosition）と向き（mAngleY）は Zombie が持ったまま、関数ごとに渡す
 ・「今どの状態か（State）」「いつどのアニメへ移るか」は Zombie に残す。部品は State を知らない

 3. 分け方の方針
================================================================================
 ・1・2 回目と同じく、「持っている値」と「それを変える関数」が一緒に動く所だけを分ける（Extract Class）。
 ・今回はそれに加えて、別のクラスの中身を覗いて計算している関数を、そのクラスへ移す（Move Function）。
 ・修正の入口が次のように分かれる：
     アニメの繋ぎ目がおかしい・腰が飛ぶ        → ZombieAnimationSet
     攻撃してこない・遠くからつかむ            → ZombieAttackReach
     いつ攻撃・よろけ・倒れるへ移るかがおかしい → Zombie

 4. 段階G：アニメの切り替え（ZombieAnimationSet）
================================================================================
 持つ物：アニメ 6 つ、根の動きの表 4 つ、mWalking、mMoveStartTime（★1 案A のとき）
 借りる物：ZombieModel（形・歩きの表）、SkinnedMeshInstance、ZombieRootMotionSpan（どれも Zombie のメンバ。作るときに渡す）
 移す定数：kDeathFadeTicks・kDeathStartTime・kStaggerFadeTicks・kStaggerStartTime・kRecoverFadeTicks・kMoveRestartTime・
          kLocomotionFadeTicks・kAttackStartTime・kAttackFadeTicks・kFallbackWalkSpeed・kCrawlStartTime（理由のコメントごと）
 移す関数：findAnimation（無名の namespace のまま）

 関数（案）：
   ZombieAnimationSet( const ZombieModel* model, const ZombieAnimationNames& names,
                       SkinnedMeshInstance* mesh, ZombieRootMotionSpan* rootSpan );
   void startStanding();                 // 作った直後の立つアニメ（今のコンストラクタの最後の setAnimation）
   void setWalking( bool walking );      // 今の setWalking
   void playAttack( Vector3* footing );  // 攻撃のアニメ＋根の動き（相手を通り抜ける）。終わったら立つ
   void playStagger( Vector3* footing ); // よろけ＋根の動き（通り抜けない）
   void playDeath( Vector3* footing );   // 死亡＋根の動き（全員を通り抜ける）
   void playDowned( Vector3* footing );  // 前へ倒れる（無ければ死亡）＋根の動き
   void returnToLocomotion( Vector3* footing ); // 歩く・立つへ戻し、根の動きの区間を閉じる（攻撃・よろけの終わり、振りほどき）
   float walkDistanceThisTick() const;   // 今の walkDistanceThisTick
   bool hasFinishedFalling() const;      // 今の canStartCrawling の最後の行（倒れ終わったか）
   bool canWalk() const;                 // 今の canChase（歩くアニメがある）
   bool hasStagger() const; bool hasDeath() const; bool hasDowned() const; bool hasAttack() const;
   float attackPeriod() const;           // 這っている間の攻撃の時計の終わり

 Zombie 側の変わり方（例）：
   今：mMesh.crossFadeTo( mStaggerAnimation, kStaggerStartTime, kStaggerFadeTicks, SkinnedMeshInstance::PLAY_ONCE );
       mRootSpan.start( mStaggerRootMotion, kStaggerStartTime, ZombieRootMotionSpan::Pass::None, &mPosition );
       mStagger.start();
   後：mAnimations.playStagger( &mPosition );
       mStagger.start();

 Zombie::Animations：中身を ZombieAnimationSet.h の struct ZombieAnimationNames へ移し、Zombie の中に
   typedef ZombieAnimationNames Animations; を置く（GameWorld の Zombie::Animations はそのまま通る）。
 宣言の順：mMesh・mRootSpan を借りるので、それらより後に宣言する（mLocomotion と同じ）。

 5. 段階H：攻撃の間合い（ZombieAttackReach）
================================================================================
 状態を持たない関数の集まり（★3 案A）。
 移す定数：kAttackStartDistance・kAttackStartHalfAngle・kGrabReachDistance・kGrabHalfAngle・kGrabCloseDistance・
          kReachApproachSpeed・kCrawlAttackStartDistance・kCrawlGrabReachDistance（理由のコメントごと）

 関数（案）：
   struct Origin{                 // 攻撃する体の今の形（Zombie が作って渡す）
       Vector3 center;            // 体の中心（bodyCenter）。向きの差はここから測る
       Vector3 reachFrom;         // 手の届く距離を測る所（立っていれば center、這っていれば頭）
       float angleY;              // 向き（度）
       bool crawling;             // 体を引きずっているか（距離の組を切り替える）
   };
   bool canStart( const Origin& origin, const Vector3& target );  // 今の canStartAttack の最後の 2 行
   bool canGrab( const Origin& origin, const Vector3& target );   // 今の isTargetInReach の後半
   float approachStep( const Vector3& center, const Vector3& target ); // 手を伸ばしている間に寄る長さ（寄らなくてよければ 0）

 Zombie に残す物：canStartAttack の前半（攻撃のアニメがある・相手がつかめる・ほかが攻撃に行っていない・追っている・
   腕が残っている）と isTargetInReach の前半（相手がつかめる）。どれも「今の状態」を見る判断なので Zombie の物。
 消える物：Zombie::reachDistanceTo・headingDifferenceTo（ZombieAttackReach の中へ）。
   flatDistanceTo は swayStrength でも使うので Zombie に残す。

================================================================================
 6. 段階I：持ち主の違う小さな関数を移す
================================================================================
 ・HitboxSet::partCenter( BodyPart part, Vector3* out ) const を足す（その部位の箱が置かれていれば中心を書いて true）。
   Zombie::headPosition は「頭の箱の中心、無ければ目の高さ」の 2 行になる。
 ・SkinnedMeshInstance::shownWorldPose( std::vector< Matrix34 >* out ) const を足す（今の Zombie::shownWorldPose の中身。
   update 前は根の位置に置く）。Zombie::shownWorldPose は呼ぶだけになる（public は変えない）。
 ・★2 案A のとき：ZombieAttack に void updateWithoutAnimation( float period, bool targetInReach ) と時計を足す。
   Zombie の mAttackClock と、updateAttack の這っている間の 6 行が消える。
   start() で時計を 0（今の kAttackStartTime）へ戻す。

================================================================================
 7. 分けない所と理由
================================================================================
 ・倒れて這う間のつなぎ（updateDowned・crawlChase・startCrawling、約 90 行）：
   追う（ZombieLocomotion）・攻撃（ZombieAttack と段階H）・腕（ZombieCrawl）・胸（ZombieCrawlBody）・欠損・メッシュを全部使う。
   外へ出すと「Zombie の部品を全部借りる別の Zombie」になり、修正の入口がかえって増える。
 ・hasArm・canCrawl：腕の左右（ZombieCrawlLayout::Side）と欠損（BodyPart）を結ぶ 6 行。どちらの部品へ入れても
   もう一方を知ることになるので、両方を知っている Zombie に残す。
 ・State パターン（状態ごとのクラス）：Alive と Downed が同じ追う・攻撃・撃たれる処理を共有するので、今も勧めない。
 ・定数だけを別ファイルへ移すこと：理由のコメントは使う所の近くに置く（2 回目と同じ）。今回の定数は使う関数ごと移る。

 12. 懸念点
================================================================================
 ・ZombieAnimationSet はメッシュと根の動きの区間を借りる。宣言の順を間違えると、作る前の物を借りる（ヘッダにコメントを書く）
 ・mWalking は「攻撃を始めたら立つ」（playAttack の中）でも変わる。今の startAttack の mWalking = false を落とさないこと
 ・Zombie::Animations を別名にするので、前方宣言では使えない（GameWorld は Zombie.h を include 済みなので問題なし）
