0. 何が問題か
 持ち物（Inventory）は自キャラの物なのに、シーン（GameScene）が持っている。
   ・GameScene::mInventory を、毎ティック GameWorld::update → PlayerComponent::setInput の引数で自キャラへ渡している
     （自キャラが自分の持ち物を、外から毎回もらっている）
   ・シーンの係（HudController・BagController・LootController）は、作るときに Inventory* を受け取って覚えている
   ・「自キャラが何を持っているか」を知りたい所は、自キャラの物ではなく GameScene をたどる必要がある
 体力（PlayerHealthComponent）・持つ銃（HoldComponent）は自キャラの部品なのに、持ち物だけが外にある。

1. 今、持ち物を読み書きしている所
   持ち主    GameScene::mInventory（RaidStart::startBag で作る）
   世界の中  GameWorld::update（引数で受け取る）→ PlayerComponent::setInput → mInventory
               → HoldComponent::syncWithInventory（カバンの銃を持つ）・updateReload（予備の弾を弾倉へ）→ GunComponent
   シーン    GameScene：ロードの後の restoreMagazineRounds・mInteractor.update（E で拾う）・mEditor.publish（F6）
             HudController：使える物のマークの色（canInteract）・右下の予備の弾の数
             BagController：カバンの画面の全部（14 か所）
             LootController：漁る画面・給油口（4 か所）
   持ち物そのもの（Inventory・ItemGrid）と、それを引数で受け取る関数（IInteractable::interact・GunComponent::updateReload・
   InventoryScreen・MagazineSync など約 40 か所）は、今のままでよい（Inventory を渡す形は変えない）

2. 分けた後の形
 2-1 InventoryComponent（新。GameSrc/Interaction/Item/InventoryComponent.h / .cpp。Inventory・ItemComponent と同じ所）
   自キャラの持ち物を持つ部品。中身は今の Inventory をそのまま 1 つ持つだけ（PlayerHealthComponent が PlayerHealth を持つのと同じ形）
     explicit InventoryComponent( const ItemGrid& bag )      … bag: 始めのカバンの中身（写して持つ）
     Inventory& inventory()  /  const Inventory& inventory() const
     static Inventory* inventoryOf( GameObject* holder )     … holder が nullptr・この部品が付いていなければ nullptr
     static const Inventory* inventoryOf( const GameObject* holder )
   inventoryOf は HoldComponent::heldGun と同じ役（物の外から読む所が、同じ 3 行を書かずに済むようにする）
   自分では動かない（updatePhase は None）

 2-2 自キャラ
   PlayerFactory::spawn( world, position, yawDegree, startBag )   … 引数に始めのカバンを足し、1 行足す
      obj->addComponent< InventoryComponent >( startBag );
   PlayerComponent
      ・setInput の引数から inventory を消す。メンバー mInventory（Inventory*）は、start で借りる InventoryComponent* に替える（★1）
      ・update の中の hold->syncWithInventory・hold->updateReload へ渡す物は、その部品の inventory()
      ・HoldComponent・GunComponent の関数は変えない（PlayerComponent が渡す形のまま）

 2-3 世界
   GameWorld のコンストラクタに始めのカバンを足す（★2）
      GameWorld( MeshCache* meshes, TownCache* town, DayCondition condition, const ItemGrid& startBag )
      写して持ち（mStartBag）、placePlayer で PlayerFactory::spawn へ渡す
   GameWorld::update の引数から inventory を消す

 2-4 シーン
   GameScene：mInventory を消す。mWorld( …, RaidStart::startBag() ) で渡す
      使う所は InventoryComponent::inventoryOf( mWorld.player() ) で引く
      （ロードの後の restoreMagazineRounds は、自キャラが置けなかったら飛ばす。mInteractor.update は自キャラが居るときだけ呼ばれている）
   HudController・BagController・LootController（★3）
      コンストラクタの Inventory* と、メンバー mInventory を消す
      使うたびに自キャラから引く private 関数を 1 つずつ持つ（Inventory* inventory() const）
      BagController::canOpen は「持ち物があって、死んでいない」にする（今は「自キャラが居て、死んでいない」）
   GameEditorBridge::publish：引数の Inventory* を消し、中で world の自キャラから引いて EditorWindow::setInventory へ渡す
      （EditorWindow は今も「無ければ nullptr」を受け取れる）

3. 依存の向き（一方通行のまま）
   PlayerFactory ─→ InventoryComponent（付ける）
   PlayerComponent ─→ InventoryComponent（start で借りる）─→ Inventory
   GameScene・HudController・BagController・LootController・GameEditorBridge ─→ InventoryComponent::inventoryOf( 自キャラ )
   ・InventoryComponent は自キャラ・銃・画面を知らない（持ち物を持つだけ）
   ・GameWorld は持ち物の中身を知らない（始めのカバンを預かって、自キャラを作るときに渡すだけ。今日の条件と同じ扱い）
   ・GameWorld::update から Inventory の名前が消える

4. 手を付けない所
   ・Inventory・ItemGrid・ItemTransfer の中身
   ・Inventory を引数で受け取る関数（IInteractable・PickupComponent・GunComponent・HoldComponent・MagazineSync・
     InventoryScreen・InventoryCursor・InteractMarkers・Interactor）
   ・カバンの画面・漁る画面の動き

5. 外から読む所
   ・F6 の Inventory の欄：今と同じ（GameEditorBridge が渡す先が、自キャラの部品の持ち物になるだけ）
   ・F6 の Objects の欄：Player の部品の数が 1 増える

6. 変わってしまう所
   ・自キャラの形の構築に失敗して自キャラが置けなかったとき：今は持ち物だけある（使う所は無い）。後は持ち物も無い。
     F6 の Inventory の欄は、持ち物が無いときの表示になる
   ・PlayerComponent が持ち物を借りる時：今は毎ティック setInput で受け取る。後は start で 1 回借りる（同じ物・同じ中身）
   ・処理の順番・数値・計測の印・ログの文字・保存ファイルは変えない

7. 決めてほしい所（★）
 ★1 InventoryComponent は自キャラに必須か、外せるか
     A（おすすめ）必須。PlayerComponent が start で requireComponent する。今も持ち物が無いと ASSERT で止めている
     B 外せる。使う所ごとに getComponent し、無ければ飛ばす（外すと、銃を持てない・リロードできない・拾えない・カバンを開けない）。
       読む所の全部に「無ければ」の枝が増える
 ★2 始めのカバンを自キャラへ渡す道
     A（おすすめ）GameWorld のコンストラクタの引数（今日の条件と同じ道。どちらも RaidStart が決める出撃の始めの形）
     B GameWorld::placeActors の引数（自キャラを置く時に渡す。LoadingPhase・GameLoader のコンストラクタにも引数が増える）
 ★3 シーンの係（Hud・Bag・Loot）の持ち方
     A（おすすめ）使うたびに自キャラから引く。作るときの Inventory* を消す
     B ロードが済んだ時に 1 回だけ渡す（setInventory）。今の形に近いが、渡し忘れと、自キャラより長く覚え続ける心配が残る

8. 手順
   1. InventoryComponent を作る。vcxproj と filters に登録する
   2. GameWorld のコンストラクタと PlayerFactory::spawn に始めのカバンを通し、自キャラへ付ける
   3. PlayerComponent：setInput から inventory を消し、start で借りる。GameWorld::update の引数を消す
   4. HudController・BagController・LootController・GameEditorBridge を、自キャラから引く形に替える
   5. GameScene の mInventory を消す
      （2〜5 は途中の状態では持ち物が 2 つあって食い違うので、5 まで進めてからビルドして確かめる）
   6. Debug・Profile・Release の 3 構成でビルド
   7. この仕様書の状態欄、GameChats/ComponentSystem.md、メモリを更新

9. 画面で確かめる所
   ・始めのカバンに拳銃と 9mm の弾が入っていて、始めから拳銃を持っている。弾倉の数が合っている
   ・Tab でカバンが開く。並べ替え・捨てる・使う（包帯）・持ち替えができる
   ・落ちている物を E で拾える。入らないときはマークが灰色になる
   ・木箱・ゴミ箱を漁って、カバンとの間で物を動かせる。ライフルを取ると持てる
   ・リロードで予備の弾が減る。右下の予備の弾の数が合っている
   ・給油口へガソリンを入れられる
   ・F6 の Inventory の欄で物を足せる・行を増やせる
   ・F6 の Objects の欄で、Player の部品の数が 14 になっている
