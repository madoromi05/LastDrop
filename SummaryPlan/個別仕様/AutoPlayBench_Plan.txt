 ・人が操作しなくても、ゲームの中で自キャラが勝手に動き（歩く・撃つ・弾を込める・ゾンビを出す・給油する）、
   その間の数字を勝手に記録するツール（2026-10-28。CSV を比べるツール PerfCompare とは別）
 ・実装は仕様の承認の後

 聞きたいこと（★）

 ★Q1. 自キャラの動かし方
     案 A（おすすめ）：シナリオ（行動の並び）を上から順に実行する。行動の中身は自分で動く
       例：「ガソリンまで歩く」は道を自分で探して歩く、「近いゾンビを撃つ」は自分で狙う。並びは毎回同じ
       → 毎回同じ流れになるので、最適化の前後を比べられる。「何を測ったか」をシナリオの名前で言える
     案 B：自分で考えるボット。ガソリンを探す → 車へ運ぶ → 寄ってきたゾンビを撃つ、を勝手に繰り返す
       → 長く放っておく確認（落ちないか・重くならないか）には向くが、毎回流れが変わるので前後の比較には向かない
     案 C：人の操作を録って、そのまま再生する
       → 作るのは楽そうに見えるが、少しでも場面がずれると（ゾンビの位置が 1 歩違うなど）、撃つ方向が合わずに崩れる
     ※ 案 A で作っておけば、B は「ループする行動」を後から足せる（11 章）

 ★Q2. 始め方
     案 A（おすすめ）：両方作る
       ・起動の引数：LastDrop.exe -autoplay town_combat
         メニューを飛ばしてゲームを始め、シナリオを走らせ、終わったらゲームを閉じる。
         tools/autoplay.bat をダブルクリックすれば Profile ビルドで走る（放っておけば数字ができている）
       ・F6 のエディタの AutoPlay 欄：シナリオを選んで Start / Stop。終わってもゲームは閉じない（見ながら直す用）
     案 B：F6 の欄だけ（毎回自分でゲームを始めてボタンを押す）

 ★Q3. 計測の中身
     案 A（おすすめ）：
       ・走り始めに VSync を自動で切り、終わったら戻す（10-27 に分かった「VSync が入っていると gpuMs に待ちが入る」を避ける）
       ・走り始めに F7 の記録を自動で始め、終わったら止める（今と同じ perf_*.csv と _system.json が出る）
       ・行動ごとに区切り、行動ごとの平均・p95・p99・最大を表にした autoplay_<シナリオ名>_<時刻>.md も書く（6 章）
     案 B：F7 の記録を自動で始め・止めるだけ（行動ごとの表は作らない。CSV を自分で見る）

 ★Q4. 走っている間の決まり
     案 A（おすすめ）：
       ・自キャラは無敵（F5 と同じ）。噛まれて死んで途中で止まらないようにする
       ・乱数の種はシナリオに書いた数で決める（ゾンビの倒れ方・湧く場所・ガソリンの置き場所）。7 章
       ・ゾンビが勝手に湧くのを止める（ZombieSpawner）。出すのはシナリオの SpawnZombies だけ。数が毎回同じになる
     案 B：無敵だけ入れ、ほかはふつうに遊ぶときと同じ（湧く場所・数が毎回違う）

================================================================================
 1. 目的
================================================================================
 ・人が同じ動きをしなくても、毎回同じ場面・同じ流れで負荷をかけ、数字を取れるようにする
   （今は自分で歩いて F9 でゾンビを出して F7 を押しているので、記録ごとに場面がずれる）
 ・最適化の前と後で同じシナリオを走らせれば、その差がそのまま「最適化の効果」になる（ポートフォリオの「計測した数字」）
 ・「撃った瞬間」「ゾンビ 20 体が追ってくる間」「給油した瞬間」など、ゲームの出来事ごとの重さを分けて見られる
 ・長く走らせて、落ちない・だんだん重くならない（物が消えずに増えていく など）ことの確認にも使う

================================================================================
 2. タルコフでは／ほかのゲームでは
================================================================================
 開発用の道具で、遊ぶ人には見えない物なので、タルコフは調べない（DebugTools_Profiling_Plan.txt の 5-5・5-6 と同じ）。
 代わりに、ほかのゲーム・エンジンが自動のプレイと計測をどうしているかを調べた（12 章）。

 ・Unreal Engine：Gauntlet という「ゲームを起動して、テストを走らせ、結果を集める」仕組みがある。
   その上の AutomatedPerfTest は、決まった動き（シーケンス）や録った試合（リプレイ）を自動で再生して性能を集める
   （AutomatedPerfTest については掲示板の書き込みで知った話で、公式の文書では確かめられなかった）
 ・ベヨネッタ 2（CEDEC 2016）：オートプレイでゲームを進めながら、CPU・GPU・メモリを毎日測り続け、ブラウザで推移を見た
 ・ソニー（CEDEC 2024）・カプコン（CEDEC 2026）：人と同じ条件で遊ぶ AI でテストを自動にしている（バグ探しが主な目的）

 合わせる所：起動の引数で「起動 → 決まった動き → 記録 → 終了」を人の手なしで回す（Gauntlet・ベヨネッタ 2 と同じ）
 あえて変える所：AI やリプレイではなく、行動の並び（シナリオ）にする。目的が「前後の比較」なので、毎回同じ流れになることを一番にする
                 （Q1 の案 C の理由のとおり、リプレイは場面が少しずれると崩れる。このゲームはまだ乱数の種を固定できない）

 3. 今ある物（2026-10-28 に調べた）
================================================================================
 ・PlayerCommand（GameSrc/Player/PlayerCommand.h）：自キャラへの 1 フレームぶんの操作。前後・横・走る・武器を出す・覗く・撃つ・弾を込める。
   コメントに「AI・リプレイなど、操作の出どころが変わっても PlayerCharacter には波及しない」とあり、ここに自動の操作を差し込める
 ・FirstPersonControl：Pad とマウスを読んで、視点を回し PlayerCommand を作る。readInputIdle（何もしない操作）もある
 ・「使う」（拾う・給油）は PlayerCommand に入っておらず、GameScene::updateInteraction が InputInteract() を直接読んでいる
 ・GameWorld::spawnZombie( 位置, 向き )：ゾンビを 1 体出す（F9 と同じ道）
 ・StreetGraph::findPath( 始め, 行き先, … )：ゾンビが建物を回り込む道探し（A*）。自キャラの「そこまで歩く」にも使える
 ・Profiling：toggleRecording（F7）・markEvent（印）・FrameRecorder::isRecording。記録の始め／止めを別々に呼ぶ口は無い
 ・Graphics::Manager::setVSync：F6 の VSync の切り替えと同じ
 ・WindowCreator::commandLineString：起動の引数を読める（今はどこも使っていない）
 ・乱数の種：ゾンビ用（GameWorld.cpp 139 行）とガソリンの置き場所（225 行）が、起動からの時間（Framework::time）で決まっている
 ・ワールドの状態の保存（DebugTools_Profiling_Plan 5-6。WorldSnapshot）は、計画はあるがコードには無い
   （メモには 10-25 実装済みとあったが、今のコードに WorldSnapshot・SnapshotPanel・Auto spawn は見つからなかった）

 4. 使い方
================================================================================
 （Q2 が案 A の場合）

  全部自動（放っておく）：
    tools\autoplay.bat town_combat
      → Profile ビルドのゲームが起動 → シナリオ AutoPlay/town_combat.xml を走らせる → 閉じる
      → Profiling/<起動時刻>/ に perf_*.csv・_system.json・autoplay_town_combat_*.md ができる
    回数を指定：tools\autoplay.bat town_combat 3   （同じシナリオを 3 回。ぶれの大きさが分かる）

  見ながら（F6）：
    F6 → AutoPlay 欄 → シナリオを選ぶ → Start
      ・走っている間の行動の名前・残り時間・経った時間を出す
      ・Stop で止める（それまでの分を書き出す）
      ・マウスかキーを触ったら止める、はしない（F6 で値を見る・変えるのに Alt でマウスを使うため）。止めるのは Stop と ESC

  シナリオのファイル：AutoPlay/<名前>.xml（PseudoXml。git に入れる。前後の比較で同じファイルを使い続けるため）

 5. 行動（シナリオに書ける物）
================================================================================
 1 行が 1 つの行動。上から順に実行し、終わったら次へ進む。どの行動にも timeout（秒）を付けられ、
 その時間で終わらなければ「時間切れ」と表に出して次へ進む（道が見つからない・ゾンビがいない などで止まり続けないように）。

  行動              中身                                                              主な書く物
  ----------------  ----------------------------------------------------------------  -------------------------------
  Wait              その場で立ち止まる                                                seconds
  MoveTo            行き先まで歩く／走る。道は StreetGraph::findPath で探す           target（座標・fuel・car）, run
                    fuel は一番近いガソリン、car は脱出用の車
  LookAround        その場で決まった速さで 1 周回る（映る物を変えて描く重さを見る）  degreesPerSecond, turns
  Holster           武器を出す／しまう                                                なし
  SpawnZombies      自キャラの前に、横に並べてゾンビを出す（F9 と同じ道）            count, distance
  ShootNearest      見えている一番近いゾンビを狙って撃ち続ける。弾が切れたら込める   seconds, part（head・body）
                    ゾンビが居なくなったら終わる
  Reload            弾を込める（込め終わるまで待つ）                                 なし
  Interact          見ている物を使う（拾う・給油）                                   なし
  Refuel            MoveTo fuel → Interact → MoveTo car → Interact をまとめた物       なし
  Repeat            中に書いた行動を決まった回数くり返す                              count

 例：AutoPlay/town_combat.xml
    <AutoPlay version="1" seed="12345" invincible="1" autoSpawn="0">
      <Wait seconds="2"/>                                  <!-- ロード直後のばらつきを捨てる -->
      <LookAround degreesPerSecond="90" turns="1"/>        <!-- ゾンビ無しの町を描く重さ -->
      <SpawnZombies count="10" distance="12"/>
      <Wait seconds="3"/>                                  <!-- 10 体が追ってくる間 -->
      <ShootNearest seconds="20" part="body"/>
      <Reload/>
      <SpawnZombies count="20" distance="15"/>
      <ShootNearest seconds="30" part="head"/>
      <Refuel timeout="60"/>
    </AutoPlay>

 自キャラへの操作の作り方
  ・行動は PlayerCommand（前後・横・走る・覗く・撃つ・弾を込める）と、視点の回す量（度）と、「使う」を出すだけ。
    PlayerCharacter・GameWorld の中には手を入れない（人が遊ぶときと同じ道を通るので、測る数字も人が遊ぶときと同じになる）
  ・狙うのは視点を回して行う（人がマウスで狙うのと同じ。照準のぶれ・反動もそのまま効く）。1 ティックに回す量には上限を付ける
    （一瞬で振り向くと、人の遊び方と描く物が変わってしまうため）

 6. 計測と出す物
================================================================================
 （Q3 が案 A の場合）
 ・走り始め：VSync を切る → F7 の記録を始める
 ・行動を始めるたび：印を付ける（PROFILE_EVENT。CSV の events 列に AutoPlay.ShootNearest などが入る）
                     CSV に step 列を足し、今どの行動か（シナリオの何行目か）を入れる
 ・走り終わり：記録を止める（perf_*.csv と _system.json を書く）→ VSync を元に戻す → 行動ごとの表を書く

 autoplay_<シナリオ名>_<時刻>.md（Markdown。技術まとめにそのまま貼れる）
  ・見出し：シナリオ名・種・回数・ビルドの種類・描く大きさ・CPU と GPU の名前・VSync（切ってあること）
  ・表 1：行動ごと（行目・行動・かかった秒・フレーム数・frameMs / cpuMs / gpuMs の平均と p99・最大・時間切れか）
  ・表 2：シナリオ全体（同じ列。平均の FPS と 1% low の FPS も）
  ・表 3：重かったフレームの上位 5 つ（何行目の行動の、何フレーム目か・印）。スパイクの JSON の名前も並べる
  ・数え方は PerfCompare_Plan.txt の 5 章と同じ（p95・p99 は Excel の PERCENTILE.INC と同じ線形の補間）

 計算する場所：記録している FrameRecorder（GameLib）が、止めたときに CSV と一緒に書く。
   GameLib の Profiling に「記録を始める（名前付き）／止める」「今の区切り（step）を決める」口を足す（9 章の部品）

 7. 毎回同じ場面にする
================================================================================
 （Q4 が案 A の場合）
 ・乱数の種：GameWorld::place に種を渡す形を足す。渡さなければ今と同じく起動からの時間（ふつうに遊ぶときは毎回違う）
   → ゾンビの倒れ方・個体差・ガソリンの置き場所が毎回同じになる
   （ワールドの状態の保存 5-6 の「種を決める所」と同じ物。こちらを先に作れば 5-6 でも使える）
 ・ZombieSpawner を止める口を足す（走っている間は勝手に湧かない）
 ・自キャラは町の始めの場所（TownMap::playerStart）から始める。シナリオの始めにシーンを作り直す（Retry と同じ道）
 ・行動はティックごと（1/60 秒の固定の歩み）に進める。描画の回数（フレームの速さ）に左右されない
   → 速い PC でも遅い PC でも、同じ時刻に同じ行動をしている

 それでも完全には同じにならない所（10 章）
  ・音・GPU の待ち時間・Windows の割り込みなど、ゲームの外のぶれ
  ・1 回の描画で進むティックの数（0〜5）は PC の速さで変わる。世界の進み方は同じだが、描く回数は変わる

 8. 部品と処理の流れ
================================================================================
 ゲームのコード（ZF_EDITOR の中だけ。Release には入らない）

  新：GameSrc/DebugMode/AutoPlayScenario.h/.cpp   シナリオのファイルを読み、行動の並びにする（PseudoXml）
      GameSrc/DebugMode/AutoPlayAction.h/.cpp     行動 1 つの窓口（interface）と、5 章の行動ごとの実装
                                                  1 ティック進めて「PlayerCommand・視点の回す量・使うか・終わったか」を返す
      GameSrc/DebugMode/AutoPlayer.h/.cpp         並びを上から実行する係。計測の始め／止め・VSync・無敵・湧きを止める も ここ
      GameSrc/DebugMode/AutoPlayPanel.h/.cpp      F6 の AutoPlay 欄
  直：FirstPersonControl   readInput の代わりに、渡された操作と回す量を使う readScripted を足す（カーソルロックの扱いは readInputIdle と同じ）
      GameScene            AutoPlayer があれば、beginFrame で readScripted、update で AutoPlayer を 1 ティック進める。「使う」も AutoPlayer から
      GameWorld            種を渡す place・ZombieSpawner を止める口
      SceneManager / Framework  起動の引数 -autoplay を読み、メニューを飛ばしてゲームを始め、終わったら閉じる
      EditorWindow         AutoPlay 欄を足す
  GameLib：Profiling に startRecording( 名前 ) / stopRecording / setSection( 番号, 名前 ) と、止めたときの行動ごとの表の書き出しを足す
           （今の toggleRecording は startRecording / stopRecording を呼ぶ形にする。F7 の動きは変えない）

  ほか：tools/autoplay.bat（Profile の exe を -autoplay 付きで起動。回数の指定）
        AutoPlay/town_combat.xml（最初のシナリオ。5 章の例）

 影響範囲：ふつうに遊ぶとき（-autoplay なし・F6 で Start しない）は、通る道は今と同じ（種は今と同じ・湧きも止めない）。
 修正の入口：行動を足すときは AutoPlayAction に 1 つ足し、AutoPlayScenario の名前の表に 1 行足すだけ。

 9. 確かめ方
================================================================================
 ・Debug・Profile・Release のビルドが警告なしで通る（Release には AutoPlay が入らない）
 ・tools\autoplay.bat town_combat で、人が触らずに 起動 → シナリオ → 閉じる まで進み、3 つのファイルができる
 ・同じシナリオを 2 回走らせると、ガソリンの置き場所・ゾンビの数・行動の順番と秒数が同じになる
 ・表 1 の行動ごとのフレーム数を足すと、全体のフレーム数になる
 ・行動ごとの frameMs の平均が、CSV をその step で絞って Excel の AVERAGE をとった値と同じ
 ・走り終わった後、VSync が元に戻っている。F7 を自分で押したときの動きは今と同じ
 ・道が見つからない行き先・ゾンビの居ない ShootNearest で、時間切れになって次へ進む（止まり続けない）

 10. 懸念点
================================================================================
 ・自キャラの道探し：StreetGraph はゾンビ用なので、自キャラの体の大きさで通れない所を通そうとすることがある
   → timeout で次へ進む。引っかかりやすい所は、シナリオに座標の MoveTo を足して避ける
 ・ShootNearest が狙う「見えている」ゾンビの決め方：視線が建物に当たらないか（HitWorld に聞く）で決める。狙っている間にゾンビが建物の陰へ入ると次を探す
 ・前後でコードを変えると、同じシナリオでも流れが変わることがある（ゾンビの動きを変えた、など）。
   そのときは行動ごとのかかった秒・フレーム数が変わるので、表で気付ける
 ・作業の大きさ：行動 10 個・種の固定・起動の引数・GameLib の口で、今までの手順 5（調整値）と同じくらい。
   先に「Wait・LookAround・SpawnZombies・ShootNearest・Reload」と起動の引数だけを作り、MoveTo・Interact・Refuel を次に回す分け方もできる

 11. 後回しにする物
================================================================================
 ・自分で考えるボット（Q1 の案 B）：「Loop」行動として、ガソリン探し → 給油 → ゾンビを撃つ を時間まで繰り返す物を後から足せる
 ・何回か走らせた結果を並べて推移を見る（ベヨネッタ 2 のような毎日の計測。PerfCompare の 3 つ以上の比較とまとめて考える）
 ・メモリの量の記録（今の CSV にはメモリの列が無い）
 ・ワールドの状態の保存（5-6）から始めるシナリオ（<AutoPlay snapshot="..."> で、途中の場面から始める）
