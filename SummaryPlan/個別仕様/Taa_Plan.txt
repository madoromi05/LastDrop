 Q1. 前のフレームのどこを読むか（動きの求め方）
     ★A：速度の描画先は作らない。深度とカメラの「前のフレームの射影×ビュー」から、その画素の 1 フレーム前の画面の位置を出す
          （動かない物はこれで正しい）。動く物は G-Buffer の RT1 の a（今は予備）に「動きの種類」を書いて分ける（6 章）：
            手元（自キャラの腕・銃・弾）… カメラと一緒に動くので、画面の上ではほぼ止まっている → 同じ画素の前の色を読む
            ゾンビ・千切れた手足 … 歩く速さ（1m/s ほど）の分だけずれる → 深度から戻した位置を読み、近傍の色で強めに抑える（7-4）
          ・G-Buffer に描画先を足さず、キャラに前のフレームの骨の行列も要らない（Graphics_Spec.txt 11 章の弱点がほぼ消える）
          ・速度が正確でない分、ゾンビの縁は少しぼけやすい。画面で目立ったら B にする
      B：速度の描画先（RT3。RG16F）を足す。動かない物は前のフレームの射影×ビュー、キャラは前のフレームの骨とワールドの行列から
          頂点ごとに前の位置を出して書く（SkinningPipeline に前の骨の定数を足す）。正確だが、描く物すべてに手が入る

 Q2. 画面のずらし方（1 画素より細かく、毎フレーム少しずつカメラをずらす）
     ★A：Halton 列（2・3 を底）の 8 個を繰り返す。射影の行列に「画素の何分の 1」を足すだけ（5 章）
      B：16 個（なめらかだが、1 周が長く、止まっていても収まるまでに時間が掛かる）

 Q3. TAA をどこに入れるか
     ★A：霧の後・半透明の板の前（シーンの色が HDR のうち。ブルームの前）
          ・半透明の板（砂ぼこり・マズルフラッシュ）は深度を書かず動きも取れないので、TAA を通すと残像が出る（マズルフラッシュの光の尾）
          ・ブルームの前なので、光る物のにじみも TAA を通った後のなめらかな色から作る
      B：半透明の板の後（板もなめらかになるが、マズルフラッシュに残像が出る）

 Q4. FXAA との関係
     ★A：F6 → Render のアンチエイリアスを「Off / FXAA / TAA」の 1 つから選ぶ形にし、初期値は TAA。TAA のときは FXAA を通さない
          （両方掛けるとぼけが重なる。タルコフも同じ欄から 1 つ選ぶ。1 章）
      B：TAA の後にも FXAA を掛ける（ゾンビの縁など、TAA が抑えきれない所も消えるが、全体がもう 1 段ぼける）

 Q5. ぼけへの対策（タルコフでは TAA のぼけを Sharpness で戻すのが定番。1 章）
     ★A：前のフレームの色を読むときに Catmull-Rom（なめらかな 3 次の補間。5 回の読み込みの近似）を使い、読み直すたびにぼけていくのを抑える。
          仕上げのシャープは段階 8 では入れない（画面で見て、ぼけが気になったら足す）
      B：TAA の後にシャープのパス（AMD の CAS のような、輪郭だけを強める物）を足し、強さを F6 で動かす

 Q6. SSAO・SSR・ディザのノイズを毎フレーム動かすか（段階 5〜7 では「TAA が無いので動かさない」と決めていた）
     ★A：動かす。IGN にフレームの番号でずらしを足す（8 章）。TAA が何フレームかを均すので、同じ点の数でざらつきが減る。
          SSAO・SSR のぼかしは今のまま残す（TAA を切ったときに戻るため）
      B：動かさない（今のまま）

 Q7. 履歴（前のフレームの絵）を捨てる時
     ★A：シーンを作り直したとき・観察用カメラ（F4）の切り替え・暗転から戻ったとき・TAA を ON にしたとき。それ以外は捨てない
          （画面の外から入ってきた所・物の陰から出てきた所は、7-3 の「画面の外」と 7-4 の近傍の色で抑える）
      B：前のフレームの深度も持ち、深度が大きく違う画素は履歴を捨てる（物の陰から出てきた所の残像は減るが、深度をもう 1 枚持つ）

 Q8. 遊ぶ人の設定（Options）に足すか
     ★A：段階 8 では足さない（F6 だけ）。アンチエイリアスの選択は、決めてある画質の設定のタスク（段階 6 の Q8・段階 7 の Q10）でまとめて足す
      B：Options に「アンチエイリアス：Off / FXAA / TAA」を足す

 1. タルコフでは
================================================================================
 アンチエイリアスの欄
  ・Off / FXAA / TAA / TAA High から 1 つ選ぶ。DLSS・FSR を使うときは、アップスケーラが AA も兼ねるので AA の欄は使わない（段階 5 の 1 章と同じ）
  ・攻略は TAA（か TAA High）を勧める物が多い。「遠くの金網のフェンスや草のちらつきが消えるのは TAA だけ」（BetterFPS 1.1.0.1 向け）。
    FXAA は「FPS を取りたいとき」の代わり、とする攻略もある
  ・TAA のぼけは Sharpness で戻すのが定番で、勧める値は攻略ごとにばらばら（0.5〜0.7・0.7〜0.8 など。上げすぎると縁にちらつき）
  ・TAA・TAA High で残像が出る、という報告がある（特にサプレッサーの周り。遊ぶ人の書き込み）
  ・倍率の高いスコープを覗くときは、DLSS・FSR より TAA を勧める記事がある（アップスケーラを使うとスコープの中が低い解像度で描かれるため）
 アップスケーラ
  ・0.12.12.15.4（2022-04）で DLSS 2.3.1 を入れ、Streets of Tarkov（0.13）の頃に FSR 2.1、0.13.0.4（2023-04）で DLSS 2.5.1・FSR 2.2 へ更新した
 このゲームへの当てはめ
  ・遊ぶ人は TAA のちらつきの少なさを選び、ぼけは Sharpness で戻している → まず TAA のぼけを作りで減らし（Q5 の Catmull-Rom）、
    シャープは画面を見てから
  ・残像は「動く物の周り」に出る → 動きの種類を分けて、手元は画面の上で止まっている物として扱う（Q1）。マズルフラッシュは TAA を通さない（Q3）
  ・アップスケーラ（DLSS・FSR）は入れない。ただし、ずらし・前のフレームの位置・履歴は同じ材料なので、TAA の作りはその土台になる（Graphics_Spec.txt 11 章）

 2. 今のコードで関係するところ
================================================================================
  ・GameScene::draw（2026-10-30）
      影 → G-Buffer（drawStatic → デカール → drawDynamic：自キャラ・弾 → ゾンビ・千切れた手足）→ SSAO → ライティング → SSR → 混ぜる → 霧 →
      半透明の板（読み取り専用の深度）→ 当たり判定の表示 → endScene（ブルーム → Present.hlsl：ToneMap・グレーディング・ディザ → FXAA）
  ・カメラ：FirstPersonCamera::projectionViewMatrix（setPerspectiveTransform）。GameScene が SSAO・SSR・デカール・霧・板へ同じ行列を渡している
    （ずらしを入れれば全部のパスが同じずれで揃う）
  ・G-Buffer：RT1 RGBA16F の a は予備（writeGBuffer が kSpare 0 を書く）。b3 の材質値は 4 つとも使っている（w は水たまり）
  ・キャラ：SkinningPipeline（b1 に骨）。前のフレームの骨は持っていない
  ・ノイズ：Noise.hlsli の interleavedGradientNoise（ディザ・SSAO の角度・SSR の歩き始め）。どれもフレームごとには動かしていない
  ・PostProcess：シーンの色 RGBA16F・深度 D32。FXAA は 8bit の中間を通す（fxaaEnabled）
  ・観察用カメラ（FreeCamera。F4）は Debug だけ。シーンの作り直しは SceneManager
  ・GPU の印は 1 フレーム 20 個まで（GpuTimer::kMaxMarks。今 16 個）

================================================================================

 5. 画面のずらし（8-a。Q2 の A）
================================================================================
  ・フレームの番号 i（0〜7 を繰り返す）の Halton 列（底 2 と 3）から、−0.5〜0.5 画素のずれ (jx, jy) を作る
  ・射影の行列の「x と y にずらしを足す」所（クリップの xy に jx × 2 / 幅 × w、jy × 2 / 高さ × w を足す）だけを変える。
    FirstPersonCamera に「ずらした射影×ビュー」と「ずらしていない射影×ビュー」を両方持たせ、描く物には前者、TAA の位置の計算には後者を使う
  ・前のフレームの「ずらしていない射影×ビュー」を GameScene が覚えておく（TAA が前の画面の位置を出すのに使う）
  ・TAA を切っている間は、ずらしを 0 にする（今と同じ絵）

 6. 動きの種類の印（8-a。Q1 の A）
================================================================================
  ・RT1 の a に書く：0 動かない物（建物・車・置物・地面・デカール）、1 手元（自キャラの体・腕・銃・弾）、0.5 動く物（ゾンビ・千切れた手足）
  ・書き分けは GBuffer の定数（b4。今は水たまりの値が入っている）に「今描いている物の動きの種類」を足し、writeGBuffer が書く。
    GameScene が描く物の切り替わりで GBuffer::setMotion を呼ぶ（GameWorld::drawDynamic を自キャラ・弾と、ゾンビ・手足に分ける）
  ・デカールは RT1 に書くが、a は「アルファで混ぜる」に使っているので、印も混ざる。デカールは動かない物にしか貼らないので、印は 0 のまま（混ぜても 0）
  ・G-Buffer の表示に「Motion」（印を色で。0 黒・0.5 青・1 赤）を足す

 7. TAA のパス（8-b）
================================================================================
 7-1. 作り
  ・GameSrc/Render/TemporalAntiAliasing.h / .cpp（新しく作る）：履歴（RGBA16F・画面の大きさ）2 枚を行き来し、Taa.hlsl で
    「今のシーンの色」と「前の履歴」を混ぜた物を新しい履歴へ書き、それをシーンの色へ写し戻す
    （シーンの色を読みながらシーンの色へは書けないので、新しい履歴へ書いてから写す。写すのは全画面 1 回）
  ・読む物：シーンの色（霧の後）・深度・RT1（動きの種類）・前の履歴。定数：今の「ずらしていない射影×ビュー」の逆・前の「ずらしていない射影×ビュー」・
    今のずらし・値（7-5）

 7-2. 前のフレームの位置
  ・動かない物・動く物：画素の深度から（ずらしを除いた位置で）ワールドの位置を戻し、前の射影×ビューで画面へ戻した所 = 前の位置
  ・手元：同じ画素（前の位置 = 今の位置）

 7-3. 混ぜ方
  ・前の位置が画面の外なら履歴を使わない（今の色だけ）
  ・前の履歴は Catmull-Rom（5 回の読み込み。Q5 の A）で読む
  ・新しい色 = lerp( 今の色, 抑えた履歴の色, historyWeight )。historyWeight 初期値 0.9（動く物は movingHistoryWeight 0.8、手元は firstPersonHistoryWeight 0.85）
  ・混ぜる重みは明るさで割り戻す（Karis の「1 / (1 + 明るさ)」）。HDR の明るすぎる 1 画素（街灯の芯）が履歴に焼き付いて点滅しないように

 7-4. 近傍の色で抑える（残像を消す）
  ・今の画素の周り 3×3 の色を YCoCg（明るさと色の差）にして、平均と広がり（標準偏差）から箱を作り、履歴の色をその箱の中へ寄せる
    （Salvi の分散で切る方法）。箱の広さ γ は 1.0（動かない物）・0.75（動く物）・1.0（手元）が初期値
  ・物の陰から出てきた所・ゾンビが通った後ろは、履歴の色が箱の外になるので、今の色に近づく

 7-5. 値（TaaParams。F6 → Tuning）
  ・historyWeight 0.9・movingHistoryWeight 0.8・firstPersonHistoryWeight 0.85・clipGamma 1.0・movingClipGamma 0.75
  ・antiAliasingMode()（F6 → Render。Off / FXAA / TAA）
  ・どれも見た目を確かめる前の初期値

  ・Graphics_Spec.txt 13 章の目標（ToneMap・FXAA 0.5ms）と比べ、技術まとめ 8 章⑫に足す
  ・手順（2026-10-30。ユーザーが録る。F7 は押すたびに記録の開始／停止で、開始ごとに別の CSV になる）

      GPU の印が 20 個の上限に入っているので、今回は gpu.Effects・gpu.PostProcess・gpu.FXAA の列も CSV に出る（段階 7 の記録では消えていた）
      録ったら CSV のフォルダ（Profiling/<日時>/）を教えてもらい、こちらで集計する

 13. 実装で仕様から変えた所（8-a）
================================================================================
  ・作ったもの
      TemporalJitter（GameSrc/Render）：Halton（底 2・3）の 8 個のずらし。advance( TAA か ) で進み、TAA でないときは 0 に止める。
        apply( 射影×ビュー, 幅, 高さ ) が行列の 1・2 行目に「ずらし × 4 行目」を足す。frameIndex（8-c のノイズに使う）
      GameScene::draw：カメラを置いた後に、ずらした行列で Manager の射影×ビューを上書きし、G-Buffer・デカール・SSAO・ライティング・SSR・霧・
        半透明の板・G-Buffer の表示へ同じ行列を渡す（映る範囲 ViewFrustum と影はずらさない）
      AntiAliasing（PostProcessParams.h）：Off / FXAA / TAA。fxaaEnabled() をやめて antiAliasingMode() にした（F6 → Render のコンボ）
      MotionKind（GBuffer.h）：Static・Moving・FirstPerson。GBuffer::setMotion が b4 の定数へ書き、writeGBuffer が RT1 の a に書く（0・0.5・1）
      GameWorld：drawDynamic を drawFirstPerson（自キャラ・弾）と drawCharacters（ゾンビ・千切れた部位）に分け、GameScene が間で setMotion
      G-Buffer の表示「Motion」（黒 動かない物・青 動く物・赤 手元）
      GameLib：BLEND_LINEAR_KEEP_ALPHA（色はアルファで混ぜ、描画先のアルファは書き換えない）。デカールはこれで描く
  ・ずらしは FirstPersonCamera に持たせず、GameScene がカメラの行列に足す（TemporalJitter）。FirstPersonCamera と観察用カメラ（FreeCamera）の
    どちらでも同じに効き、カメラのクラスに手を入れずに済む。「ずらしていない射影×ビュー」は camera.projectionViewMatrix() のまま
  ・6 章の「デカールは RT1 の a も混ぜるが 0 のまま」は間違いだった。GameLib の BLEND_LINEAR はアルファを「描いた物のアルファ」で上書きする
    （SrcBlendAlpha ONE・DestBlendAlpha ZERO）ので、弾痕の下の壁が 1（手元）と読まれる。描画先のアルファを残す混ぜ方を GameLib に足した
  ・b4 の定数（水たまりの値）は GBufferPassConstants に名前を変え、動きの種類 gMotion を足した（G-Buffer へ描く間ずっと同じ値の入れ物）
  ・アンチエイリアスの初期値は 8-a では FXAA のまま（TAA の混ぜるパスが無いと、ずらしだけで画面が震えるため）。8-b で TAA にする
  ・ずらしは Halton の 1 番目から使う（0 番目は (0, 0) で、1 周の中に「ずらし無し」が入るため）
  ・確かめたこと：シェーダを fxc で全部（最適化あり・-Od とも新しい警告なし）、Debug / Release / Profile のビルド。画面はユーザーの確認待ち（10 章の 8-a）

 14. 実装で仕様から変えた所（8-b）
================================================================================
  ・作ったもの
      Resource/Shader/Taa.hlsl：動きの種類で前の位置を分け（手元は同じ画素）、前の履歴を Catmull-Rom（5 回の読み込み）で読み、
        周り 3×3 の YCoCg の平均と標準偏差の箱へ寄せ、明るさで割り戻した重みで混ぜる。今の色は t6、前の履歴は t7（GBuffer.hlsli の t2〜t5 と重ならない番号）
      Resource/Shader/TaaCopy.hlsl：新しい履歴をシーンの色へ写し戻す
      TemporalAntiAliasing（GameSrc/Render）：履歴 2 枚（RGBA16F）・前のフレームのずらしていない射影×ビュー・履歴が使えるか。resolve と invalidate
      TaaParams：historyWeight 0.9・movingHistoryWeight 0.8・firstPersonHistoryWeight 0.85・clipGamma 1・movingClipGamma 0.75・firstPersonClipGamma 1
        （F6 → Tuning の TAA）
      GameScene::draw：霧の後に resolve と GPU の印「TAA」。アンチエイリアスの初期値を TAA にした
  ・7-5 の箱の広さは、手元の分も調整できるよう firstPersonClipGamma を足した（7-4 の表の 1.0 を初期値に）
  ・Q7 の「履歴を捨てる時」：
      シーンの作り直し … TemporalAntiAliasing もシーンと一緒に作り直されるので、最初は履歴が無い
      観察用カメラ（F4）の切り替え … 見ているカメラ（GameScene::viewCamera の返す物）が前のフレームと違ったら捨てる（ZF_EDITOR で囲まずに済む）
      TAA を ON にしたとき … TAA 以外の間は毎フレーム捨てておく
      G-Buffer の表示の間（ライティングを描かない）… 捨てる
      画面の大きさが変わったとき … 履歴の描画先が作り直されて空になるので捨てる（仕様に無かったので足した）
      暗転から戻ったとき … 今の作りでは死んだ後の暗転は GameOver のシーンへ進む（戻ってこない）ので、何もしていない
  ・9 章の表示「TAA history」（履歴の重み）は作っていない。画面で残像の場所を探すのに要るようなら足す
  ・確かめたこと：シェーダを fxc で全部（最適化あり・-Od とも警告なし）、Debug / Release / Profile のビルド。画面はユーザーの確認待ち（10 章の 8-b）
