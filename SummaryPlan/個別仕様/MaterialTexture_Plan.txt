 Q1. ORM を作る物
     ★A：建物（building・building_noground）・銃（rifle・rifle_mag）・ゾンビ・自キャラ（2 つの部分）に、
          落ちている弾（ammo_drop）と飛ぶ弾頭（bullet_tip）を足す
          ・弾は元の画像に Roughness・Metallic がある（車・ガソリン缶と同じ作りで済む）。今は粗さ 0.35・金属 1 で一様。
            懐中電灯で照らすと薬莢の真鍮と弾頭の色の違いが出る
      B：建物・銃・キャラだけ（GraphicsExtra_Spec.txt の範囲のまま）

 Q2. ORM を作る道具
     ★A：新しく tools/orm_gen.py を作る（Blender をバックグラウンドで動かす。設定は tools/configs/orm/<名前>.json）。
          元の画像から作る・FBX に埋め込まれた画像から作る・色の画像から表で作る、の 3 つを 1 つの道具で扱う。
          メッシュの txt は <StaticMesh> / <Part> の行に ormmap="..." を足し、roughness・metallic を 1 にするだけ（形は変えない）。
          fbx_to_gamelib.py の設定（mesh_orm・parts の ormmap）にも同じ物を書き、作り直しても消えないようにする
          ・FBX からメッシュを作り直さないので、形・UV・アニメが変わらず、確かめる所が材質だけで済む
      B：fbx_to_gamelib.py に全部入れて、FBX から作り直す（道具は 1 つで済むが、txt が全部書き直しになり差分が大きい）

 Q3. 建物・銃の「色 → 粗さ・金属」の表（元に粗さ・金属の画像が無い物。3 章の画像を見て決めた）
     ★A：色相・彩度・明るさで材質を分け、材質ごとの値に、明るさの細かい揺れ（±0.08）を少し混ぜる。表は configs の json に書く
          建物  赤れんが（橙・彩度 0.3 以上）      粗さ 0.85  金属 0
                目地（れんがの中の明るく彩度の低い所） 0.95      0
                灰色のコンクリート（屋根・壁の帯）   0.9       0
                黒（窓の中・使っていない所）         0.8       0   （今と同じ値）
          銃    鉄（灰色。彩度 0.15 未満）           0.45      1
                削れて地金が出た所（明るい灰。明るさ 0.65 以上） 0.3  1
                木（橙茶。彩度 0.3 以上・明るさ中）  0.6       0
                赤いベークライト（弾倉・握り。赤・彩度 0.45 以上） 0.35  0
          ・表の値は ORM を作った後、F6 の G-Buffer 表示（Roughness・Metallic）で見て直す
      B：Blender で手で塗る（正確だが、ユーザーの作業が大きい）

 Q4. AO（ORM の r）
     ★A：ゾンビだけ元の Occlusion を入れる。建物・銃・自キャラ・弾は 1（陰は SSAO に任せる）
          ・建物の色の画像は Baked だが、縮めて見た限り陰はほとんど焼かれていない（れんがの模様だけ）。色の画像はそのまま
          ・自キャラの FBX には AO の画像が無い
          ・ゾンビの色の画像に陰が焼かれていて Occlusion と二重に暗くなるなら、B に戻す（画面確認で見る）
      B：全部 1（AO の画像を使わない）

 Q5. キャラの金属
     ★A：ゾンビ・自キャラとも金属 0。粗さだけ画像から作る（粗さ = 1 − 光沢）
          ・ゾンビの 2_Metallic.tga は色が全部 0（a だけ値がある。Unity の「金属 r・なめらかさ a」の形だが、金属は無い）
          ・自キャラ（Mixamo）は Specular・Glossiness の作りで、金属の画像が無い。Specular は 1001 が一様 0.22、1002 が 0.07〜0.42 で、
            金属らしい明るさ（0.5 より上）の所が無い
      B：自キャラの Specular の明るい所（0.35 より上）を金属にする（装備の金具が光るかもしれないが、布が光る誤りも出やすい）

 2. 今のコードで分かったこと（計画を書く前に調べた）
================================================================================
  ・GraphicsExtra_Spec.txt 6 章は「SkinnedMeshGBuffer.hlsl が ORM を読むように直す」としていたが、もう読んでいる。
    SkinnedMeshGBuffer.hlsl は StaticMesh と同じ GBuffer.hlsli の writeGBuffer を呼び、writeGBuffer が t11 の ORM を読む。
    SkinnedMeshLoader も MeshLoaderUtil::loadMaterial（ormmap を読む）を通る。<Part> ごとにも読める
    → 段階11 はシェーダ・C++ を変えずに、画像とメッシュの txt だけで済む
  ・ORM の無い材質は白 1 画素（粗さ = txt の数値 × 1）。今の値：建物 0.8・銃 0.5・自キャラ 0.7・ゾンビ 0.8（MeshMaterial の既定値）・弾 0.35 金属 1

 4. 作り方（tools/orm_gen.py。Q2 の A）
================================================================================
  ・動かし方："C:\Program Files\Blender Foundation\Blender 4.5\blender.exe" --background --factory-startup --python tools/orm_gen.py -- <設定>.json
  ・設定（tools/configs/orm/<名前>.json）
      "output": "Resource/xxx_orm.tga"   "size": 書き出す大きさ
      元の画像から：  "roughness": 画像（"invert": true で 1 − 値。光沢の画像）・"metallic"・"ao"（無ければ 金属 0・AO 1）
      FBX の埋め込み："fbx": FBX のパス・"roughness_image": "Ch15_1001_Glossiness"（画像の名前で探す）
      色から：        "albedo": 色の画像・"rules": [ { 色相の範囲・彩度・明るさの条件, "roughness", "metallic" }, … ]・"default"・"detail": 0.08
  ・色から作るとき：色の画像をリニアにせず sRGB の数のまま HSV にして表を引く（目で見た色と表の値を合わせやすい）。
    条件は上から順に見て、最初に合った物を使う。境目は 1 画素ずつ切り替わる（縮小の段でなめらかになる）
  ・書き出した TGA は tools/texture_to_dds.ps1 に Kind = Data で足して DDS にする

 7. 確かめる絵と計測
================================================================================
  確かめる絵（ユーザー。F6 → Render の G-Buffer 表示）
  ・Roughness：建物のれんがと目地・コンクリートが少し違う濃さ。銃の鉄（暗い）と木（明るい）が分かれる。ゾンビの傷の所が暗い（つやがある）

        画像のメモリは BC7 で 約 4+1+4+4+4+0.06 ≒ 17MB 増える。技術まとめ 8 章に足す

 8. 懸念点
================================================================================
  ・色から作った粗さは「それらしい」だけ（GraphicsExtra_Spec.txt 10 章）。気になる所（窓・銃）だけ手で直す道は残す（Q3 の B）
  ・銃の鉄を金属 1 にすると、拡散の色が消えて暗くなる（金属は色を鏡面に回す）。暗すぎたら鉄の粗さを上げるか、色の画像の明るさを見る
  ・ゾンビの 2_Metallic の a（平均 0.92）は「なめらかさ」かもしれない。使うと全身がつやつやになるので使わない（2_gloss の方が傷と合う）
  ・building_noground は building と同じ画像を使うので、ORM も 1 枚を共有する
  ・段階12（ぼけた映り込み）は粗さ 0.4〜0.7 の面で確かめる。この段階で、銃の鉄 0.45・木 0.6・自キャラの装備がその範囲に入る

 10. 実装で仕様から変えた所・決めた細かい所（2026-11-02）
================================================================================
  ・Q3 の表は、色の画像の HSV を数えてから決めた（256 に縮めて 2 次元の度数を見た）
      建物：黒 25.9%・コンクリート（彩度 0.15 未満）15.8%・目地（橙で明るさ 0.66 以上）10.2%・れんが 48.1%。
            目地は 2 章の案の「彩度の低い所」ではなく「れんがの中の明るい所」で分けた（目地も橙のままで、彩度では分からなかった）
      銃  ：削れ（灰で明るさ 0.5 以上）1.2%・鉄 69.7%・ベークライト（色相 345〜13°・彩度 0.45 以上）3.0%・木 26.1%。
            明るさ 0.65 以上の灰はほとんど無かったので、削れの下限を 0.5 にした
  ・明るさの揺れ（detail 0.08）は、周り 1/256 の幅の平均との差で付ける（周りより暗い所ほど粗く）
  ・作った ORM の平均：建物 粗さ 0.86・銃 粗さ 0.48 金属 0.71・ゾンビ 粗さ 0.92 AO 0.50（使っていない所は 0）・
    自キャラ 粗さ 0.76（体）0.57（装備）・弾 粗さ 0.33 金属 0.92
  ・txt は材質の行だけを書き換えた（git diff で各 1 行）。roughness・metallic は行の終わりへ移り、どちらも 1
  ・fbx_to_gamelib.py：mesh_orm_export（false なら ORM を書き出さず属性だけ書く）と parts の ormmap を足した。
    設定 9 つ（building・building_noground・rifle・rifle_mag・ammo_drop・bullet_tip・zombie・player）に mesh_orm / ormmap と
    roughness・metallic 1 を書いた（作り直しても今の txt と同じ材質になる。作り直しての突き合わせはしていない）
  ・ゲームを動かしての確かめはまだ（ORM はゲーム画面に入って初めて読む）。txt の ormmap の画像が全部あることだけ確かめた
  ・作ったもの：tools/orm_gen.py・tools/configs/orm/*.json（6 つ）・Resource/building・rifle・zombie・player_body・player_body1・bullet の _orm(.tga/.dds)
