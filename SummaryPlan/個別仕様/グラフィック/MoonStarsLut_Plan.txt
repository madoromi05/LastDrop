 0. 決めること（★はおすすめ）
================================================================================
 Q1. 月を水たまり・車の塗装に映すか
     ★A：映す。環境光の鏡面（LightList.hlsli の environmentLight の「その向きにちょうど見える物」）に月の円板を足す。
          粗さが低いほど、くっきり映る（粗いと周りの空の色にならす今の作りのまま薄まる）。模様は付けない（映り込みは小さく、ぼけるため）
          ・SSR は空を映せない（空は深度が一番奥で、当たる物が無い）。なので水たまりの空は今も environmentLight の色になっている
          ・雨上がりの水たまりに月が映るのは、夜の町の見せ場の 1 つ
      B：空にだけ描く（水たまりには映らない）

 Q2. 月の模様の画像
     ★A：tools/texgen/moon_gen.py で作る（512×512。丸の中に、暗い大きな斑（海）と小さなクレーターの濃淡。周りは透明）。
          puddle_gen.py と同じく乱数の種を固定し、何度作っても同じ絵にする。BC7_SRGB
          ・全体の計画（GraphicsExtra_Spec.txt Q11）のとおり
      B：NASA の月の画像（CGI Moon Kit。パブリックドメイン）を縮めて使う（本物の月の模様になるが、画像の出どころを記録に残す）

 Q3. LUT を引く色の空間
     ★A：画面の色（sRGB の数。0〜1）で引き、表にも画面の色を入れる。引いた後にリニアへ戻し、ビネット・赤み・暗転は今の順番のまま
          ・夜の絵はほとんどが暗い。リニアの数で 32 段に分けると、画面の暗い半分（sRGB の 0〜0.5）が 32 段のうち 7 段ほどしかなく、
            暗い所の色の段が見えてしまう。画面の色で分ければ 16 段ある
          ・Photoshop などで画面の写真に掛けた色の調整を、そのまま表にも掛けられる（7 章の手順）
      B：リニアの数で引く（gradeColor と同じ数のまま扱えるが、暗い所が粗い）

 Q4. LUT の書き出し方（今の色の調整を表に焼く）
     ★A：GPU で焼く。gradeColor を Present.hlsl から Grading.hlsli へ移し、Present.hlsl と新しい LutBake.hlsl の両方が同じ関数を使う。
          焼いた 1024×32 の描画先（RGBA8）を TGA に書き出す機能を GameLib の RenderTarget に足す（Texture の writeTga と同じ作り。
          画面の読み戻しは Manager の capture と同じ）
          ・式が 1 か所だけなので、今後 gradeColor を直しても書き出しがずれない
      B：gradeColor を CPU（C++）に書き写して焼く（GameLib を変えないが、同じ式が 2 か所になる）

 Q5. LUT のファイルの場所と読み直し
     ★A：書き出しは Resource/lut_export.tga（F6 のボタン。毎回上書き）。読むのは Resource/lut.tga（外で直した物をこの名前で置く）。
          起動時に lut.tga があれば読む。F6 に「読み直す」ボタン（起動したまま外で直して、すぐ見比べる）。
          lut.tga が無いときは LUT を引かない（今と同じ絵。混ぜる強さの欄は灰色）。
          LUT は数のまま読む（TEXTURE_COLOR_SPACE_LINEAR。BC7 に縮めない：縮めると色の表に誤差が入るため。TGA のまま）
      B：F6 にファイルの名前を打つ欄を作り、いくつもの LUT を切り替える（見比べやすいが、今は 1 つあれば足りる）

 2. 今のコードで関係するところ
================================================================================
  ・空：LightList.hlsli の skyColor（skyGradient × 描く空の明るさ）。DeferredLighting.hlsl が深度が一番奥の画素で呼ぶ（104 行目あたり）
  ・霧：Fog.hlsl は深度が一番奥の画素（空）には掛けない。地平線の空の色が霧の色と同じなので、つながって見えている
  ・環境光：environmentLight（Pbr.hlsli の鏡面・SsrComposite.hlsl の SSR が当たらなかった所）。sharp（その向きの空）と blurred（ならした色）を粗さで混ぜる
  ・月の光の向き：LightingParams の moonElevation 35°・moonAzimuth 40°（lightDirectionFrom で向きにする）。月の CSM も同じ向き
  ・ライトの定数：LightList.cpp の LightConstants ＝ LightList.hlsli の cbuffer LightConstants（b2）。月の絵の定数はここに足す
  ・テクスチャの番号：ライティングのパスは t2〜t5（G-Buffer・深度）・t6〜t9（影）・t10（SSAO）・t13（SSR）を使う。上限は t15
    → 月の模様は t14
  ・色：Present.hlsl の PSMain は トーンマップ → gradeColor → ビネット → 赤み → 暗転 → 画面の色へ（linearToSrgb）→ ディザ。
    t2 シーンの色・t3 ブルーム（PostProcess.cpp の kSceneColorSlot・kBloomSlot）→ LUT は t4
  ・GameLib：Texture::create( ファイル ) は TGA と DDS を読める。RenderTarget には書き出しが無い（Q4）。
    Manager の capture は画面（バックバッファ）だけを読み戻して TGA に書く

 4. 月（9-a）
================================================================================
  ・向き：月の光の進む向きの逆（光は月から町へ進むので、月は −向き にある）。定数 gMoon の xyz（月の方の向き）
  ・大きさ：見かけの半径の角度 moonRadius（初期値 0.75°。直径 1.5°。本物の 0.5° は画面で小さすぎる）
  ・円板：向き dir と月の向きの角度が半径より小さい所。月の中の位置（月の向きに垂直な 2 本の軸で測った −1〜1）で模様を引く
    （moon.dds。α が月の形。縁は 1 画素ぶんなめらかに切る）
  ・明るさ：moonColor（今の月の光の色）× moonDiscIntensity（初期値 3。トーンマップの前の HDR の数。ブルームのしきい値 1 を少し超える）
  ・にじみ（halo）：月の周りに、離れるほど薄くなる明るさを足す（moonHaloIntensity 初期値 0.05・moonHaloFalloff 初期値 8。
    exp( −角度 / 半径 / falloff ）の形）。夜の薄い霧で光が散ったように見せる
  ・描く所：skyColor に足す（空の画素だけ）。Q1 の A なら environmentLight の sharp にも円板を足す（模様なし・同じ明るさ）
  ・月が地平線より下（moonElevation < 0）のときは描かない（今は 0〜90° の範囲なので起きないが、式は守っておく）

 5. 星（9-a。13 章で削除。コードには無い。作った時の記録として残す）
================================================================================
  ・向き dir を立方体の 6 面へ写し、面ごとに細かい升目（1 辺 starGridSize 個。初期値 256）に分ける。升目ごとのハッシュで
      ある・ない（starDensity 初期値 0.06 の割合でだけある）／升目の中の位置／明るさ（暗い星が多く明るい星は少ない：乱数の 8 乗）／色の温度（青白〜黄）
    を決め、隣の 3×3 の升目の星だけを見る（升目の境で星が切れないように）
  ・星の大きさ：画面の 1.2 画素ぶんの角度（縦の画角 ÷ 画面の高さ × 1.2）より小さくしない。
    1 画素より小さいと、TAA が毎フレームずらすたびに当たったり外れたりしてちらつくため
  ・消える所：
      高さ（dir.y）が starHorizonFade（初期値 0.15。約 9°）より下へ向かって消える（地平線は明るく、霧の色につながる所）
      月の周り（月の半径の 6 倍まで）で消える（月の明るさに負ける）
  ・明るさ：starIntensity（初期値 0.4。HDR の数。ブルームのしきい値より下：にじませない）
  ・Q1 の A でも、星は水たまりに映さない（小さく、粗さでならされて消えるため）

 6. LUT（9-b）
================================================================================
 6-1. 形（全体の計画 Q4）
  ・1024×32 の帯。横に 32 枚並べ、1 枚が 32×32。横の位置が赤、縦が緑、何枚目かが青（Unity・UE と同じ並び）
  ・表の中身は画面の色（sRGB の数。Q3）。何もしない表（恒等）は「位置の色がそのまま」
 6-2. 引き方（Present.hlsl）
  ・gradeColor の後の色を画面の色（linearToSrgb）にし、表を引いて、リニアへ戻す
  ・青の向きは 2 枚を読んで混ぜる（3D テクスチャの補間の代わり）。赤・緑は 1 枚の中で線形補間（端の半画素を避けて読む）
  ・混ぜる強さ lutStrength（0〜1。初期値 1）で gradeColor の後の色と混ぜる
  ・lut.tga が無いときは引かない（Q5）。今と同じ絵
 6-3. 焼き方（Q4 の A）
  ・Grading.hlsli：今の gradeColor をそのまま移す（中の定数・PresentConstants の値も同じ物を読む）
  ・LutBake.hlsl：1024×32 の描画先へ全画面で描く。画素の位置から「恒等の色（画面の色）」を作り、リニアに直して gradeColor に通し、
    画面の色に戻して書く
  ・GameLib：RenderTarget に writeTga( ファイル名 ) を足す（RGBA8 のときだけ。読み戻しは Texture の writeTga と同じ staging）
  ・F6 のボタンを押したフレームだけ焼いて書き出す（毎フレームは焼かない）
 6-4. 焼いた表の確かめ
  ・書き出した lut_export.tga を lut.tga にして読み、カラーグレーディングを切る（F6 → Render の Grading）と、
    LUT だけで同じ絵になる（違いは 32 段に焼いた補間の誤差だけ）
  ・カラーグレーディングを入れたまま LUT も引くと、調整が二重に掛かる → LUT を読んだ間は gradeColor を飛ばす（全体の計画 Q5 の A
    「LUT を読み込んだ後は、gradeColor の代わりに LUT を引く」）。混ぜる強さ 0 のときは gradeColor の結果と同じ

 7. LUT を外の道具で直す手順（Photoshop・GIMP・Krita など）
================================================================================
  1) F6 → Render → Grading で「Export LUT」を押す → Resource/UI/lut_export.tga（今の色の調整を焼いた表）
  2) 同じ画面の写真を撮る（今ある capture。F6 の表示を閉じてから）
  3) 写真を外の道具で開き、色の調整を「調整レイヤー」で足す（トーンカーブ・色相・彩度など。ぼかし・ゆがみは使えない）
  4) 同じ調整レイヤーを lut_export.tga にも掛けて、Resource/UI/lut.tga の名前で保存（TGA・24bit か 32bit・圧縮なし。大きさは 1024×32 のまま）
  5) F6 の「Reload LUT」を押して見比べる。強さを動かす
  ・写真と表は同じ「画面の色」なので、写真で見た色の変わり方が、そのままゲームに出る（Q3）

================================================================================

      記録 1：Sky detail OFF・LUT なし（今と同じ）
      記録 2：Sky detail ON・LUT なし
      記録 3：Sky detail ON・LUT あり（強さ 1）
  ・見る数：gpu.Lighting（空と環境光の計算が増える）・gpu.Present（LUT を引く）。どちらも 0.02ms 以下の見込み（全体の計画 9 章）

      準備：Profile・F6 → Render の VSync を切る（切ってから Record CSV）・夜（Night）・懐中電灯 ON・ほかは全部 ON のまま（AA は TAA）

            表示が「LUT: lut.tga 1024x32」になり、Color grading を切っても絵が変わらないことを見る（6-4 の確かめ）。
            見終わったら Color grading を ON に戻す
      記録 1（道）：月が見えて、水たまりも映る所で立ち止まり、向きを変えずに Record CSV を押して
        A：Sky detail OFF・LUT strength 0 で約 30 秒 → B：Sky detail ON で約 30 秒 → C：LUT strength 1 にして約 30 秒 → Stop CSV で止める
      記録 2（空）：真上に近い所を向いて同じ A → B（LUT は空と関係ないので B まで）
      分け方：GPU の印では A・B・C を見分けられないので、切り替えた時刻（だいたいの秒）を教えてもらい、前後 2 秒と最初・最後の 1 秒は使わない
      見る数：gpu.Lighting（A→B の差が月・映る月の重さ）・gpu.PostProcess（B→C の差が LUT の重さ）・GPU 全体・CPU の中央値
      録ったら CSV のフォルダ（Profiling/<日時>/）と切り替えた秒を教えてもらい、こちらで集計する

 12. 実装で仕様から変えた所（9-a・9-b。2026-10-31）
================================================================================
 9-a 月・星
  ・月と星の式は Resource/Shader/SkyDetail.hlsli に分けた（LightList.hlsli が include。skyColor と environmentLight から呼ぶ）。
    定数はライトの一覧（b2）に gMoonDirection・gMoonColor・gMoonHalo・gStars の 4 つを足した（LightList.cpp の LightConstants と同じ並び）
  ・水たまりに映す月（Q1）は、粗さ 0.5 で消える（kMoonReflectionMaxRoughness）。今の environmentLight は「その向きの空」と「ならした色」を
    粗さで混ぜるだけなので、そのまま足すと粗い地面にも小さな円板が薄く映るため。縁は半径の 15% でなめらかに切る（映り込みの画素の大きさは分からない）
  ・月の模様の段（ミップ）は、画面の 1 画素に模様の何画素が入るかで自分で選ぶ（全画面のパスの分かれ道の中なので、自動の段の選び方に頼らない）。
    見かけの直径 1.5°・縦の画角 60° なら、月は画面で 27 画素ほど
  ・1 画素の角度は GameScene が「縦の画角 ÷ 画面の高さ」で渡す（EnvironmentLight::pixelAngle）。星の大きさと月の段の選び方の両方に使う

 9-b LUT
  ・Present.hlsl の定数を PresentConstants.hlsli、gradeColor と表を引く関数を Grading.hlsli に分けた（Present.hlsl と LutBake.hlsl が include）。
