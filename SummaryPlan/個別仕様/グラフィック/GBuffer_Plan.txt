 3. 段階2 でやること・やらないこと
================================================================================
 やること
  ・GameLib に「RGBA8 を sRGB で書く描画先」を足す
  ・G-Buffer 3 枚を作り、不透明な物を全部そこへ描く（静的メッシュ・キャラ）
  ・全画面 1 回のライティングのパスで、今と同じ式の色を HDR の色（RGBA16F）へ出す
  ・半透明の板・デバッグの線は、ライティングの後に今のまま描く
  ・前の描き方と F6 で切り替え、G-Buffer の中身を画面で見られるようにする

 やらないこと（段階3 以降。Graphics_Spec 15 章）
  ・PBR の式・粗さ・金属、ライトの種類（月・街灯・懐中電灯）、16 灯、空、環境光の見直し
  ・影、SSAO、SSR、霧、デカール、TAA の速度（RT3）
  ・弾痕をデカールに置き換えること（9 章。ディファードの後に決める）

 4. G-Buffer の中身（段階2 の使い方）
================================================================================
  枚      形式              段階2 の中身                              段階3 の中身（Graphics_Spec 4-1）
  ------  ----------------  ----------------------------------------  -------------------------------
  RT0     RGBA8（sRGB）     rgb：色（頂点色×材質の色×画像）           同じ
                            a ：予備（0）
  RT1     RGBA16F           xyz：法線（ワールド・法線マップ済み）      xyz：同じ  a：予備
                            a ：スペキュラの鋭さ（8〜48 をそのまま）
  RT2     RGBA8（sRGB）     rgb：スペキュラの色（Q2）                  r：AO g：粗さ b：金属 a：発光
                            a ：予備（0）                              （UNORM へ戻す）
  深度    D32F              PostProcess の深度をそのまま使う          同じ

 ・RT2 を sRGB にする理由：スペキュラの値は 0.02 のような小さい数が多く、リニアに直すと
   0.0015。8bit にリニアのまま入れると 0 になる（0.0015 × 255 ＝ 0.4）。sRGB の描画先なら
   GPU が暗い所を細かく持ってくれるので、RT0 と同じ形式を使い回せる
 ・スペキュラの (2+鋭さ)/2π は G-Buffer に入れる前に割り戻し、ライティングのパスで掛ける
   （RT2 には 1 を超えない「材質の色」だけが入る）
 ・発光は今どの材質も 0 なので段階2 では入れない（段階3 で RT2 a へ）。0 でない材質が
   G-Buffer の経路へ来たら ASSERT で知らせる
 ・画像のアルファは今も色の計算に使っていない（不透明・BLEND_OPAQUE）。段階2 も使わない
 ・メモリ（2560×1369）：RT0・RT2 各 14MB、RT1 28MB、計 約56MB 増える

 5. 1 フレームの流れ（切り替え後）
================================================================================
  GameScene::draw
   (1) PostProcess::beginScene            色と深度を消す（今と同じ）
   (2) setupLights                        ライトを Manager へ（今と同じ）
   (3) GBuffer::begin                     描画先を RT0〜RT2 ＋ 深度にし、消す。RenderPass ＝ GBuffer
   (4) GameWorld::draw                    今と同じ順番（自キャラ→ゾンビ→建物→置物→地面）
   (5) GBuffer::end                       RenderPass ＝ Forward。描画先を外す
   (6) DeferredLighting::draw             描画先を「シーンの色」だけにし、全画面 1 回で色を出す
                                          （G-Buffer 3 枚と深度を t2〜t5 で読む）
   (7) PostProcess::resumeScene（新規）   描画先を「シーンの色＋深度」へ戻す
   (8) 弾痕・砂ぼこり・血しぶき・マズルフラッシュ・デバッグの線（今と同じ）
   (9) PostProcess::endScene              ブルーム→露出→ACES→ビネット→sRGB（今と同じ）

 ・(6) の間は深度を描画先から外す（同じ深度を描画先とシェーダの両方に付けられないため）
 ・何も描かれていない画素（深度が 1）は、今の消す色（PostProcess の clear の色）をそのまま出す
   （空は段階3）

================================================================================
 6. 物を G-Buffer へ描く
================================================================================
--------------------------------------------------------------------------------
 6-1. どの物がどちらの経路か
--------------------------------------------------------------------------------
  G-Buffer   建物・地面（道路）・車・ガソリン・落ちた弾・弾頭（MeshMaterial を通る物すべて）
             自キャラ・ゾンビ・千切れた部位（SkinningPipeline を通る物すべて）
  フォワード 弾痕・砂ぼこり・血しぶき・マズルフラッシュの板（LitQuadBatch）
             デバッグの線・ゾンビの道の線（PrimitiveRenderer）

--------------------------------------------------------------------------------
 6-2. 描き方を知らせる部品（RenderPass。Q3）
--------------------------------------------------------------------------------
  ・RenderPass::current() が Forward か GBuffer を返す。変えるのは GBuffer::begin / end だけ
  ・読むのは MeshMaterial::apply（固定パイプラインか StaticMeshGBuffer.hlsl か）と
    SkinningPipeline::begin（SkinnedMesh.hlsl か SkinnedMeshGBuffer.hlsl か）の 2 か所だけ
  ・影響範囲：この 2 か所の外は、G-Buffer に描いているかを知らない（draw は変わらない）
  ・修正の入口：経路を足すとき（段階4 の影）は RenderPass の enum と、この 2 か所

--------------------------------------------------------------------------------
 6-3. G-Buffer へ描くシェーダ
--------------------------------------------------------------------------------
  ・StaticMeshGBuffer.hlsl：標準の頂点。固定パイプラインと同じ b0 の行列・材質の値を読む
    （MeshMaterial::apply は今どおり setDiffuseColor などを呼ぶので、値の渡し方は変えない）
  ・SkinnedMeshGBuffer.hlsl：骨の変形は SkinnedMesh.hlsl と共通（Skinning.hlsli へ出す）
  ・法線マップは Lighting.hlsli の perturbNormal をそのまま使う（画面微分。今と同じ）
  ・裏を描いたとき（doublesided="1" の材質）は法線を反転する（SV_IsFrontFace）。
    今は両面の材質が無いので、入れるだけで絵は変わらない

 7. ライティングのパス
================================================================================
  ・DeferredLighting.hlsl。drawFullScreen で 1 回描く
  ・1 画素ごとに：深度と「射影×ビューの逆行列」（b1）から位置を戻す → G-Buffer を読む →
    shadePixel と同じ式（4 灯のディフューズとスペキュラ＋環境光）
  ・同じ式を 2 回書かないよう、Lighting.hlsli を「面の情報を受け取って色を返す関数」と
    「画像を読んで面の情報を作る部分」に分ける。フォワード（SkinnedMesh.hlsl）と
    ディファードが同じ関数を呼ぶ
  ・GameLib の固定パイプライン（PixelLightingNormalMapPsHlsl.h）は今と同じ式で残る。
    フォワードの間はこれと Lighting.hlsli の 2 つが同じであることが前提（今も同じ）
  ・ライトの値は b0 をそのまま読む（drawFullScreen が送る）。4 灯のまま

 11. 確かめ方
================================================================================
  ・同じ絵：同じ場所・同じ向きでフォワードとディファードを切り替え、見比べる。
    違いが出てよいのは 8bit にした色の丸め（1/255 程度）だけ
  ・見る場所：明るい所と暗い所の建物の壁（法線マップ）、道路、ゾンビの肌、
    自キャラの腕と銃（真鍮の弾頭のスペキュラ）、千切れた部位の断面、遠くの建物
  ・位置の戻し：8-2 の格子が、カメラを動かしても壁に貼り付いたままか
  ・隠れ方：弾痕・血しぶき・砂ぼこりが壁の裏から透けて見えないか、壁の手前で切れないか
  ・計測：VSync を切り、同じ場面で F7 の CSV。gpu.Player〜Ground（G-Buffer へ描く時間）と
    gpu.Lighting を、フォワードのときの gpu.Player〜Ground と比べる
    （VSync を入れたままだと Present の待ちが混ざる。2026-10-27 の誤り）

 12. 懸念点
================================================================================
  ・GPU の時間は少し増える見込み：今の町はライトが 4 灯で、フォワードでも重くない
    （GPU 平均 0.31ms）。ディファードの得はライトが増える段階3 で出る。段階2 の数字は
    「土台のコスト」として書く（得をしたとは書かない）
  ・8bit の色：RT0 の色を 8bit に丸めるので、ゾンビの暗い肌に段差が出ないか。
    sRGB で入れるので出ない見込み。出たら RT0 を RGBA16F にする（メモリ +14MB）
  ・法線マップの画面微分：G-Buffer に描くときも同じ方法なので、絵は変わらない。
    ただし千切れた部位の断面のような UV の面積 0 の所は今も元の法線へ戻している。
    同じ処理を通るので差は出ない見込み
  ・GameLib の固定パイプラインとの二重：フォワードを消すまで、式の変更（段階3）は
    Lighting.hlsli だけにし、固定パイプライン側は触らない
  ・ゾンビの頭上のバー（F3）・ImGui は PostProcess の外なので影響しない

 14. 実装で仕様から変えた所（2-a。2026-10-28）
================================================================================
  ・静的メッシュのシェーダを選ぶ場所は MeshMaterial::apply ではなく StaticMeshPart::draw にした。
    キャラも MeshMaterial::apply を通るので、apply で選ぶとキャラのシェーダ（SkinningPipeline::begin で付けた物）を
    上書きしてしまうため。読む 2 か所は StaticMeshPart::draw と SkinningPipeline::begin
  ・法線マップの無い静的メッシュは、G-Buffer へ描くときだけ強さを 0 にする（SkinnedMeshData::draw と同じ処理）。
    シェーダは t1 を必ず読み、空だと 0 が返って法線がずれるため。固定パイプラインは法線マップ無し用の PS に
    切り替わるので、今の描き方の絵は変わらない
  ・G-Buffer の表示の欄は F6 の Tuning ではなく Render（VSync の下の「G-Buffer」）に置いた。
    Tuning は小数の調整値だけを扱い（Copy as C++ でコードへ戻す物）、表示の選択はそこに入らないため
  ・2-a では、いつもの絵（Final）は今の描き方のまま。Final 以外を選んだときだけ G-Buffer へ描き、
    PostProcess の後に画面へ直接写す（ToneMap を通さない）。ライティングのパス（2-b）で Final もディファードにする
  ・深度から位置を戻すため、GameLib の Matrix44 に setInverse（逆行列）を足した。式は乱数の行列で
    A × A⁻¹ が単位行列になることを確かめた（誤差 1e-15 程度。scratch の perl）
  ・発光が 0 でない材質を ASSERT で知らせる案（4 章）は入れていない。MeshMaterial は発光を持たず、apply が
    いつも 0 を設定するので、G-Buffer の経路へ発光が来ることが無いため
  ・G-Buffer 3 枚は Release でも作る（約 56MB）。2-b でいつもの絵がディファードになるので、作り分けはしない
  ・2-a で足した物
     GameLib  ：RENDER_TARGET_RGBA8_SRGB（Enum.h・RenderTargetImpl.h）、Matrix44::setInverse
     GameSrc  ：Render/RenderPass・GBuffer・DeferredLighting（今は drawView だけ）、PostProcess::resumeScene / sceneDepth、
                SkinningPipeline の G-Buffer 用シェーダ、GameScene::draw の流れ、EditorWindow の Render 欄、
                シェーダのエラーの 1 行に GBuffer と DeferredLighting を足した
     シェーダ ：Skinning.hlsli（SkinnedMesh.hlsl から骨の変形を出した）・GBuffer.hlsli・StaticMeshGBuffer.hlsl・
                SkinnedMeshGBuffer.hlsl・DeferredLighting.hlsl
  ・画面で確かめること（2-a）
     F6 → Render → G-Buffer で Albedo / Normal / Specular / Sharpness / Depth / Position を順に選ぶ
       Albedo   ：今の絵から陰影を抜いた色。建物・道路・ゾンビ・腕と銃が全部出ているか（抜けた物は G-Buffer へ描けていない）
       Normal   ：上を向く地面が緑っぽく、壁が向きごとに赤・青っぽい。法線マップの凹凸が見えるか
       Specular ：殆ど黒。弾頭と落ちた弾だけ黄土色
       Sharpness：材質ごとに灰色の濃さが違う
       Position ：1m の格子が、カメラを動かしても壁・地面に貼り付いたままか（位置の戻しが正しいか）
     Final に戻すと、いつもの絵と変わらないこと（今の描き方には触っていない）

 15. 実装で仕様から変えた所（2-b。2026-10-28）
================================================================================
  ・Lighting.hlsli を lightSurface（面の情報 → 照らした色。発光は含まない）と shadePixel（画像と法線マップを読んで
    lightSurface を呼び、発光を足す）に分けた。計算の中身と順番は前と同じ（albedo × (環境光＋ディフューズ) ＋ スペキュラ）
    なので、フォワードの絵（キャラ）は変わらない。固定パイプライン（建物など）は GameLib の中なので触っていない
  ・ライティングのパスは DeferredLighting.hlsl の表示 Final（0）。G-Buffer の色・法線・スペキュラ・鋭さと、深度から戻した
    位置を lightSurface に渡す。スペキュラは G-Buffer に入れるとき割った (2+鋭さ)/2π を掛け戻す（GBuffer.hlsli の
    normalizedSpecularColor）。発光は足さない（今どの材質も 0。段階3 で RT2 a から読む）
  ・何も描かれていない画素（深度 1）は discard して、PostProcess が消した色をそのまま残す（消す色を 2 か所に書かない）
  ・描画先：G-Buffer の後に PostProcess::bindSceneColor（色だけ。深度はシェーダから読むので外す）→ ライティング →
    resumeScene（色＋深度）→ 弾痕・砂ぼこり・血しぶき・マズルフラッシュ・デバッグの線。2-c の並べ直しはこれで済んでいる
    （残りは画面で隠れ方を見ることだけ）
  ・F6 → Render に「Deferred」のチェックを足した（初期値 ON。Release は Deferred のまま）。G-Buffer の表示が Final 以外の
    ときは、チェックに関わらず G-Buffer へ描いて中身を見せる
  ・GPU の印「Lighting」を足した（ディファードのときだけ出る）。ディファードの間の gpu.Player〜Ground は
    「G-Buffer へ描く時間」、フォワードの間は「描いて色を出す時間」になる
  ・前と違って見えてよい所：色とスペキュラを 8bit（sRGB）に丸める分。スペキュラ 0.02 は 5/255 に丸まり、
    リニアで約 2% 弱くなる（0.00155 → 0.00152）。見て分かる差ではない見込み
  ・2-b で足した・変えた物
     シェーダ ：Lighting.hlsli（lightSurface に分けた）・GBuffer.hlsli（normalizedSpecularColor）・DeferredLighting.hlsl（Final）
     GameSrc  ：DeferredLighting::drawLighting と RenderPath / renderPath()、PostProcess::bindSceneColor、
                GameScene::draw の流れ、EditorWindow の Deferred のチェック
  ・画面で確かめること（2-b）
     F6 → Render の Deferred を入れたり切ったりして、同じ場所・同じ向きで見比べる
       明るい所と暗い所の建物の壁（法線マップ）、道路、ゾンビの肌、自キャラの腕と銃、弾頭と落ちた弾のツヤ、
       千切れた部位の断面、遠くの建物、撃ったときのマズルフラッシュの照り返し（点光源も同じ 4 灯に入っている）
     弾痕・血しぶき・砂ぼこりが壁の裏から透けないか、壁の手前で切れないか（2-c）
     計測（2-d）：VSync を切り、同じ場面で Deferred の ON と OFF の F7 の CSV を取る
       結果（2026-10-28。Profile・VSync なし。ON と OFF は別々の起動で録ったので場面は揃っていない）
         Profiling/20261028_133519/perf_20261028_133651.csv（Deferred・89,143 フレーム）
         Profiling/20261028_192956/perf_20261028_193007.csv（Forward・144,791 フレーム）
         GPU 全体の中央値  Forward 0.340ms → Deferred 0.345ms
         増えた所（平均）  建物 0.040 → 0.065・地面 0.022 → 0.034・Lighting 0.056（合わせて約 +0.09ms）
         ゾンビの中央値は 0.164 → 0.073 と下がったが、映っていたゾンビの数の違いと見ている（数は CSV に無い）
         GPU 全体の平均（0.357 → 0.461）・99%（0.80 → 1.42）は、このゾンビの場面の違いを含むので比べない
         Debug ビルドの記録（20261028_192642）はシェーダが最適化なしなので使わない
  ・不具合（2026-10-28 ユーザーの画面確認で発覚・同日修正）：Deferred で画面が真っ暗（UI は見える）
     原因：G-Buffer へ描くときのブレンドが、前に描いた物（半透明の板・UI）の「アルファで混ぜる」のまま残っていた。
           G-Buffer のアルファは透明度ではなくデータで、RT0 は予備の 0 なので何も書かれず色が 0、
           RT1 は鋭さ（8〜48）なので法線が何倍にも膨らんでいた。2-a の表示で気付かなかったのは、表示の確認のときは
           ブレンドがたまたま不透明だったため（表示の後に描く物の設定が次のフレームに残る）
     調べ方：一時的にライティングの結果を「NaN なら紫・0 なら緑」、次に「色 / ライトの値 / 法線」を画面の 3 分割で出し、
             ゲーム本編から起動して撮った（起動シーンとシェーダは元に戻した）
     修正：GBuffer::begin で BLEND_OPAQUE を設定する。修正後、町・車・ゾンビ・銃がディファードで描かれることを撮って確かめた
     教訓：描画先を自分で切り替える所は、深度・カリングと同じくブレンドも自分で設定する（前の物の設定に頼らない）
