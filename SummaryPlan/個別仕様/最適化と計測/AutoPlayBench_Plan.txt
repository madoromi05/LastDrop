 聞きたいこと（★）

 ★Q1. 自キャラの動かし方
     案 A（おすすめ）：シナリオ（行動の並び）を上から順に実行する。行動の中身は自分で動く
       例：「ガソリンまで歩く」は道を自分で探して歩く、「ゾンビの左脚を撃つ」は自分で狙う。並びは毎回同じ
       → 毎回同じ流れになるので、最適化の前後を比べられる。「何を測ったか」をシナリオの名前で言える
     案 B：自分で考えるボット（ガソリンを探す → 車へ運ぶ → 寄ってきたゾンビを撃つ、を勝手に繰り返す）
       → 毎回流れが変わるので、前後の比較にも「全部の出来事を起こす」にも向かない
     案 C：人の操作を録って再生する → 場面が少しずれると狙いが合わずに崩れる

 ★Q2. 始め方
     案 A（おすすめ）：両方作る
       ・起動の引数：LastDrop.exe -autoplay all_events
         シナリオを走らせ、終わったらゲームを閉じる（タイトル画面から始めるので、メニューの出来事も起こせる）。
         tools/autoplay.bat をダブルクリックすれば Profile ビルドで走る
       ・F6 のエディタの AutoPlay 欄：シナリオを選んで Start / Stop。終わってもゲームは閉じない（見ながら直す用）
     案 B：F6 の欄だけ

 ★Q3. 計測の中身
     案 A（おすすめ）：走り始めに VSync を自動で切って CSV の記録を始め、終わったら止めて VSync を戻す。
       行動ごと・出来事ごとの表を autoplay_<シナリオ名>_<時刻>.md に書く（8 章）
     案 B：記録の始め・止めだけ（表は作らない）

 ★Q4. 走っている間の決まり
     案 A（おすすめ）：始めは「無敵・乱数の種を固定・勝手な湧きを止める」。どれもシナリオの行動で途中から切り替えられる
       （噛まれて体力が減る・死ぬ・勝手に湧く、の出来事を起こすときだけ切る）
     案 B：始めから全部ふつうに遊ぶときと同じ

 ★Q5. 入力の差し込み方（改 1 で追加）
     案 A（おすすめ）：仮想のパッド。AutoPlay が「W を押している」「マウスを右へ 3 画素」「E を押した瞬間」を作り、
       Pad が読んだ本物の入力の代わりに使う。ゲームの中は人が遊ぶときと全く同じ道を通る
       → タイトル・一時停止・設定・結果の画面も同じ仕組みで押せる
          （PlayerCommand に直接入れる案だと、メニューと「使う」に、それぞれ別の差し込み口が要る）
     案 B：PlayerCommand と視点の回す量を直接渡す（初めの案。自キャラの操作だけなら少し簡単）

 ★Q6. 起きなかった出来事の扱い（改 1 で追加）
     案 A（おすすめ）：表の一番上に「起きなかった出来事」を並べる。起動の引数で走らせたときは、ゲームの終わりのコードを 1 にする
       （autoplay.bat が「NG：起きなかった出来事 3 個」と出す。直した後の確認に使える）
     案 B：表に回数を並べるだけ

================================================================================
 1. 目的
================================================================================
 ・人が同じ動きをしなくても、毎回同じ場面・同じ流れで負荷をかけ、数字を取れるようにする
 ・ゲームの出来事を全部起こし、出来事ごとの重さ（撃った瞬間・部位が千切れた瞬間・給油した瞬間・シーンを切り替えた瞬間 …）を分けて見る
 ・最適化の前と後で同じシナリオを走らせれば、その差がそのまま「最適化の効果」になる（ポートフォリオの「計測した数字」）
 ・ついでに「全部の出来事がまだ起きるか」の確かめにもなる（どこかを直して、別の出来事が起きなくなったら気付ける）
 ・長く走らせて、落ちない・だんだん重くならないことの確認にも使う

================================================================================
 2. タルコフでは／ほかのゲームでは
================================================================================
 開発用の道具で、遊ぶ人には見えない物なので、タルコフは調べない（DebugTools_Profiling_Plan.txt の 5-5・5-6 と同じ）。
 代わりに、ほかのゲーム・エンジンが自動のプレイと計測をどうしているかを調べた（14 章）。

 ・Unreal Engine：Gauntlet という「ゲームを起動して、テストを走らせ、結果を集める」仕組みがある。
   その上の AutomatedPerfTest は、決まった動き（シーケンス）や録った試合（リプレイ）を自動で再生して性能を集める
   （AutomatedPerfTest については掲示板の書き込みで知った話で、公式の文書では確かめられなかった）
 ・ベヨネッタ 2（CEDEC 2016）：オートプレイでゲームを進めながら、CPU・GPU・メモリを毎日測り続け、ブラウザで推移を見た
 ・ソニー（CEDEC 2024）・カプコン（CEDEC 2026）：人と同じ条件で遊ぶ AI でテストを自動にしている（バグ探しが主な目的）

 合わせる所：起動の引数で「起動 → 決まった動き → 記録 → 終了」を人の手なしで回す（Gauntlet・ベヨネッタ 2 と同じ）
             人と同じ入力の道を通す（ソニー・カプコンの「人と同じ条件」。Q5 の案 A）
 あえて変える所：AI やリプレイではなく、行動の並び（シナリオ）にする。目的が「前後の比較」と「全部の出来事を起こす」なので、
                 毎回同じ流れになることを一番にする

 3. 今ある物（2026-10-28 に調べた）
================================================================================
 ・Pad（GameSrc/Core/Pad.h）：1 回の描画につき 1 回 update し、操作の番号（WorkId）ごとに「押されている・押した瞬間・離した瞬間・軸の量」を返す。
   ゲームの入力は全部ここを通る（InputFire() などのショートカット）。仮想のパッドはここに差し込める（Q5 の案 A）
 ・PlayerCommand：自キャラへの 1 フレームぶんの操作。コメントに「AI・リプレイなど、操作の出どころが変わっても…」とある（Q5 の案 B の口）
 ・GameWorld：出来事の一覧を毎ティック出している（zombieHitsThisTick・surfaceHitsThisTick・zombieAttacksThisTick）。spawnZombie もある
 ・道探し：書いた時は StreetGraph::findPath（A*）。今は NavMesh（Map/NavMesh）。自キャラの「そこまで歩く」にも使える
 ・Profiling：toggleRecording（今は F6 の Perf 欄の Record CSV から呼ぶ）・markEvent（印）。印は今「Shot」と「押したボタンの名前」しか付いていない。1 フレームに残せる印は 16 個まで
 ・Graphics::Manager::setVSync・WindowCreator::commandLineString（起動の引数。今はどこも使っていない）
 ・乱数の種：ゾンビ用（GameWorld.cpp 139 行）とガソリンの置き場所（225 行）が、起動からの時間（Framework::time）で決まっている
 ・窓が裏に回ると一時停止する（GameScene::beginFrame）。放っておいて走らせる間は、これを止める必要がある
 ・ワールドの状態の保存（DebugTools_Profiling_Plan 5-6。WorldSnapshot）は、計画はあるがコードにもコミットの履歴にも無い

 4. 使い方
================================================================================
 （Q2 が案 A の場合）

  全部自動（放っておく）：
    tools\autoplay.bat all_events
      → Profile ビルドのゲームが起動 → シナリオ AutoPlay/all_events.xml を走らせる → 閉じる
      → Profiling/<起動時刻>/ に perf_*.csv・_system.json・autoplay_all_events_*.md ができる
      → 起きなかった出来事があれば、窓に「NG」と名前が出る（Q6 の案 A）
    回数を指定：tools\autoplay.bat town_combat 3   （同じシナリオを 3 回。ぶれの大きさが分かる）

  見ながら（F6）：
    F6 → AutoPlay 欄 → シナリオを選ぶ → Start
      ・今の行動の名前（何行目か）・経った時間と、出来事の一覧（起きた物は灰色、まだの物は白）を出す
      ・Stop で止める（それまでの分を書き出す）。ESC も Stop と同じ（走っている間の ESC は一時停止ではなく止める）

  シナリオのファイル：AutoPlay/<名前>.xml（PseudoXml。git に入れる。前後の比較で同じファイルを使い続けるため）
    最初に用意する物：
      all_events.xml   5 章の出来事を全部起こす（7 章）。長い（5 分ほど）
      town_combat.xml  撃ち合いの重さだけを見る短い物（ゾンビ 10 体・20 体を撃つ。1 分ほど）
      town_walk.xml    ゾンビ無しで町を一回り歩く・見回す（描く重さだけを見る）

================================================================================
 6. 行動（シナリオに書ける物）
================================================================================
 1 行が 1 つの行動。上から順に実行し、終わったら次へ進む。
 どの行動にも次の 2 つを付けられる。
   timeout="秒"  その時間で終わらなければ「時間切れ」と表に出して次へ進む（止まり続けない）
   expect="名前"  この行動の間に、その出来事が起きなければ「起きなかった」と表に出す（, で区切って何個でも）

 ■ 流れ
  Wait            seconds                   その場で立ち止まる
  WaitFor         event, timeout            その出来事が起きるまで待つ（例：Zombie.Corpse になるまで）
  Repeat          count（中に行動を書く）   中の行動をくり返す
  Label / Note    text                      表に見出しを入れるだけ（何もしない）

 ■ 画面・メニュー（仮想のパッドの UiUp・UiDown・UiDecide・UiLeft・UiRight・Menu を押す）
  MenuSelect      button                    今の画面のボタンを名前で選んで決定する（Start・Options・Controls・Back・Resume・Retry・Title・Quit）
  SetOption       item, value               設定の値を変える（Master・Effects・Sensitivity。スライダーを左右に押して合わせる）
  Pause           なし                      ESC を押す（走っている間の ESC は Stop にしているので、仮想のパッドからだけ押せる）
  WaitScene       scene                     その画面になるまで待つ（ロードを含む）

 ■ 移動・視点
  Walk            direction, seconds, run   向き（forward・back・left・right、組み合わせも可）へ決まった秒だけ歩く／走る
  MoveTo          target, run               行き先まで歩く／走る。道は NavMesh で探す
                                            target：座標・fuel（一番近いガソリン）・car・zombie・start
  LookAround      degreesPerSecond, turns   その場で決まった速さで回る（映る物を変えて描く重さを見る）
  LookAt          target, pitch             その方を向く（target は MoveTo と同じ。空を見るときは pitch）

 ■ 銃
  Aim            mode                      hold（押したまま）・toggle（短押し）・off（やめる）
  Fire            count, interval           今向いている方へ count 発撃つ。interval="0" で続けて（連射）
  Reload          なし                      弾を込める（込め終わるまで待つ）
  EmptyMagazine   なし                      空へ撃って弾倉を空にする（空からの Reload・空撃ちの前に使う）
  ShootSky        count                     空へ撃つ（何にも当たらない弾・銃声で寄せる）
  ShootSurface    material, count           その材質の物を探して撃つ（concrete＝建物、dirt＝車道、metal＝車）
  SetAmmo         magazine, reserve         弾の数を決める（確認用。予備が 0 のときの出来事を起こすため）

 ■ ゾンビ
  SpawnZombies    count, distance, facing, at
                  facing：toward（こちらを向いて出る＝すぐ気付く）・away（背を向けて出る＝うろつく）
                  at：front（前）・behind（後ろ。見えない）・behindBuilding（建物の向こう。回り込ませる）・narrow（狭い所）
  Shoot           target, part, until, count
                  target：nearest（一番近い）・grabbing（つかんでいるゾンビ）・downed（這っているゾンビ）
                  part：head・torso・leftUpperArm … rightLowerLeg（部位の名前は BodyPart と同じ 10 個）
                  until：stagger・critical・severed・downed・dead・count（count 発撃ったら終わる）
  ShootCorpse     count                     一番近い死体を撃つ
  LetGrab         なし                      撃たずに止まって待ち、つかまれるまで待つ（攻撃は 1 体ずつなので、来るまで待つ）
  KillAll         なし                      立っているゾンビを全部倒す（場面を片付ける）
  SetAutoSpawn    state                     勝手に湧くのを on／off

 ■ 物・脱出
  Interact        なし                      今見ている物を使う（E）
  PickUp          item                      MoveTo → LookAt → Interact をまとめた物（fuel など。作るときに今の物で決める）
  Refuel          なし                      ガソリンを持っていなければ拾い、車へ行って入れる
  Escape          なし                      必要な数になるまで Refuel をくり返す（クリア画面へ進む）

 ■ 自キャラ
  SetInvincible   state                     無敵を on／off（F6 の切り替えと同じ）
  Die             なし                      無敵を切って LetGrab をくり返し、死ぬまで待つ（ゲームオーバー画面へ進む）

 ■ 確認用
  DebugKey        work                      キーを 1 回押す（WorkId の名前。今は F6 の Editor だけ）
  SetSwitch       name, state               F6 の確認用の切り替え（DebugSwitches）を on／off
  FlyFreeCamera   seconds                   観察用カメラで決まった道を飛ぶ（上・下・前へ）
  SetRender       view                      G-Buffer の見せ方を変える（F6 の Render 欄と同じ値）
  SetVSync        state                     VSync を on／off（走り始めは off。比べたいときだけ）

 自キャラへの操作の作り方（Q5 の案 A の場合）
  ・行動は仮想のパッドの「押している・押した瞬間・視点の軸の量」を作るだけ。ゲームの中には手を入れない
    （人が遊ぶときと同じ道を通るので、測る数字も人が遊ぶときと同じになる）
  ・狙うのは視点を回して行う（人がマウスで狙うのと同じ。照準のぶれ・反動もそのまま効く）。
    1 ティックに回す量には上限を付ける（一瞬で振り向くと、人の遊び方と描く物が変わってしまうため）
  ・部位を狙う位置は、ゾンビの当たり判定の箱（HitboxSet）の真ん中を読む（読むだけ。ゾンビには手を入れない）

 7. 全部の出来事を起こすシナリオ（all_events）
================================================================================
 5 章を全部起こす順番の案（AutoPlay/all_events.xml）。前の出来事の結果を次で使うように並べる。
 9・13 の拾う・脱出は書いた時（5 日間・車へ運ぶ形の前）の流れ。作るときは 1 回勝負の出撃の流れで組み直す。

   1 タイトル     MenuSelect Options → SetOption → MenuSelect Controls → Back → Back → MenuSelect Start → WaitScene game
   2 何もいない町 Walk 前後左右・走る・壁に当てる → LookAround → Interact（何も無い所）
   3 銃           Aim hold／toggle／off → Fire 1 → Fire 10（連射）→ Reload → EmptyMagazine → Fire（空撃ち）→ Reload
                  → SetAmmo reserve 0 → Reload（込められない）→ SetAmmo 戻す
   4 物に撃つ     ShootSurface concrete／dirt／metal → ShootSky → ShootSurface concrete count（弾痕の上限より多く）
   5 撃たれる     SpawnZombies 1 → Shoot torso until stagger → Shoot head until critical → … until dead → WaitFor Zombie.Sink
                  → SpawnZombies 1 → 左右の腕と脚を Shoot until severed → Shoot leftThigh until downed → Wait（這う）
                  → 両腕を Shoot until severed（這えない）→ ShootCorpse
   6 動き         SpawnZombies facing away（うろつく）→ behind → ShootSky（銃声で寄る）→ 隠れて Wait（諦める）
                  → behindBuilding（回り込む）→ narrow count 10（詰まって横へ）→ Wait（フラつき）→ KillAll
   7 攻撃         SpawnZombies 1 → LetGrab → Shoot grabbing（振りほどく）→ LetGrab → Wait（噛まれる）
                  → Downed を作って LetGrab（足をつかむ）→ KillAll
   8 湧く         SpawnZombies（上限より多く）→ KillAll → SetAutoSpawn on → Wait（湧く・補充）→ SetAutoSpawn off → KillAll
   9 拾う         PickUp fuel → Refuel → SetAutoSpawn on → Wait（目標の数が増える）→ off
  10 確認用       SetSwitch 各種 → FlyFreeCamera → SetRender 各 view → 戻す
  11 一時停止     Pause → MenuSelect Options → Back → Resume → Pause → Retry（本編を作り直す）
  12 死ぬ         Die → WaitScene gameOver → MenuSelect Retry
  13 脱出         Escape → WaitScene clear → MenuSelect Title → MenuSelect Quit

 種で決まる出来事（クリティカル 10%・死亡アニメの種類）は、種を決めているので毎回同じ結果になる。
 種を変えて起きなくなったら、Shoot の until="critical" が時間切れになって表に出る。

 9. 毎回同じ場面にする
================================================================================
 （Q4 が案 A の場合）
 ・乱数の種：GameWorld::place に種を渡す形を足す。渡さなければ今と同じく起動からの時間（ふつうに遊ぶときは毎回違う）
   → ゾンビの倒れ方・個体差・クリティカル・ガソリンの置き場所が毎回同じになる
   （ワールドの状態の保存 5-6 の「種を決める所」と同じ物。こちらを先に作れば 5-6 でも使える）
 ・ZombieSpawner を止める口を足す（SetAutoSpawn）
 ・本編はシナリオで Start してから始まる（町の始めの場所 TownMap::playerStart から）
 ・行動はティックごと（1/60 秒の固定の歩み）に進める。描画の回数（フレームの速さ）に左右されない
 ・仮想のパッドの入力は、描画ごとに 1 回 Pad が読む。押した瞬間（triggered）は 1 回の描画だけ立てる（人がキーを押したのと同じ）

 それでも完全には同じにならない所（12 章）
  ・音・GPU の待ち時間・Windows の割り込みなど、ゲームの外のぶれ
  ・1 回の描画で進むティックの数（0〜5）は PC の速さで変わる。世界の進み方は同じだが、描く回数は変わる

 12. 懸念点
================================================================================
 ・作業がとても大きい：行動 約 35 個・出来事 約 70 か所・メニューの口・種の固定。今までで一番大きい（手順 5 の 3〜4 倍）
   → 10 章の 4 段に分け、段ごとに画面で確かめる
 ・自キャラの道探し：NavMesh はゾンビの体の大きさで作っているので、自キャラが通れない所を通そうとすることがある → timeout で次へ進む
 ・部位を狙って撃っても、照準のぶれ・反動・ゾンビの動きで別の部位に当たることがある
   → Shoot は until の状態になるまで撃ち続ける（狙った部位以外に当たっても止めない）。倒れてしまったら新しく出し直す
 ・「詰まって横へ」「フラつき」「探すのを諦める」は、場面しだいで起きないことがある → expect と timeout で表に出す。起きやすい場面は作りながら探す
 ・出来事の名前は文字列なので、打ち間違えると数えられない → 名前の一覧（AutoPlayEvents）に無い名前は Debug で止める。シナリオの expect も読むときに一覧と照らす
 ・Pad.cpp に文字列を書かない決まり（メモリ）：仮想のパッドの口は WorkId だけで受ける。名前と WorkId の対応は GameLib の WorkIdName を使う
 ・出来事の印が多いフレームは、1 フレーム 16 個までの印の上限を超えることがある（ゾンビが何体も同時に撃たれた など）
   → CSV の events 列からは落ちるが、AutoPlayEvents の回数は別に数えるので、発火の表は正しい
 ・前後でコードを変えると、同じシナリオでも流れが変わることがある → 行動ごとのかかった秒・フレーム数が変わるので、表で気付ける

  ★Q4. 「速くなった／遅くなった」をどこで決めるか
      案 A（おすすめ）：平均の差が 5% 以上 かつ 0.05ms 以上なら印を付け、それ以外は「差なし（ぶれの内）」
      案 B：印は付けず数字だけ　案 C：統計の検定（U 検定など。ここまでは要らない）

 15-3. 読む物（今の CSV の形）
  ・Record CSV を止めると Profiling/<起動時刻>/perf_<時刻>.csv と perf_<時刻>_system.json が書かれる（FrameRecorder::stop）
  ・CSV の 1 行目は記録した日時（startedAt,…）。列名は 2 行目から。1 行目が startedAt でない古い CSV は飛ばさない
  ・列：frame, frameMs, cpuMs, presentMs, sleepMs, otherMs, gpuMs, ticks, state, wroteFile, events, 区間の列（Scene.update など）、
        gpu.<名前> の列、回数の列（PROFILE_COUNT）
      gpuMs は空のことがある。state が loading / suspended の行はプレイ中の数字に混ぜない。wroteFile = 1 は計測のファイルを書いたフレーム。
      区間は入れ子（World.player は Scene.update の中）なので足し合わせない
  ・_system.json：ビルドの種類・VSync・描く大きさ・CPU と GPU の名前・電源・requiredFps(60)・goalFps(144)

 15-4. 数え方
  ・数える行：state が playing、wroteFile が 0。始めの --skip フレーム（既定 30。右上の表示がならす数 kAveragedFrames と同じ）も捨てる
  ・gpuMs が空の行は gpuMs の列だけから外す。区間の列が 0 の行も 0 のまま数える（1 フレームあたりの時間として比べる）
  ・列ごとに 平均・中央値・p95・p99（Excel の PERCENTILE.INC と同じ線形の補間）・最大
  ・frameMs だけ 平均の FPS・1% low の FPS（1000 ÷ p99）・予算（_system.json の requiredFps・goalFps。無ければ 60・144）を超えた数と割合
  ・差：後 − 前（ms）と前に対する割合（%）。マイナスが速くなった方
  ・AutoPlay の表（8 章）も同じ数え方にする

 15-5. 出す物
  ・見出し：前・後のファイル名、数えたフレーム数、捨てたフレーム数（loading / suspended / wroteFile / skip ごと）
  ・表 1 全体（frameMs・cpuMs・gpuMs・presentMs・sleepMs・otherMs）・表 2 FPS と予算を超えた数・
    表 3 区間（どちらかの平均が 0.05ms 以上の物を差の大きい順。--all で全部）・印の回数（場面の中身が違わないかの目安）
  ・片方にしか無い区間は「−」にして、表の下に名前を並べる
  ・条件が違うときは比べるのを止めず、表の上に注意を出す（比べられないと決めるのはユーザー）：
      ビルドの種類が違う・VSync が入っている（cpuMs・gpuMs で比べる）・描く大きさが違う・CPU / GPU / ドライバが違う・
      電源がバッテリー・数えたフレームが 300 未満・前と後のフレーム数が 2 倍以上違う・_system.json が無い

 15-6. 部品（tools/perf_compare.py 1 つ。関数ごとに役目を 1 つ）
  find_latest_pair()・read_recording()・summarize()・compare()・check_conditions()・format_tables()・main()
  定数はファイルの頭に名前を付けて置く：DEFAULT_SKIP_FRAMES = 30、MIN_MEANINGFUL_MS = 0.05、CHANGE_RATIO = 0.05、MIN_FRAMES = 300、
  FRAME_COUNT_RATIO = 2.0、DEFAULT_REQUIRED_FPS = 60、DEFAULT_GOAL_FPS = 144

 15-7. 確かめ方と懸念点
  ・引数なし・2 つ指定・1 つ指定の 3 通りが動く。1 つの列の平均と p99 が Excel の AVERAGE・PERCENTILE.INC と同じ
  ・同じファイルを前と後に渡すと、差がすべて 0・判定がすべて「差なし」
  ・場面がそろっていないと、差が変更のせいか場面のせいか分からない（ツールでは直せない。印の回数と注意で気付く。直すのはワールドの状態の保存や AutoPlay）
  ・区間の名前を後で変えると、前と後で別の区間に見える（「片方にしか無い区間」に出るので気付ける）
  ・後回し：グラフ・3 つ以上の記録を並べる・load_*.json の比較
