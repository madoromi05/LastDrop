 0. 決めたこと（Q1〜Q4）
================================================================================
 Q1. 覚え方
     ★A：動かしてコンパイルした結果（頂点と画素のバイトコード）を、読んだファイルの更新時刻と一緒にファイルへ書く。
          次の起動で、更新時刻が今と同じなら、それを読んでコンパイルを飛ばす
          ・今メモリに覚えている物（CompiledShader）をそのまま書くだけ。.hlsli を 1 つ変えればコンパイルし直すので、ホットリロードは今のまま
      B：ビルドの時に fxc で .cso を作る（ビルドの設定が増え、動かしている間に直したシェーダとの二重の管理になる）

 Q2. 置き場所
     ★A：作業フォルダの ShaderCache/<Debug か Optimized>/ に、シェーダ 1 本 1 ファイル。git には入れない
          ・コンパイルの設定は Debug（D3DCOMPILE_DEBUG・最適化なし）と、それ以外（Profile・Release。OPTIMIZATION_LEVEL3）の 2 通り。
            同じ設定どうしは同じフォルダを使い、Debug と Profile を行き来しても書き換え合わない
          ・ファイル名はシェーダのパスの / と \ を _ にした物（Resource_Shader_DeferredLighting.hlsl.bin）

 Q3. 読んだ物を使ってよいかの確かめ
     ★A：ファイルの頭の印・形式の番号・コンパイルの設定が今と同じで、読んだファイル全部の更新時刻が今と同じとき。
          読めない・壊れている・シェーダが作れないときは、黙ってコンパイルし直して書き直す（遊ぶ人には何も出さない）

 Q4. 古いファイルの片付け
     ★A：しない。シェーダ 1 本につき 1 ファイルを上書きするだけで増えない（31 本で数 MB）

================================================================================
 ・GameLib/src/Graphics/ShaderImpl.h の compile：起動中に同じファイルをコンパイル済みで、読んだファイルが変わっていなければメモリの結果から作る

 2. やること
================================================================================
 ・CompiledShader.h（新）：FileStamp と CompiledShader を ShaderImpl.h から移す（ShaderImpl と ShaderDiskCache の両方が使う形のため）
 ・ShaderDiskCache（新。GameLib/src/Graphics）：1 本のシェーダの CompiledShader を、ファイルへ書く・ファイルから読む係
   ・作るときに覚える所（フォルダ）とコンパイルの設定を受け取る（単体テストで別のフォルダを渡せるように）
   ・load：覚えた物があって形式と設定が今と同じなら読む。更新時刻が今と同じかは呼ぶ側（isUnchanged）が見る
   ・save：フォルダが無ければ作って書く。書けなくても何もしない（次の起動でコンパイルし直すだけ）
 ・ShaderImpl::compile：メモリ → ファイル → コンパイル の順に探す。コンパイルできたらメモリとファイルの両方に覚える
 ・.gitignore に /LastDrop/ShaderCache/

 3. 測り方と見込み
================================================================================
 ・前：load_Game 1,532・1,572ms（shader 728・736ms）、load_Boot 866・958ms（shader 136・134ms）
 ・後：このビルドで 1 回起動して出撃（ここで覚える）→ もう一度起動して出撃した load_Game・load_Boot の shader と totalMs と longestFrameMs
 ・見込み：shader 728 → 10〜20ms（同じ起動の 2 回目と同じくらい。ファイルを読む分だけ増える）。出撃のロード 1.5 → 約 0.8 秒、
   一番長いフレーム 726ms → 300ms 以下（TownVisibility などが残る）。起動 0.87 → 約 0.74 秒
 ・単体テスト（使い捨て。scratchpad）：書いて読むと同じ中身／設定が違うと読まない／壊れたファイルは読まない／無いファイルは読まない

 4. 懸念点
================================================================================
 ・シェーダを書き換えた後の最初の 1 回は、今までどおりコンパイルする（その 1 本だけ）
 ・更新時刻だけを見る。中身を戻して時刻だけ古くする（git の checkout など）と、時刻が変わるので作り直す側に倒れる
 ・D3DCompiler の DLL が変わっても、バイトコードの形は同じなので読める
 ・Manager の中の文字列から作るシェーダ（ManagerImpl.h の D3DCompile）は対象外（ファイルが無く、数も少ない）
