 1. 決めること（★はおすすめ）
================================================================================
 Q1. 「構えている」はどの段階か（武器は しまう／持つ／覗く の 3 段階）
     ★A：覗いている（右クリックでサイトを覗いている）間。覗くのをやめてから 2 秒で消える
          ・ふだん歩いている間は出ないので、画面がすっきりしたまま（今までの「HUD は出さない」に近い）
      B：銃を出して持っている間ずっと。しまってから 2 秒で消える
          ・銃を出している時間がほとんどなので、ほぼ出しっぱなしになる

 Q2. 出す中身
     ★A：銃の絵（カバンと同じ絵）＋「28 / 30」（弾倉の今の数 / 弾倉に入る数）。予備の弾の数は出さない
      B：A に、絵の下に予備の弾の数（例「予備 60」）を足す

 Q3. 2 秒の数え方
     ★A：「覗いている・リロード中」のどちらも終わった瞬間から 2 秒（リロードを込め終えた後も 2 秒残る＝新しい数が見える）
      B：覗くのをやめたときだけ 2 秒残し、リロードは終わったらすぐ消す

 Q4. 出る・消えるとき
     ★A：出るときは 0.15 秒、消えるときは 0.3 秒で、薄さをなめらかに変える（2 秒の後に 0.3 秒かけて消える）
      B：パッと出てパッと消える

 Q5. 半透明の具合と大きさ（座標の高さ 480 のとき）
     ★A：右下から 16 離した所に、幅 150・高さ 56 の黒い板（不透明度 45%）。
          左に絵（48×48）、右に「28 / 30」（大きい文字）。絵と文字は不透明度 90%
      B：板を出さず、絵と文字だけを半透明で置く（明るい場所で読みにくくなる）

 Q6. 弾倉が空のとき
     ★A：数を赤くする（「0 / 30」が赤）。それ以外は白
      B：色は変えない

 2. タルコフでは
================================================================================
  ・タルコフには、弾数をいつも出す HUD は無い。Alt+T で弾倉を確かめると、正確な数ではなく
    「Full / Nearly full / Empty」のようなおおよその量だけが出る（出典 1・2・3）。
  ・確かめたときに画面のどこに出るか（右下かどうか）は、調べた範囲では分からなかった。
  ・あえて変える所：依頼どおり「正確な数」を「覗いた・リロードした時に自動で」出す。
    表題の「爽快さを追求したタルコフ」に合わせ、弾を数える手間を減らす（確かめる操作を増やさない）。
    いつも出しっぱなしにはしない所（必要なときだけ出す）はタルコフの「画面に出さない」考えに寄せる。

 3. 今のコードで関係するところ
================================================================================
  ・GameScene::draw（GameScene.cpp 850 行あたり）：InteractMarkers を積む → RaidHud::draw（中で UiRenderer::draw）。
    → 弾数の表示はこの間で「積むだけ」にする（UiRenderer は 1 回の描画に 1 回しか draw できない）。
  ・HoldComponent::heldGun( player )：手に持っている銃（素手なら nullptr）。isAiming()：覗いているか。
  ・GunComponent::isReloading()・magazineRounds()・spec().magazineCapacity・spec().item（絵を引く物の種類）。
  ・ItemIcons::icon( ItemId )：物の絵（読み込み中は nullptr）。カバンの画面ごとに 1 つ持っている。

 4. やること
================================================================================
  4-1. AmmoHudVisibility（新規・GameSrc/Scene/Game/Hud/）
       ・「出す条件が今あるか」を毎ティック受け取り、残す時間（2 秒）と薄さ（0〜1）だけを決める。
       ・秒は AmmoHudParams の定数（2.0 / 0.15 / 0.3）。ティックへは GameTime::secondsToTicks。
       ・一時停止中は進めない（ゲームの更新から呼ぶので自然に止まる）。
  4-2. AmmoHud（新規・同じ所）
       ・表示だけ。銃・薄さを受け取り、右下に板・絵・「28 / 30」を積む（draw は呼ばない）。
       ・自分で ItemIcons を 1 つ持つ（カバンの画面と同じ持ち方）。
       ・並べ方・色の定数はこの .cpp の無名名前空間に置く（マジックナンバーにしない）。
  4-3. GameScene
       ・更新：heldGun があり（覗いている か リロード中）を AmmoHudVisibility へ渡す。銃を持っていなければ条件なし。
       ・描画：InteractMarkers の後・RaidHud::draw の前に AmmoHud::add。カバン・一時停止を開いている間は出さない（今の else の中に置く）。
  4-4. vcxproj / filters に 4 ファイルを足す（VS を閉じてから）。
  4-5. Debug / Release / エディタの 3 構成でビルド。画面の確認はユーザー。

  実装（2026-11-08）：上のとおり。Q2 の変更で、文字は「弾倉の数（大きい文字）/ 予備の数」。数の幅は外から測れないので、
       数・「/」・予備をそれぞれ決まった列の真ん中に置いた（AmmoHud.cpp の kRoundsColumn など）。
       Debug / Release / Profile ビルド済み・画面確認待ち・未コミット。

  影響範囲：GameScene と新しい 2 クラスだけ。銃・構え・リロードの処理は読むだけで変えない。
  修正の入口：時間 → AmmoHudParams、見た目 → AmmoHud.cpp の定数、出す条件 → GameScene の 1 か所。

 5. 懸念点
================================================================================
  ・リロード中の数：今の作りでは込め終えた瞬間に数が変わる（抜いた時点では減らない）。リロードの途中は古い数のまま見える。
    （タルコフのように抜いた時点で 0 に見せたい場合は、別に決める）
  ・絵は正方形 256×256。ライフルは横長の物なので、48×48 だと小さく見えるかもしれない（画面で見てから大きさを直す）。
