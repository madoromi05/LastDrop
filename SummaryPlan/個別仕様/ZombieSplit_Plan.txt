 ★1 どこまで分けるか
     （おすすめ）案A：段階A（根の動き）・段階B（よろけ）・段階C（体を引きずる体の形）の 3 つ
       ・どれも「中身をそのまま移す」だけで、動きは変わらない。Zombie は約 988 → 約 800 行、メンバは約 50 → 約 38
       ・3 つとも「持っている値」と「それを変える関数」がひとまとまりで、Zombie の外とはほとんど話さない
     （別案）案B：段階A だけ（一番まとまっている。メンバ 6・関数 6・約 75 行）
     （別案）案C：案A ＋ 立っている・倒れている・死体を State パターンのクラスに分ける（7 章）
       ・update の分岐は一番すっきりするが、追う・攻撃・よろけ・根の動きがどの状態からも呼ばれるので、
         状態のクラスへ Zombie の中身をほとんど渡すことになる。今は勧めない

 ★2 根の動きの区間が、メッシュと移動を「借りて持つ」か「毎回もらう」か
     （おすすめ）案A：作るときに SkinnedMeshInstance と CharacterMover を借りて覚える（mMover と同じ形。CharacterMover も this を覚えている）
       ・呼ぶ側は mRootSpan.end( &mPosition ) のように短く書ける。今 endRootMotion を呼んでいる 4 か所がそのまま 1 行
     （別案）案B：関数ごとに mesh・mover を引数で渡す。借りている物が見えやすいが、呼ぶたびに 3〜4 個の引数が並ぶ

--------------------------------------------------------------------------------
 決まっていること（今までの方針から）
--------------------------------------------------------------------------------
 ・動きは 1 つも変えない（式・呼ぶ順・定数はそのまま移す）
 ・Zombie の public の関数（GameWorld・確認用の表示が使う物）は 1 つも変えない
 ・新しいクラスは GameSrc/Zombie に置く（ZombieChase・ZombieAttack と同じく、ゾンビの部品）。
   部品は Zombie のメンバとして値で持つ（unique_ptr にしない。今の ZombieChase などと同じ）
 ・どの値を・どのアニメで使うか（攻撃のアニメには通り抜けの決まりが Target、など）を決めるのは Zombie のまま。
   分けたクラスは「言われた通りに区間を進める・時間を数える・形を測る」だけ

 2. 今のコードで分かったこと
================================================================================
 ・今どう動くかが、mState だけでなく次の組み合わせで決まる：
     mStaggering（よろけ中）・mAttack.isActive()（攻撃中）・mRootMotion != nullptr（根の動きの区間中）・mCrawl.isStarted()（引きずり中）
   update を読むには、これを全部頭に置く必要がある
 ・メンバのうち、まとまって 1 つの仕事をしている物：
     根の動き    mRootMotion・mRootPass・mRootAnchor・mRootStartOffset・mRootLastTime・mMeshOffset（6 個）
                 と startRootMotion・applyRootMotion・endRootMotion・freezeRootMotion・meshRoot・moveFooting（6 関数・約 75 行）
     よろけ      mStaggering・mStaggerCooldownTicks（2 個）と canStagger・updateStagger の時間を数える所
     引きずる体  mCrawlCenter・mCrawlChestOffset・mCrawlYawOffset（3 個）と startCrawling の測る所・placeCrawlingBody
 ・追う（chase・avoidCrowd・weave・standAside・turnToward）と攻撃（canStartAttack・startAttack・updateAttack）は、
   互いに呼び合い、mChase・mPath・mAttack・mMesh・mPosition・mAngleY を全部使うので、きれいな境目が無い（7 章）

================================================================================
 3. 分け方の方針
================================================================================
 「持っている値」と「それを変える関数」が一緒に動く所だけを分ける。
 分けたクラスは Zombie の状態（State）・アニメの名前・相手（ChaseTarget）を知らない。
 Zombie に残るのは「いつ・どのアニメで・どの決まりで」始める・終えるか、の判断。
 こうすると、根の動きがおかしいときは ZombieRootMotionSpan だけ、いつ始めるかがおかしいときは Zombie、と直す入口が分かれる。

 進める順：段階A → 段階B → 段階C（1 段ごとに 3 構成のビルドを通す）

 4. 段階A：根の動きの区間（ZombieRootMotionSpan）
================================================================================
 置き場所：GameSrc/include/GameSrc/Zombie/ZombieRootMotionSpan.h・src/Zombie/ZombieRootMotionSpan.cpp

 今の ZombieRootMotion（アニメごとの根の動きの表。ZombieModel が持ち、同じ種類の全員で共有）とは別のクラスにする。
 表は「アニメの何フレーム目で根がどこにあるか」、区間は「この体が今その表のどこを流していて、どこから始めたか」（1 体ごと）。

   // 攻撃・よろけ・倒れるアニメの間、腰の前後の動き（根の動き）を、壁・車に当たりながら置き場所へ移す区間（1 体ぶん）。
   // 移動の箱と bodyCenter は始めた所（アンカー）に残し、置き場所だけを根に付いて行かせ、絵はその分だけ戻して置く
   // （SummaryPlan/個別仕様/ZombieRootMotion_Plan.txt）。いつ始めて・どの表で・誰を通り抜けるかは持ち主（Zombie）が決める。
   class ZombieRootMotionSpan{
   public:
       // 置き場所を動かすとき、ほかの動くもののどれを通り抜けるか（今の Zombie::RootPass をそのまま移す）。
       enum class Pass{ None, Target, AllBodies };
       // mesh・mover：借りるだけ。この区間より長く生きていること（どちらも同じ Zombie のメンバ）。
       ZombieRootMotionSpan( SkinnedMeshInstance* mesh, const CharacterMover* mover );

       // 前の区間を閉じて（footing を絵の根へ戻す）、table のアニメを startTime から流し始めた区間を始める。table が nullptr なら閉じるだけ。
       void start( const ZombieRootMotion* table, float startTime, Pass pass, GameLib::Math::Vector3* footing );
       // 見えているアニメ時刻の分だけ、アンカーから当たりながら footing を動かし、絵の根をその分だけ戻して置く。区間の外なら何もしない。
       // passThrough：Pass::Target のとき通り抜ける体（nullptr 可）。
       void apply( const ICollisionBody* passThrough, GameLib::Math::Vector3* footing );
       void end( GameLib::Math::Vector3* footing ); // 区間を閉じ、footing を絵の根へ戻す
       void freeze();                              // 区間を閉じ、ずれは残す（倒れ終わった死体）
       // footing を moved だけ動かした（攻撃中に寄る）。区間の間はアンカーも同じだけ動かす。
       void moveFooting( const GameLib::Math::Vector3& moved, GameLib::Math::Vector3* footing );

       bool isActive() const;                                                       // 区間の中か
       const GameLib::Math::Vector3& anchor() const;                                // 始めた所（区間の中だけ意味がある）
       GameLib::Math::Vector3 meshRoot( const GameLib::Math::Vector3& footing ) const; // 絵の根（footing ＋ ずれ）
   private:
       // 今の Zombie の mRootMotion・mRootPass・mRootAnchor・mRootStartOffset・mRootLastTime・mMeshOffset をそのまま移す
   };

 足元（mPosition）は Zombie が持ったまま、ポインタで渡す（足元は追う・引きずる・沈むでも使うので、区間の物にしない）。
 アニメごとの表 4 つ（mAttackRootMotion など）は Zombie に残す（どのアニメがどの表か、は Zombie の判断）。

 Zombie の書き換え：
   startRootMotion( t, time, RootPass::X ) → mRootSpan.start( t, time, ZombieRootMotionSpan::Pass::X, &mPosition )
   applyRootMotion( target )               → mRootSpan.apply( target ? target->body : nullptr, &mPosition )
   endRootMotion()                         → mRootSpan.end( &mPosition )
   freezeRootMotion()                      → mRootSpan.freeze()
   meshRoot()                              → mRootSpan.meshRoot( mPosition )
   moveFooting( m )                        → mRootSpan.moveFooting( m, &mPosition )
   mRootMotion ? mRootAnchor : mPosition   → mRootSpan.isActive() ? mRootSpan.anchor() : mPosition（bodyCenter）
 Zombie から消える：RootPass・関数 6 つ・メンバ 6 つ（★2 案A なら Zombie に残す 1 行の包みは作らない）

 注意：今の applyRootMotion は、Pass::Target で target->body を通り抜ける。target が nullptr のときは
 nullptr を渡す（今と同じ）。宣言の順は mMesh・mMover の後（借りるので）。

 5. 段階B：よろけの時間（ZombieStagger）
================================================================================
 置き場所：GameSrc/include/GameSrc/Zombie/ZombieStagger.h・src/Zombie/ZombieStagger.cpp

   // よろけの最中か・次のよろけを出せるまでの間あけ、を数える（SummaryPlan/個別仕様/ZombieStagger_Plan.txt）。
   // フルオートで当て続けても、よろけ続けて動けなくならないようにするため。頭に当たったときは間あけを待たない。
   // アニメを流す・止めるのは持ち主（Zombie）。ここは時間と「出してよいか」だけ。
   class ZombieStagger{
   public:
       ZombieStagger();
       bool canStart( BodyPart part ) const; // よろけていない、かつ（間あけが済んだ、または頭）
       void start();                         // よろけ始めた
       void finish();                        // よろけのアニメが終わった。ここから間あけを数える
       void cancel();                        // 倒れたので、よろけを打ち切る（間あけは数えない。今の mStaggering = false と同じ）
       void tick();                          // よろけていない間、間あけを 1 ティック減らす（今の updateStagger の else 側）
       bool isActive() const;
   private:
       bool mActive;
       int mCooldownTicks;
   };

 Zombie に残る：よろけのアニメが無ければ出さない判断（mStaggerAnimation）、アニメを繋ぐ・戻す、根の動きの区間を始める・閉じる。
 kStaggerCooldownSeconds は ZombieStagger.cpp へ移す（使うのはそこだけになる）。kStaggerStartTime・kStaggerFadeTicks は Zombie に残す。

 6. 段階C：体を引きずる体の形（ZombieCrawlBody）
================================================================================
 置き場所：GameSrc/include/GameSrc/Zombie/ZombieCrawlBody.h・src/Zombie/ZombieCrawlBody.cpp

 今の ZombieCrawl（腕の骨を曲げる、姿勢の書き換え）とは別にする。ZombieCrawl は「骨をどう曲げるか」、
 こちらは「倒れた体の胸の位置と、進む向きと見た目の向きのずれ」（置き場所の計算）で、仕事が違う。

   // 脚を失って倒れた体を、胸を中心に動かすための形（SummaryPlan/個別仕様/ZombieCrawl_Plan.txt）。
   // 倒れ終わった姿勢で一度だけ測り、その後は胸の位置と進む向きから、見た目の向き・足元を決め直す。
   class ZombieCrawlBody{
   public:
       ZombieCrawlBody();
       // 倒れ終わった姿勢（mesh の今の骨）から、腰 → 首を進む向き、胸を中心として測る。見た目は動かさない。
       // footing / angleY：今の足元と見た目の向き。*angleY を進む向きへ書き換える。骨が引けなければ false（何も変えない）。
       bool start( const SkinnedMeshInstance& mesh, const ZombieCrawlLayout& layout, const GameLib::Math::Vector3& footing, float* angleY );
       // 胸を step だけ動かした（壁に沿って滑った後の量）。
       void moveCenter( const GameLib::Math::Vector3& step );
       // 胸の位置と進む向き angleY から、見た目の向きを mesh へ、足元を footing へ書く（胸の高さは地面に合わせる）。
       void place( float angleY, const CharacterMover& mover, SkinnedMeshInstance* mesh, GameLib::Math::Vector3* footing );
       const GameLib::Math::Vector3& center() const; // 胸の位置（ワールド）。追う・回り込む・壁に当たるのはこの位置
   private:
       GameLib::Math::Vector3 mCenter;      // 今の mCrawlCenter
       GameLib::Math::Vector3 mChestOffset; // 今の mCrawlChestOffset
       float mYawOffset;                    // 今の mCrawlYawOffset
   };

 Zombie に残る：いつ引きずり始めるか（canStartCrawling）、追い方（crawlChase）、腕の数（hasArm・canCrawl。部位欠損を知っているのは Zombie）、
 攻撃の時計（mAttackClock。攻撃の段階の話なので、引きずる体の形ではない）。
 今の startCrawling の「mPath.clear()・mCrawl.start()」も Zombie に残す。

 7. 今回は分けない所と、その理由
================================================================================
 ・追う（chase・avoidCrowd・weave・standAside・turnToward・walkDistanceThisTick）：
   追う途中で「攻撃を始めてよいか」を見て攻撃へ移り、攻撃の間も turnToward を使う。引きずる体も同じ turnToward を使う。
   分けると、追う側のクラスが攻撃・引きずり・メッシュ・足元を全部借りることになり、Zombie を薄くした別の Zombie になるだけ
 ・攻撃（canStartAttack・startAttack・updateAttack・approachDuringAttack）：段階は既に ZombieAttack に分けてあり、
   残っているのはアニメ・根の動き・のけぞりとのつなぎ（Zombie の仕事そのもの）
 ・State パターン（★1 案C）：上の 2 つがどの状態からも呼ばれるので、今は勧めない。
   今回の 3 つを分けた後、状態ごとの update（updateStanding・updateDowned・updateAfterDeath）へ update の分岐を
   まとめるだけでも、読む所はかなり減る（これは段階C の後に、別に見せる）
 ・基底クラスが 5 つ（Component・ICollisionBody・IHittable・IDamageable・IWorldMember）なのは、
   どれも「できること」のインターフェースなので、設計の方針どおり（減らさない）

 11. 懸念点
================================================================================
 ・ZombieRootMotionSpan がメッシュを借りて setPosition するので、「メッシュを置くのは Zombie とこの区間の 2 か所」になる
   （今も applyRootMotion が置いているので、増えるわけではない。区間のコメントに書く）
 ・ZombieRootMotion（表）と ZombieRootMotionSpan（区間）は名前が似ている。両方の先頭のコメントに、もう一方との違いを書く
 ・Zombie.h の先頭の長い説明は、分けた部品へ移せる文（根の動きの細かい所など）を移し、Zombie には「誰に任せるか」だけを残す
