--------------------------------------------------------------------------------
 決まりごと（Claude の判断。確かめてもらう）
--------------------------------------------------------------------------------
 ・分離は「歩く向き」だけを変える。位置を直接動かさない（動くのは今までどおり CharacterMover の掃引だけ）
 ・分離で数えるのは、立って歩ける（Alive で、倒れていない・体を引きずっていない）ゾンビだけ。死体・這うゾンビは数えない
   （這うゾンビは足元に寝ているので、立っているゾンビが避けると不自然に大回りになる）
 ・攻撃に行っている 1 体は、分離で向きを変えない（つかみに行く動きを崩さない）。ほかの体はその 1 体から離れる
 ・近くのゾンビを探すのは、全員を見る（数十体なので全員どうしの距離で足りる。空間分割は要らない）
 ・F6 の Debug タブ（ゾンビの体力・通り道の表示）で、分離の向き（短い線）も見えるようにする
 ・値は調整値の構造体（ZombieCrowdParams）にして、F6 で動かせるようにする

 1. タルコフでは（と、ほかのゲーム）
================================================================================
 調べて分かったこと
 ・タルコフにはハロウィンのイベント（2024 年〜）で「感染者（ゾンビ）」が出る（Labs などに多数）。硬くて数が多い、という紹介まで
 ・別のパッチで、AI の気付き方（距離・視野・天気・姿勢）を作り直した。昔から「AI の巡回の道が間抜け」という声がある
 調べても分からなかったこと（推測で埋めない）
 ・タルコフのゾンビが、互いにどう避け合うか・車などをどう回り込むか（公式の資料・パッチノートに無い）
 ほかのゲーム・定番のやり方
 ・群れが互いにぶつからないように「近くの仲間から離れる向きを足す」（分離。Craig Reynolds の Steering Behaviors）
 ・Left 4 Dead の感染者の大群は、AI の作りを GDC で説明しているが、避け合いの細かい作りは今回の検索では確かめられなかった
 合わせる所・変える所
 ・タルコフの数字が無いので、定番の「分離」に合わせる。囲むかどうか（★1 案B）は遊びやすさで決める

 2. 原因（今のコードで分かったこと）
================================================================================
 押し合い
 ・追っている全員が、同じ一点（自キャラの足元）へまっすぐ向く（ZombiePath::steer の行き先が全員同じ）
 ・前のゾンビが 1.2m で止まると（kStopDistance）、後ろのゾンビは前の体の長方形に当たって滑るが、行き先がまっすぐ前なので
   滑る向きが決まらず、押し付けたまま止まる。2 体が向かい合うと、互いに相手の正面へ滑り合って動けなくなる
 ・Chase の間は「近づけない」を数えていない（あきらめるのは Search の間だけ）
 車などへの引っかかり（作ったときの原因。NavMesh に替えて無くなった）
 ・当時の道探しの図の点は交差点だけで、交差点から交差点への道が通りの途中の車を通り抜けていた

================================================================================
 3. 押し合いの直し（★1 案A）
================================================================================
 ・歩く向き ＝ 行き先（通り道の今の点）への向き ＋ 分離の向き × 強さ
 ・分離の向き：1.5m 以内の、立って歩けるほかのゾンビそれぞれから、自分への向き（水平・長さ 1）に
   （1 − 距離 ÷ 1.5m）を掛けて足す。足した長さが 1 を超えたら 1 にする
 ・強さ：0.8（行き先への向きより少し弱い。正面に仲間がいると、斜め前へ回り込む）
 ・止まっている間（自キャラまで 1.2m 以内で立っている）も、仲間と重なりそうなら（0.7m 以内）その場で少し向きを変えて半歩よける
   （ほかの体の後ろに隠れたまま止まり続けないように）
 ・群れの位置は、GameWorld が毎ティック「立って歩けるゾンビの位置の並び」を作って、全員の update に渡す（Zombie は名簿を知らない）
 ・案B（取り囲む）のとき：自キャラまで 4m 以内では、行き先を「自キャラのまわり 1.2m の輪の上で、今の自分の向きから見た位置」にし、
   分離で輪の上に散らばる

 5. どちらにも効く「詰まったら横へ」（★3）
================================================================================
 ・追っている（Chase）・探している（Search）間に、今向かう点へ 1.5 秒（0.3m ずつ）近づけなければ「詰まった」
   （10/26 変更）点との距離ではなく「自分が今向かう点の向きへ進んだ長さ」で数える。距離で数えると、ゾンビより速く逃げる
   自キャラを追う間、まっすぐ歩けていても詰まった扱いになり、一瞬横へそれていた。向きの成分だけを数えるので、
   壁に沿って滑るだけの動きは今までどおり「進めていない」になる
 ・詰まったら、今の向きの左右 90° の 1.5m 先のうち、腰の高さの線で通れる方（両方通れれば行き先に近い方）を「よける点」にし、
   そこへ着く（0.5m）か 1 秒たつまで、そちらへ歩く。その後、通り道を探し直す
 ・左右どちらも通れなければ、少し下がる（後ろ 1m）
 ・Search の「着けなければあきらめる」（2 秒）は、よけても着けなかったときだけにする（よける前にあきらめない）

 8. なめらかに曲がる（角・よけ・群れの揺れ）
================================================================================
 依頼：「経路探索：建物を回り込む」の動きをもっとなめらかにしたい（2026-11-18）

 原因（コードで分かったこと）
   ・角で止まって回る：向きの差が 60° を超える間はその場で回るだけ。通り道の点は角そのもので、
     角の 1m 手前で次の点へ切り替わるので、直角の角では差が 90° になり「止まる → 回る → 歩き出す」になる
   ・角の 1m 手前で次の点を向くと、まっすぐ次の点へ向かう線が角の内側（建物）へ切り込み、壁に沿って滑っていた
   ・回る速さが一定（1 秒 180°）で、回り始めと回り終わりに強弱が無い
   ・詰まったら真横 1.5m へ向きを切り替える。分離の向きは毎ティック求め直すので、群れの中で向きが小刻みに揺れる

 直し方（値はどれも ZombieCrowdParams。F6 の Tuning → ZombieCrowdParams で動かせる）
   A. 通り道に沿って少し先の点を向く（ZombiePath::aimPoint）
      ・角の点そのものではなく、自分 → 今の角 → その先…と通り道をたどって lookaheadDistance（1.5m）進んだ点を向く
      ・次の角へ移るのは、角の二等分線を越えたとき（ZombiePath::hasPassedCorner）。近さ 1m で切り替えると、
        先を向いて回る体が角へ近づかないまま次の点を向き、角の内側へ切り込むため。角の 0.3m 内に来たときも移る（折り返す角用）
      ・最初の角へ入ってくる向きには、通り道を探したときの自分の足元（mRouteStart）を使う
   B. 回る速さに強弱（ZombieLocomotion::turnToward）
      ・差に決まった割合を掛けて回す。差が半分になるまで turnHalfLife（0.1 秒）。上限は今のまま（立つ 180°/秒・這う 60°/秒）
      ・「60° を超える間はその場で回る」の決まりは残す。A で角では超えなくなり、真後ろの相手へ振り向くときだけ効く
   C. よける向きを斜め前に（ZombiePath::startSidestep・pickSidestep）
      ・向かう点の向きから左右 sidestepAngle（45°）の通れる方へ。通れなければ真横、それも無理なら下がる（今までどおり）
   D. 分離の向きをならす（ZombieLocomotion::avoidCrowd）
      ・前のティックに混ぜた向きから今の向きへ寄せてから混ぜる。半分追い付くまで separationHalfLife（0.2 秒）
      ・立ち止まったらならした向きを捨て、歩き出したら 0 から寄せる
   共通：半減期 → 1 ティックに残る割合は GameTime::remainPerTick に置いた（AimSway の同じ計算もこれを使う）

 変えたクラス
   Core/GameTime（remainPerTick）・Player/Camera/AimSway・Zombie/Move/ZombiePath・ZombieLocomotion・ZombieCrowdParams

 確かめ方
   ・Debug・Profile・Release のビルドが警告なしで通る（2026-11-18 通過）
   ・建物の角を回って追わせると、角で止まらずに弧を描いて曲がる（F6 の Debug タブの水色の線で、通り道の角を見ながら）
   ・群れで追わせると、向きが小刻みに揺れない。詰まった体は斜め前へよけて歩き続ける
   ・F6 で lookaheadDistance を 0 にすると、角の点そのものを向く（比べるため）

 懸念点
   ・先読みの点は角の内側を少し回るので、体が建物の角に触れて滑ることがある（今までの 1m 手前で切り替える形よりは浅い）。
     気になるなら lookaheadDistance を短くする
   ・回り終わりがゆっくりになる分、攻撃の前に相手の方を向き終わるのが少し遅れる

 9. 引っかかる原因を調べる仮の記録（ZombieStuckProbe）
================================================================================
 依頼：8 章の後も「まだ引っかかることがある」。データを取れるようにして原因を確かめる（2026-11-18）
 今の形（まずここを見る）：原因が分かった（10 章）ので、CSV の書き出しはユーザー指示で消した。消した物は
   ZombieStuckProbe・SweepHit の target と body・CharacterMover::move( delta, lastHit )・NavMesh::distanceToFloor と、
   ZombieMoveTrace の出来事の種類・CSV の列の値。残したのは画面だけ（F6 の Zombie info の赤い印と番号・先読みの点への紫の線）で、
   ZombieMoveTrace は印を出すか（mark・isMarked）と向いている点（aimPoint）だけを持つ。下の列の説明は作ったときの形

 見分けたい原因の候補
   1. 先読みの点が角の内側を回り、体が建物の角にこすれる        → hit が Wall
   2. 仲間どうしで押し合って詰まる                                → hit が Zombie・neighbors が多い
   3. 床（NavMesh）の外へ押し出され、道探しも失敗して壁へ向かう   → floor_dist が 0 より大きい・route_left が 0
   4. 床の形に無い小物（消火栓・街灯など）にぶつかる              → hit が Box で、floor_dist は 0
   5. 向く点が揺れて、その場で回り続ける                          → event が Turning
   6. 道探しの順番待ちで古い通り道を歩く                          → waiting_path が 1

 記録する出来事（ZombieMoveTrace::Event。1 つにつき 1 行）
   Sidestep    ：向かう点へ 1.5 秒進めず、よけ始めた（ZombiePath）
   GiveUp      ：見失った後、着けないので探すのをあきらめた
   WanderStall ：うろつく先へ近づけず、選び直した（ZombieChase）
   NoProgress  ：歩きたいティックが 1 秒続く間に、体の前へ進めた長さが進みたかった長さの 3 割未満（壁に沿って横へ滑った分は数えない）
   Turning     ：歩きたい 1 秒の半分以上、その場で向きを変えていた

 書く所：Profiling/zombie_stuck_log.csv（出撃のロードが終わるたびに作り直す）
 列：time（ロードからの秒）, zombie（GameObject の番号。画面の赤い番号と同じ）, event, mode, runner, crawling,
     x, z, angle, dest_x, dest_z, dest_dist, aim_x, aim_z（先読みで向いている点）, route_left（残りの通り道の点の数）, waiting_path,
     checked_wanted / checked_forward / checked_turning_ticks（最後に確かめた 1 秒の、進みたかった長さ・前へ進めた長さ・回っていたティック）,
     floor_dist（一番近い床までの水平の距離。床の上なら 0、近くに無ければ -1）, neighbors（1m 内のほかのゾンビの数）,
     hit（最後に歩いたティックに最後に当たった相手：None / Box / Wall / Player / Zombie / Body）, hit_zombie（相手がゾンビならその番号、ほかは -1）,
     hit_normal_x, hit_normal_z（当たった面の向き）

 画面（F6 の Debug タブの Zombie info）
   ・出来事の後 3 秒、頭の上に赤い縦線と十字、その上に CSV と同じ番号（#12 など）
   ・追う・探す間は、先読みで向いている点へ紫の線（水色の通り道・橙色の分離と並べて見る）

 変えたクラス
   新：Zombie/Move/ZombieMoveTrace・DebugMode/ZombieStuckProbe

================================================================================
 10. ナビメッシュの半径を移動の長方形から求める
================================================================================
 依頼：9 章の記録で、原因は「ゾンビの 2D の大きさが実際よりも小さいこと」と分かった（ユーザー。2026-11-18）
       聞き直した答え：小さいのは「ナビメッシュの前提」。直し方は「余白を増やす」

 原因（コードで確かめたこと）
   ・ナビメッシュ（NavMeshBuilder の kAgentRadius = 0.4m）は「ゾンビの長方形の半幅は約 0.3m」として床の縁を壁から離していた
   ・実際の移動の長方形（BodyFootprint）は、T ポーズの胴と脚を囲んで四辺へ 0.15m 足した大きさ。0.4m はこの余白より前の大きさで決めた値で、
     斜めを向くと角がさらに外へ出る。通り道の上をまっすぐ歩いても、長方形の角が壁に届いてこすれていた
   ・2026-11-03 の時点で「まだ引っかかるなら、ナビメッシュの半径を長方形の対角から求める」と残していた件

 直し方
   ・BodyFootprint::reachRadius：足元を中心に、どの向きでも長方形が収まる円の半径（足元から一番遠い角までの水平の距離）
   ・ナビメッシュの半径 ＝ reachRadius ＋ navMeshClearance（ZombieDirector::navMeshRadius）
   ・余白は 2 つとも ZombieCrowdParams（F6 の Tuning → ZombieCrowdParams）。どちらも次の出撃から効く（出撃のロードで作るため）
       footprintPadding  ：長方形を体より一回り大きくする幅（0.15m。今までの ZombieModel の kFootprintPadding）
       navMeshClearance  ：床の縁を、長方形が収まる円の外へさらに離す幅（0.05m で始める）
   ・ナビメッシュを作る段（GameLoader の NavMesh）で、ゾンビの設計図（ZombieModel）を先に作って半径を求める（setup はそれを使う）
   ・TownCache は、覚えた床と半径が違えば作り直す（NavMesh::agentRadius で比べる）
   ・ロードのデバッグ出力：「ZombieFootprint: reach … m -> navmesh radius … m」と「NavMesh: agent radius … m -> eroded … m」

 変えたクラス
   Collision/BodyFootprint（reachRadius）・Map/NavMeshBuilder（半径を引数に。kAgentRadius は消した）・Map/NavMesh（build に半径・agentRadius）・
   Map/TownCache・Scene/Game/World/TownEnvironment・GameWorld・ZombieDirector（navMeshRadius・prepareModel）・
   Zombie/Animation/ZombieModel（余白を ZombieCrowdParams から）・Zombie/Move/ZombieCrowdParams

 懸念点
   ・半径を大きくすると、半径の 2 倍より狭い隙間（建物の間・車の間）は床から消え、ゾンビは回り込む
   ・床のますは 0.2m なので、削る幅は 0.2m の倍数に切り上がる（例：半径 0.45m なら 0.6m 削り、1.2m より狭い所が通れない）。
     ロードの出力を見て、狭すぎるならますを 0.1m にする（作る時間は延びるが、町ごとに 1 回で覚える）

 確かめ方
   ・Debug・Profile・Release のビルドが警告なしで通る（2026-11-18 通過）
   ・ロードのデバッグ出力で reach・navmesh radius・eroded を見る
   ・F6 の Zombie info で、床の縁（薄い緑）が前より壁から離れ、引っかかりの赤い印が減る
