 ★ ユーザーに決めてもらうこと（おすすめを先に書く）
--------------------------------------------------------------------------------
 ★1 秒→ティックの丸め方
     （おすすめ）案A：一番近い整数へ丸める（std::lround）
       ・float の誤差で 125.99999 になっても 126 になる。調整値（F6）を何にしても 1 ティック短くならない
       ・リロードの音の合図が 1 ティック（約 17ms）遅くなる（9 章）。Blender で測った時刻にはこちらの方が近い
     （別案）案B：切り捨てのまま、誤差の分だけ足してから切り捨てる（seconds * 60 + 0.001）
       ・今の値はどれも変わらない。ただ「0.001 を足す理由」をコメントで説明しないといけない
     （別案）案C：切り上げ（std::ceil）。誤差で 90.00001 になると 91 になり、逆向きにずれるので勧めない

 ★2 角度を折り返す範囲
     （おすすめ）案A：[-180, 180)（180 は -180 にする。今の PlayerCharacter と同じ）
       ・同じ向きの表し方が 1 つに決まる（180 と -180 が両方出てこない）
       ・Zombie・FirstPersonControl では、ちょうど +180° のときだけ -180° になる（9 章。真後ろを向くときに
         回る向きが逆になるだけで、どちらへ回っても同じ速さで真後ろへ向く）
     （別案）案B：[-180, 180]（今の Zombie・FirstPersonControl と同じ）。PlayerCharacter の方が変わる

 ★3 角度の折り返しの計算のしかた
     （おすすめ）案A：floor で 1 回で計算する（degree - 360 * floor( ( degree + 180 ) / 360 )）
       ・何周ずれていても 1 回で済む。無限大が来ても止まらない（今の while だと終わらない）
       ・1 周の内の値は、今の while と同じ結果になる
     （別案）案B：今の while のまま 1 か所へ移すだけ

 ★4 行列から位置を取り出す関数をどこに置くか
     （おすすめ）案A：GameSrc の PlacementMatrix に足す（PlacementMatrix::translationOf）
       ・「置き場所の行列を作る・読む、ただ 1 か所」になる。GameLib は触らない
     （別案）案B：GameLib の Matrix34 に translation() を足す
       ・GameLib に setTranslation はあるのに、読む方が無い。ただ GameLib を変えることになる

--------------------------------------------------------------------------------
 決まっていること（ユーザーの指示・今までの方針から）
--------------------------------------------------------------------------------
 ・計算の結果は（9 章に書いた所以外）変えない。変えるのは「どこに書いてあるか」だけ
 ・秒で決めた値は秒のまま書き、使う所でティックへ直す（今のやり方のまま）
 ・形は今の GameSrc/Math のクラスに合わせる（AxisRotation・MatrixBlend と同じく、状態を持たない static 関数のクラス。
   中身は .cpp に書く。Release は LTCG が有効なので、別の .cpp にあってもインライン展開される）
 ・速さ・重力を「ティックあたり」に直す割り算（1 / ( seconds * 60 ) など）は float のままで丸めが無いので、今回は触らない

 2. 今のコードで分かったこと
================================================================================
 2-1. 秒→ティックが切り捨て
   static_cast< int >( seconds * GameTime::kTicksPerSecond ) が 22 か所にある
   （関数にしてあるのが 6 ファイル：Zombie・ZombiePath・WeaponReload・PlayerDamageView・AmbienceSystem(toFrames)・WeaponStance。
    残りは定数の初期化にそのまま書いてある）。

   float で計算すると、次の秒は 1 ティック短くなる（0.01 秒きざみで 0〜20 秒を調べて 10 個）：
       1.05 秒 → 62.999996 → 62（正しくは 63）
       2.1  秒 → 125.99999 → 125（正しくは 126）
       4.2・8.15・8.4・16.05・16.3・16.55・16.8・17.05 秒 も同じ
   今コードに書いてある秒の値はどれも当てはまらない（0.2・0.25・0.5・0.6・1・1.2・1.5・2・10 などはぴったり）。
   当てはまる可能性があるのは F6 で動かす値（WeaponStanceParams::tapSeconds、ZombieCrowdParams::sidestepAfterSeconds・
   sidestepSeconds）と、乱数で決める秒（ZombieChase の音を聞いてからの遅れ・うろつく前の待ち）。

   割り切れない値は、切り捨てで 1 ティック近く短くなっている：
       リロードの合図 0.45 / 1.25 秒 = 21.6 ティック → 21、1.6 / 1.25 = 76.8 → 76、2.1 / 1.25 = 100.8 → 100

 2-2. 同じ計算のコピー
   名前                    数   ファイル
   wrapSignedAngle          3   Zombie・PlayerCharacter・FirstPersonControl（範囲が違う：PlayerCharacter だけ [-180,180)）
   flatDistance             5   Zombie(flatDistanceBetween)・ZombieChase・ZombiePath・ZombieStride・StreetGraph
   flatten                  1   SweepMath（ほかは Vector3( v.x, 0.f, v.z ) を直接書いている）
   translationOf            5   Zombie・ZombieCrawl・ZombieFlinch・SeveredLimb・FirstPersonBody
   lerp                     2   MatrixBlend・ZombieCrawl
   clamp                    1   ZombieCrawl
   clampSigned              2   AimSway・AimRecoil
   smoothStep / easeInOut   4   CameraShake・SkinnedMeshInstance・PlayerDamageView・WeaponReload
   wrapPhase（0〜1 の輪）   2   AimSway（1 回だけ引く）・FootstepEmitter（while）
   向き（atan2( x, z )）    4   Zombie ×3・FirstPersonControl（「0 は +Z、90 は +X」の約束をコメントで繰り返している）
   ticksToSeconds           1   Zombie（WeaponReload にもその場で書いた割り算がある）

 3. 秒→ティックの変換（GameTime）
================================================================================
 置き場所：今の GameSrc/Core/GameTime.h（ティックの長さを決めている所。直す入口が「時間の単位」と同じ所になる）。

   namespace GameTime{
       const float kTicksPerSecond = 60.f;  // 今のまま
       const float kTickSeconds = ...;      // 今のまま
       const int kMaxTicksPerFrame = 5;     // 今のまま
       // 秒をティック数へ直す。一番近い整数へ丸める（★1）。
       // 切り捨てにしないのは、float の誤差で 2.1 秒が 125.99999 ティックになり、1 ティック短くなるため。
       // 負の秒は来ない前提（来たら負のティックを返す。今の呼び出しも同じ）。0 秒なら 0。
       int secondsToTicks( float seconds );
       // ティック数を秒へ直す（確認用の表示・合図の時刻を秒で読む所が使う）。
       float ticksToSeconds( int ticks );
   }

 ・中身は GameSrc/src/Core/GameTime.cpp に書く（新しく作る）。ヘッダに <cmath> を入れないため
 ・定数の初期化に使っている所（const int kXxxTicks = secondsToTicks( kXxxSeconds );）は、今と同じく
   起動時に計算される。kTicksPerSecond は定数なので、ほかの .cpp の初期化の順に左右されない
 ・各ファイルの secondsToTicks・toFrames・ticksToSeconds は消して、GameTime:: のものを呼ぶ
 ・FireControl の連射の間隔は、GameTime::secondsToTicks( kSecondsPerMinute / kRoundsPerMinute ) と書き直す
   （1 発の間隔の秒をティックへ直す、と読めるように。値は 6 ティックのまま）

 4. 角度（AngleMath）
================================================================================
 置き場所：GameSrc/include/GameSrc/Math/AngleMath.h・src/Math/AngleMath.cpp（新しく作る）。
 角度は全部「度」（GameLib の sin・cos・atan2 が度で受けるのに合わせる）。

   // 水平の向き（度）の決まりごとの、ただ 1 か所。向き 0 は +Z、90 は +X（PlacementMatrix・rotateY と同じ回り方）。
   class AngleMath{
   public:
       // degree を [-180, 180) へ折り返す（★2・★3）。
       static float wrapSigned( float degree );
       // current から target へ回るときの、近い回り方の角度（[-180, 180)。正なら +X 側へ回る）。
       static float difference( float target, float current );   // = wrapSigned( target - current )
       // 水平の向き（direction の x・z だけを見る）を度で返す。x・z が両方 0 なら 0（向きが無い）。
       static float headingOf( const GameLib::Math::Vector3& direction );
   };

 置き換える所：
   ・wrapSignedAngle の 3 つ → AngleMath::wrapSigned
   ・Zombie::headingDifferenceTo・turnToward の「wrapSignedAngle( atan2( x, z ) - mAngleY )」→ AngleMath::difference( AngleMath::headingOf( ... ), mAngleY )
   ・Zombie 617 行・FirstPersonControl 213 行の atan2( x, z ) → AngleMath::headingOf
   ・ZombieCrawl・FirstPersonBody・BoxFitter の atan2 は「2 つの向きの間の角度」「主軸の角度」で、向きの約束とは別の計算なので触らない
   ・各ファイルの kHalfTurn・kFullTurn は、ほかに使っていなければ消す（ZombieChase の「真後ろ = +180」は残す）

 6. 数の計算（ScalarMath）
================================================================================
 置き場所：GameSrc/include/GameSrc/Math/ScalarMath.h・src/Math/ScalarMath.cpp（新しく作る）。

   // 1 つの数の、よく使う計算の、ただ 1 か所（GameLib::Math に無い物だけ。min・max・abs は GameLib のまま使う）。
   class ScalarMath{
   public:
       static float lerp( float a, float b, float t );            // a + ( b - a ) * t。t は 0〜1 に限らない
       static float clamp( float value, float low, float high );
       static float clampSigned( float value, float limit );      // -limit〜limit。limit は 0 以上
       // 始めと終わりがゆっくりになる曲線（smoothstep。t * t * ( 3 - 2t )）。t は 0〜1 で渡す（外は丸めない。今と同じ）。
       static float smoothStep( float t );
       // 0〜1 の輪（1 周 = 1）の位置を [0, 1) へ折り返す。何周ずれていても 1 回で計算する。
       static float wrapUnit( float phase );
   };

 置き換える所：lerp 2・clamp 1・clampSigned 2・smoothStep / easeInOut 4・wrapPhase 2。
 名前は easeInOut ではなく smoothStep にそろえる（シェーダーの smoothstep と同じ式だと分かるように）。
 各ファイルで easeInOut を呼んでいる所の「なぜ曲線にするか」のコメントは、呼んでいる所に残す（理由はそこごとに違うため）。

 9. 挙動が変わる所
================================================================================
 ・リロードの音の合図（★1 案A のとき）：弾倉を抜く 21→22、挿す 76→77、槓桿 100→101 ティック目（どれも約 17ms 遅い）。
   リロード全体の長さ（2 秒 = 120 ティック）は変わらない
 ・ZombieChase の乱数で決める待ち時間（★1 案A のとき）：平均で 0.5 ティック長くなる（見て分かる差ではない）
 ・角度（★2 案A のとき）：Zombie・FirstPersonControl で、ちょうど +180° の向きが -180° になる。
   ゾンビが真後ろの相手へ向き直るとき、回る向きが逆になることがある（速さ・着くまでの時間は同じ）
 ・それ以外の値（今の定数のティック数・距離・曲線）は 1 つも変わらない

 11. 懸念点
================================================================================
 ・変えるファイルが多い（約 30）。1 つずつは小さいが、段階ごとに分けてビルドを通し、差分も段階ごとに見せる
 ・AimSway の wrapPhase は今「1 回だけ引く」なので、1 周以上ずれた値が来ると今は [0,1) に収まらない。
   wrapUnit にするとそれも収まるので、挙動が変わるのは今おかしい値が来た時だけ（今の呼び方では来ない）
 ・GameTime.h は多くのファイルが読むので、関数を足すとビルドし直すファイルが多い（1 回だけ）
