--------------------------------------------------------------------------------
 ★ ユーザーに決めてもらうこと（おすすめを先に書く）
--------------------------------------------------------------------------------
 ★1 GameObject にする範囲
     （おすすめ）動く物・使う物は全部 GameObject にする。町（建物・道路・地面）・飛ぶ弾・エフェクトの並びは今のまま
       ・GameObject にする：自キャラ・銃（AK47 として独立した物）・ゾンビ・落ちているガソリン・落ちた弾・車・何度でも拾えるガソリンの置き場
       ・今のまま：建物・地面（数が多く、インスタンシングと間引きで 1 回にまとめて描いている。最適化【A】）、
         BulletList（数百発を詰めて持つ方が速い）、弾痕・砂ぼこり・血しぶき・千切れた部位（数が多く、短い間だけの絵）
     （別案）建物・弾・エフェクトも全部 GameObject にする。Unity には一番近いが、最適化【A】の描き方を作り直すことになり、遅くなる見込み

 ★2 更新の呼び方
     （おすすめ）部品が update を持ち、GameObjectWorld が「段」ごとにまとめて呼ぶ。段の順は GameWorld に書く
       ・段：Input（操作を読む）→ Think（ゾンビの判断）→ Move（動く・当たり）→ Animate（アニメ・骨）→ Late（銃を手に付ける・光・音）
       ・段の中は作った順。部品は自分がどの段で動くかを 1 つ返す（Unity の Update / LateUpdate と Script Execution Order を、番号ではなく名前で決める形）
       ・GameWorld::update は「弾 → world.update( Input ) → … → world.update( Late ) → flush」と段を順に呼ぶだけになる。
         順番がコードに見える、という前回の ★2 の良さは残す
     （別案）前回のまま、GameWorld が forEach< 部品 > で 1 種類ずつ呼ぶ。部品が細かくなると GameWorld のループが 20 本を超える

 ★3 部品どうしの探し方（画像の GetComponent< HoldComponent >()）
     （おすすめ）部品は start()（全部の部品を付け終えた後に 1 回だけ呼ばれる。Unity の Start）で、要る部品を getComponent で探してポインタを覚える。
       要るのに無ければ ASSERT で止める（Unity の RequireComponent の代わり）。毎ティック探さない
       ・名前はこのプロジェクトの書き方に合わせて addComponent< T >( 引数… ) ／ getComponent< T >()（小文字始まり。GameLib と同じ）
     （別案）画像と同じ AddComponent / GetComponent（大文字始まり）。今のコード全体と書き方がずれる

 ★4 銃をどう持つか
     （おすすめ）銃は自キャラとは別の GameObject（"AK47"）にし、自キャラの HoldComponent が「今持っている物」として借りる
       ・AK47 ＝ Model・Gun（連射・弾倉・反動・リロード）・Item（拾える・持てる）・Light（銃に付けたライト）・
         MuzzleFlash（画像の FlipBookFirePlayer）・Sound の部品
       ・持っている間は、自キャラの右手の骨に付いて動く（今の HeldItem と同じ計算を Late の段で）
       ・後で「落とす・拾い直す・2 本目の銃」を足すとき、物の作りを変えずに済む（タルコフの銃が部品の付け替えで成り立つのと同じ向き。1 章）
     （別案）銃は自キャラの部品（GunComponent を自キャラに付ける）。作業は小さいが、銃が自キャラから離れられない

 ★5 途中での部品の付け外し
     （おすすめ）できるようにする。ただし付ける・外すのは flush の中で行う（今の「消えるのは flush の中だけ」と同じ約束）
       ・removeComponent< T >() は印を付けるだけ。外す前に部品の onDestroy() を呼ぶ（名簿から外す・借りているポインタを捨てる）
       ・例：ゾンビが倒れたら Chase・Attack の部品を外す／ライトを外した銃
     （別案）今のまま、作るときに付け終えて途中では変えない

 ★6 物の名前（画像の Register("AK47")）
     （おすすめ）GameObject に名前（std::string）を持たせる。使うのは F6 のエディタに物の一覧（Unity の Hierarchy）を出すのと、デバッグ出力だけ。
       ゲームの判断には今のタグ（GameObjectTag）を使う（文字列の比べ合いで動きを決めない）
       ・名前の文字列は物を作る所（GameWorld の作る関数）にだけ書く
     （別案）名前は持たない（タグだけ）

 ★7 ゾンビの中身をどこまで分けるか
     （おすすめ）今の Zombie が持っている役割ごとのクラスを、ほぼそのまま部品にする（4 章の表）。
       「Zombie」という大きな部品は無くなり、状態（歩く・倒れる・這う・死体）を見て部品どうしをつなぐ ZombieBrainComponent が残る
     （別案）今回は自キャラと銃だけ分け、ゾンビは 1 部品のまま（前回の ★4 のまま）。作業は半分くらいになる

--------------------------------------------------------------------------------
 決まりごと（Claude の判断。確かめてもらう）
--------------------------------------------------------------------------------
 ・部品の種類は今の componentTypeId< T >（RTTI なし）のまま。同じ種類の部品は 1 つの物に 1 つまで
 ・物を持つのは GameObjectWorld だけ。ほかの物や部品は生のポインタを借りる。
   借りた物が消えたかを知りたい部品のために、GameObjectHandle（番号＋世代。消えた物なら get() が nullptr）を足す
   （自キャラが持つ銃、ゾンビが追う相手など、物をまたいで指す所だけで使う）
 ・名簿（CollisionWorld・HitWorld）へ載せる・外すのは、今と同じく IWorldMember を実装した部品が自分で行う
 ・位置と向きは TransformComponent（位置・Y の向き・行列）に 1 つにまとめ、ほかの部品は読む・書く。
   親子（Unity の Transform の親子）は作らない。銃が手に付くのは Hold が毎ティック位置を書く形（★4）
 ・描くのは今の順番（drawStatic → デカール → drawFirstPerson → drawCharacters → 影）を変えない。
   描く部品は IDrawable のような窓口ではなく、Model 系の部品を forEach で描く（描く順・TAA の動きの種類・影の有無を今のまま保つため）
 ・Release でも同じ作り。部品を探すのは start の 1 回だけなので、毎ティックの重さは今とほぼ変わらない見込み（5 章で前後を測る）

 1. タルコフでは
================================================================================
 調べて分かったこと
 ・タルコフは Unity で作られている（前回の ComponentSystem_Plan.txt 1 章）。Unity のふつうの作りは GameObject に Component を付ける形
 ・タルコフの銃は、本体に部品（照準器・グリップ・ストック・マズル・ハンドガード・ライト・弾倉…）を付け替えて組み立てるアイテム。
   付けられる部品はレールの種類などで決まる（Weapon mods）
 調べても分からなかったこと（推測で埋めない）
 ・タルコフのコードの中で、銃・自キャラ・敵をどの Component に分けているか（公開されていない）
 合わせる所
 ・銃を自キャラから独立した物にし、部品を付けて組み立てる（★4）。将来、ライト・照準器を部品として付け替えられる向き
 あえて変える所
 ・Unity の Update は全部の部品へ順番の決まらないまま呼ぶが、ここでは段（★2）で順を決める（自キャラ → ゾンビ → 銃を手に付ける、の順が大事なため）

 2. 今の作りと、画像の形との差
================================================================================
 今
 ・GameObject＋Component の土台はある（GameSrc/World/）。ただし部品は Zombie・Pickup の 2 つで、どちらも大きなクラスを 1 部品として載せているだけ
 ・自キャラ（PlayerCharacter 597 行）は銃・弾倉・反動・リロード・移動・当たり・体力・アニメを 1 つのクラスで持つ
 ・車・何度でも拾える置き場は GameWorld が直接持つ
 ・部品に update は無く、GameWorld が forEach で呼ぶ。部品どうしで探し合う仕組み（GetComponent して使う）は使われていない
 画像の形との差
  1. 物に細かい部品を何個も付けて組み立てる（Model・Gun・Rigidbody・Item・Light・Collider・Sound…）→ 今は 1 物 1 部品
  2. 部品が隣の部品を探して使う（Fire の中で Hold を探す）→ 今は無い
  3. 名前を付けて登録する（Register("AK47")）→ 今はタグだけ
  4. 銃が自キャラとは別の物 → 今は自キャラの中

 3. 新しい作りの全体像
================================================================================
  GameObjectWorld（今のものを広げる）
    ├ create( タグ, 名前 )            … 物を作る（まだ動かない）。部品を addComponent< T >( 引数… ) で付ける
    ├ spawn( 物 )                     … 全部の部品の start を呼び、名簿へ載せ、動かし始める
    ├ update( 段 )                    … その段の部品の update を作った順に呼ぶ（★2）
    ├ destroyLater / removeComponentLater → flush で onDestroy を呼んで外す・消す（★5）
    └ forEach / find / count / countTagged / oldestTagged（今のまま）

  Component（今のものを広げる）
    ├ start()           … 全部の部品が付いた後に 1 回。隣の部品を getComponent で探して覚える
    ├ update()          … 自分の段で毎ティック
    ├ updatePhase()     … どの段で動くか（動かない部品は None）
    └ onDestroy()       … 外す・消す前に 1 回

  例：銃
    GameObject* gun = mObjects.create( GameObjectTag::Weapon, "AK47" );
    gun->addComponent< TransformComponent >( position, yaw );
    gun->addComponent< StaticModelComponent >( mWeaponData );
    gun->addComponent< GunComponent >( gunSpec );          // 連射・弾倉・反動・リロード
    gun->addComponent< ItemComponent >( ItemId::Ak47 );
    gun->addComponent< LightComponent >( flashlightSpec );
    gun->addComponent< MuzzleFlashComponent >();
    gun->addComponent< SoundComponent >( SoundId::Gunshot );
    mObjects.spawn( gun );

  例：自キャラが撃つ（画像の PlayerComponent::Fire）
    void PlayerComponent::fire(){
        GunComponent* gun = mHold->heldGun();   // mHold は start で getComponent< HoldComponent >() して覚えた物
        if ( gun ){ gun->pullTrigger(); }
    }

 4. 部品の一覧（今のクラスがどこへ行くか）
================================================================================
 共通
  TransformComponent            位置・向き（今は各クラスが mPosition・mAngleY を持っている）
  SkinnedModelComponent         SkinnedMeshInstance＋Animator（骨のある見た目）
  StaticModelComponent          動かない形の見た目（銃・缶・弾・車）
  CharacterColliderComponent    CharacterMover＋BodyFootprint（ICollisionBody。壁に沿って滑る移動）
  BoxColliderComponent          BoxCollider（拾える物・車の箱）
  HitboxComponent               HitboxSet（IHittable。部位ごとの命中）
  SoundComponent                鳴らす音の番号と、鳴らす位置（今は GameScene の係が出来事を読んで鳴らしている → 8 章）

 自キャラ "Player"
  PlayerComponent               PlayerCommand を読み、移動・撃つ・リロード・ライトを隣の部品へ頼む（PlayerCharacter::update の入口）
  FirstPersonBodyComponent      FirstPersonBody（頭を潰す・背骨のピッチ・mShownPose）
  HoldComponent                 今持っている物（GameObjectHandle）・WeaponStance（しまう/持つ/ADS）・AimSway・手に付ける計算
  PlayerHealthComponent         PlayerHealth（IDamageable。無敵の切り替え）
  FootstepComponent             Gait と歩きの位相（足音の係が読む）

 銃 "AK47"
  GunComponent                  FireControl・Magazine・WeaponRecoil・WeaponReload（＋弾倉の見た目 HeldMagazine）
  ItemComponent                 アイテムの種類（ItemCatalog）。持てる・拾える
  LightComponent                銃のライト（今の isFlashlightOn と、ライトの一覧へ出す LightSource）
  MuzzleFlashComponent          MuzzleFlash（Flipbook の炎と銃口の点光源）

 ゾンビ "Zombie"（★7 おすすめの場合）
  ZombieBrainComponent          状態（歩く・よろけ・倒れる・這う・死体）を持ち、下の部品をつなぐ（今の Zombie::update の中身）
  ZombieChaseComponent          ZombieChase・ZombiePath・ZombieLocomotion・ZombieSway・ZombieStride（追う・うろつく・道探し）
  ZombieAttackComponent         ZombieAttack・ZombieAttackReach
  ZombieHealthComponent         ZombieHealth・ZombieDamageReaction・ZombieFlinch・ZombieStagger（IDamageable）
  ZombieDismemberComponent      ZombieDismemberment・ZombieCrawler（部位欠損と這う体）
  ZombieRootMotionComponent     ZombieRootMotionSpan・ZombieAnimationSet
  ZombieCorpseComponent         ZombieCorpse（倒れ終わってから沈んで消える）

 落ちている物 "Fuel" / "AmmoDrop"
  Transform・StaticModel・BoxCollider・ItemComponent・PickupComponent（IInteractable。拾われたら消える）

 車 "EscapeCar"
  Transform・StaticModel・（車の壁の当たり）・FuelTankComponent（IInteractable。ガソリンを入れる・isEscapeReady）
 何度でも拾える置き場 "FuelStation"
  Transform・BoxCollider・ItemSourceComponent（IInteractable）

 5. 移す順番（段ごとに 3 構成のビルドと、遊んでの確認で止める）
================================================================================
  0. 始める前に、今の作業ツリー（変更が多数ある）をコミットしておく（戻れる所を作る）。F6 の Perf で「前」を測る
  1. 土台を広げる：start・update（段）・onDestroy・removeComponentLater・名前・GameObjectHandle・TransformComponent。
     今の Zombie・Pickup は段 None のまま動かす（遊びは何も変わらない）
  2. 落ちている物・車・置き場を部品の組み立てにする（小さい物から。拾う・入れるの確認）

  6. F6 の Perf で「後」を測り、技術まとめ 8 章に前後を書く

 7. 懸念点
================================================================================
 ・作業がとても大きい（自キャラ 600 行・ゾンビ 500 行と、それを読む GameScene・音・デバッグ表示）。段ごとに止めて遊んで確かめる
 ・今は遊びが変わらない作業。良さが出るのは、物の種類・銃・敵を足すときと、ポートフォリオで「部品を組み立てて物を作る」と見せられること
 ・部品が隣の部品を指すので、付ける順と start の順に気を付ける（start は全部付け終えてから呼ぶので、付ける順には依らない）
 ・段の順を間違えると 1 ティック遅れの揺れが出る（例：銃を手に付けるのを自キャラのアニメより前にすると、銃が 1 ティック遅れる）。
   今の PlayerCharacter::update の中の順を、段の表に書き写してから移す
 ・作業中の物が多い（UI の文字・最適化【A】のカリングが画面確認待ち）。先にそれらを確かめてから始める方が、壊れた所の切り分けが楽
