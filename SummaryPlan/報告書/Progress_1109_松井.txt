①ゲームの作り直し(11/04～11/09)
・なぜ作り直したか(似たゲーム(タルコフ・RE:2・Left 4 Dead 2・Project Zomboid)と比べて出た原因)

	-緊張が平らで、山場が無い
	-1 か月、グラフィック・最適化が中心で、遊んで確かめる作業が後回しだった
・芯の一言：「持ち込んだ物を失うかもしれない町で、もう一つ漁るか、もう逃げるかを迷う」
・グラフィック・最適化の新しい段階は、作り直しが遊べるまで止めると決めた
・段階

	-R2 出撃と帰還(11/05)：拠点・倉庫・5 日間・スコア・保存
	-R3 漁れる場所(11/05)：ゴミ箱・木箱を開けて中を見る(開けるのに 1.0～2.5 秒。動く・撃つと取りやめ)

⑤計測と最適化
・GPU が重いと読み違えた(10/27)
	-VSync ありで測ると GPU 8.2ms → GPU が重いと読んで、描く順番(Early-Z)と背面カリングを入れた
	-物ごとに印を打つと、97% が「ゾンビ」の区間に入っていた。その区間と画面の表示待ちの相関が 0.996 → 待ち時間だった
	-VSync を切って測り直すと、GPU 全体は 0.31ms。前後の比べ方を決めずに入れたので、効果は数字で言えなかった
	-学んだこと：数字で決める前に、その数字が何を測っているかを確かめる
	-この後の最適化は「回数を数える印を足す → 前を録る → 入れる → 後を録る」の順にした
・テクスチャを DDS(BC7 / BC5)に圧縮(10/27)：ゲームのロード 1.3 秒 → 0.64 秒、テクスチャの展開 530ms → 22ms
・最適化【S】(10/31)：地面を 4m のますに分けた(1 回に調べる部品 522 → 約 5)・同じ設定は送らない(PS の定数 −85%)・頂点数を減らした
・最適化【A】(11/01～11/02)：カリング・遠い月の影を間引く・建物をインスタンシング
	-描く回数 474 → 62(−87%)、CPU の描画 0.37ms → 0.16ms(−57%)、GPU は −5% だけ
	-GPU の 8 割は画面全体の処理(ライティング・TAA など)なので、描く回数を減らしても GPU はあまり縮まない
・最適化【B】(11/03)：建物の三角形を BVH・動く体を 4m のますで引く・骨の行列を 1 フレーム 1 回・遠いゾンビのアニメを間引く
	-移動の判定で比べる体 1,178 → 6、ゾンビの更新 0.49ms → 0.22ms(−56%)
	-BVH は総当たりと答えが一致するのを単体テストで確かめた(線分 1 本 44.8µs → 0.8µs)
・最適化【C】(11/03)：道探しの順番待ち・簡易 PVS(見えうる建物を読み込み時に表にする)・LOD(車と缶だけ。建物は窓が崩れた)
	-描いた三角形 25 万 → 10 万(−58%)、GPU は −3%

⑥設計の整理
・ComponentSystem の作り直し(11/01～11/02)
	-Unity と同じ GameObject＋Component の形。作る → 部品を付ける → 置く。awake の後に start なので、付ける順は自由
	-必ず要る部品は start で受け取り、外せない印を付ける。世界に 1 つの物(NavMesh など)は共有の棚から引く
	-ZombieBrain は判断を State・Chase・Attack・Health・Crawl・Corpse の部品へ分け、524 → 141 行にした
・どこに置くかの決まり(3 層)
	-Component：1 つの物で済む仕事(ゾンビの攻撃・体力)
	-ポーズの段の鎖：1 体の骨の書き換え(一人称の体の 6 段)
	-係：多くの物・カメラ・音・UI
・大きいクラスを係へ分けた(挙動は変えず、置き場所だけ移した)
	-Zombie 988 → 549 行(10/28)
	-GameWorld から 描画・組み立て・エフェクト・命中・使う物・町・ゾンビの群れ を分けた(11/02・11/09)
	-GameScene.cpp 1,214 → 525 行(11/09。描画・一時停止とカバンの切り替え・カバンと漁りの操作・HUD・ロード・戦闘の音)
	-一人称の体を 6 つの段に(腕・背骨・目・銃の位置・揺れ・はみ出し)
	-分ける目安は「説明が『～と～』になる」「直す理由が 2 つ以上ある」
