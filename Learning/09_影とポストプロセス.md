# 09 影とポストプロセス

08 章の 2 つの部品（テクスチャへ描く・全画面を 1 回描く）の応用編。
技法の数は多いが、どれも「何を描いて、何を読んで、どんな式を掛けるか」の違い。

全部を自分で書けるようになる必要は無い。**書けるようにする物**と**読んで説明できればよい物**を分ける。

| 技法 | 目標 | 理由 |
|---|---|---|
| シャドウマップ・PCF | 書ける | 影の基本。どの会社でも聞かれる |
| ブルーム・トーンマップ | 書ける | 全画面のパスの練習に一番良い |
| CSM（月の影） | 説明できる | シャドウマップを 3 枚に増やした物 |
| SSAO | 説明できる・余裕があれば書く | 深度と法線から作る、という考え方が大事 |
| 霧・FXAA | 説明できる | 式が短い |
| TAA・SSR・Hi-Z | 流れを説明できる | 難しい。式の細部は記録（計画書）を読めば足りる |

## この章でできるようになること

- シャドウマップの 2 回の描画（光から・目から）を自分で書ける
- 影のにきび（シャドウアクネ）とその対策を説明できる
- ブルームを自分で書ける
- 自分のゲームのポストプロセスの順番と、その順番の理由を説明できる

## シャドウマップの考え方

```
1 回目：光の位置にカメラを置いて、深度だけを描く  →  影のマップ（光から一番近い面までの距離）
2 回目：普通に目から描く。画素ごとに、
        その点を「光から見た座標」へ変換し、
        影のマップに入っている深度と、自分の深度を比べる
        自分の方が遠い  →  光との間に何かある  →  影
```

## 読むときの問い

### シャドウマップ

1. `ShadowMap::begin` は `gm.setRenderTargets( nullptr, 0, mDepth )` で、色の描画先を 0 枚にしている。なぜ色が要らないか。`StaticMeshShadow.hlsl` のピクセルシェーダが何も返さないのに、何が書かれるのか
2. `spotShadowProjectionView` は、懐中電灯の「外側の角度」から画角を作っている。影のマップに入れる範囲を、ライトの照らす範囲に合わせる理由は
3. `shadowVisibility` の中で、ワールドの位置 `p` を `gShadowMatrices` で変換した後、`ndc.x * 0.5 + 0.5` と `0.5 - ndc.y * 0.5` で uv にしている。なぜ x と y で式が違うか
4. `clip.w <= 0.0` と、uv が 0〜1 の外のときは、影なし（1）を返している。それぞれどういう場所か
5. 影の「にきび」（シャドウアクネ：光の当たっている面に縞模様の影が出る）は、なぜ起きるか。このコードはどう防いでいるか（`shadowVisibility` の 3 行目）
6. `compareShadowMap` は `SampleCmpLevelZero` と比較サンプラ（`gShadowSampler`）を使っている。普通の `Sample` で深度を読んで自分で比べるのと、何が違うか
7. `shadowVisibility` は 3 × 3 = 9 回読んで平均している（PCF）。なぜ要るか
8. 影のマップは `SceneRenderer::render` の中で G-Buffer より**前**に描いている。後ではだめか

<details><summary>答え</summary>

1. 欲しいのは深度だけ。深度は、ピクセルシェーダが何も返さなくても、ラスタライザが出した深度が深度テストを通れば DSV へ書かれる。色の描画先が無ければ、ピクセルシェーダの仕事はほぼ無く、速い
2. 影のマップの画素は限られている（解像度）。照らさない所まで入れると、照らす所に使える画素が減り、影が粗くなる
3. クリップ空間の y は上が正、テクスチャの v は下が正。向きが逆なので y だけ反転する
4. `w <= 0`：光の後ろ側（射影すると前後が裏返って、でたらめな所を読んでしまう）。uv の外：影のマップに入っていない場所（届く距離の外・角度の外）。どちらも「影の情報が無い」ので影を付けない。光が届かないこと自体は、スポットの角度と距離の減衰が 0 にする
5. 影のマップは画素の粗さでしか深度を持っていない。斜めの面では、1 画素の中で本当の深度が変わるのに、マップには 1 つの値しか無い。そのため面の半分が「自分自身より奥」と判定されて縞になる。このコードは、読む位置を法線の向きと光の方へ、影のマップの画素の大きさに比例して少しずらしている（法線オフセット）。深度に一定の数を足す（バイアス）よりも、浮いた影（ピーターパン）が出にくい
6. 比較サンプラは、周りの 4 画素それぞれで「比べた結果（0 か 1）」を出してから、その結果を線形に混ぜて返す。自分で `Sample` すると、4 画素の**深度を**混ぜてから比べることになり、意味の無い値と比べてしまう。影の縁が 1 回の読み込みで少しなめらかになる
7. 影のマップの 1 画素が、画面では何画素にもなるので、縁がギザギザの階段になる。少しずつずらして何回も比べ、平均することで縁をぼかす
8. だめ。ライティングのパスで影のマップを読むので、その前にできていないといけない。G-Buffer より前である必要は無いが、ライティングより前は必須

</details>

### CSM と影の重さ

1. 月（平行光）の影を、1 枚ではなく 3 枚（カスケード）に分けているのはなぜか
2. `cascadedShadowVisibility` は、枚の境目で「次の枚と混ぜる」処理をしている。混ぜないとどう見えるか
3. 遠い枚を毎フレーム描き直していない（`CascadeRefresh`）。なぜそれで済むか。何が犠牲になるか
4. 影のマップへ描くときも、物は全部もう一度描く（頂点シェーダが走る）。影 4 枚でドローコールは何倍になり得るか。技術まとめ 8 章⑭で、何をして減らしたか

<details><summary>答え</summary>

1. 1 枚で遠くまで覆うと、近くの影に使える画素が足りず、足元の影がぼやける。近く用（狭い範囲・細かい）・中間・遠く用（広い範囲・粗い）に分ければ、画面で大きく見える近くの影だけ細かくできる
2. 境目で影の細かさが急に変わるので、地面に線が見える
3. 遠くの影は画面で小さく、少し古くても気付きにくい。月は動かないので、変わるのはカメラと動く物だけ。犠牲は、遠くの動く物の影が数フレーム遅れること
4. 最大で 5 倍（目からの 1 回＋影 4 枚）。視錐台カリングを光の側でもやる・小さい物を影から外す・遠い枚を間引く・インスタンシング

</details>

### ポストプロセス

1. `Bloom.cpp` と 3 つのシェーダを読む。ブルームは「明るい所を取り出す → 半分・その半分…と縮めながらぼかす → 拡大しながら足し戻す」。なぜ元の大きさのまま大きくぼかさないのか
2. ブルームはトーンマップの**前**（リニア・HDR）で足している（`Present.hlsl` の `PSMain`）。後ではだめな理由は
3. SSAO は G-Buffer の法線と深度だけから「物の隙間の暗がり」を作る（`Ssao.hlsl` の `occlusionAt`）。大まかに、何を調べているか。なぜ半分の大きさで作っているか
4. SSAO の結果は、ライティングの「環境光にだけ」掛けている（`DeferredLighting.hlsl` のコメント）。懐中電灯の光には掛けないのはなぜか
5. FXAA は「画面の色の輝度」から輪郭を探してぼかす。MSAA と比べた良い所・悪い所は。`Present.hlsl` が a に輝度を入れているのは何のためか
6. TAA は、毎フレーム射影行列を 1 画素より細かくずらし（`TemporalJitter`）、前のフレームの絵と混ぜる。なぜそれでギザギザが消えるか。動いている物で起きる問題（残像）を、`Taa.hlsl` の `clipToBox` はどう抑えているか
7. `SceneRenderer::render` の順番「ライティング → SSR → 霧 → TAA → 半透明の板 → ブルーム・トーンマップ → FXAA」について、「霧は半透明の板より前」「TAA は半透明の板より前」の理由をコメントから読み取る
8. `Profiling::gpuMark( "SSAO" )` のような印で、GPU の時間を段ごとに測っている（`GpuTimer.cpp`）。CPU の時計（`std::chrono`）で `drawFullScreen` の前後を測っても、GPU の時間が分からないのはなぜか

<details><summary>答え</summary>

1. 大きくぼかすには、1 画素につき周りの何百画素も読まないといけない。半分に縮めた絵で小さくぼかせば、元の大きさでは 2 倍の広さをぼかしたのと同じ。縮めるほど安く、広いぼかしができる
2. ブルームは「光の量があふれてにじむ」現象なので、光の量（リニア）のまま足す。トーンマップの後は 0〜1 に収まっているので、「どこが本当に明るいか」がもう分からない
3. 画素ごとに、その点の周り（法線の側の半球）に何点か取り、「その点が、深度バッファの面より奥に埋まっているか」を数える。埋まっている点が多いほど、周りに壁がある（隅・隙間）ので暗くする。ぼんやりした暗がりで細かさは要らないので、半分の大きさ（画素数 1/4）で作って拡大する
4. AO は「周りから来るぼんやりした光（環境光）が、隙間には届きにくい」ことの近似。向きのはっきりした光が届くかどうかは、影のマップが決める。直接の光にも掛けると、照らされた隅まで暗くなって不自然
5. 良い所：全画面 1 回で済み、ディファードでも使える・安い。悪い所：できた絵をぼかすだけなので、細い線や文字が少しにじむ・動くとちらつく所は消えない。輝度を a に入れておくのは、FXAA が近くの輝度を何度も読むので、1 回だけ計算して済ませるため
6. 毎フレーム少し違う位置を描いて、何フレーム分かを平均すれば、1 画素の中を何点も調べたのと同じになる（時間方向のスーパーサンプリング）。動く物では、前のフレームの同じ画素は別の物の色なので、混ぜると残像になる。`clipToBox` は、前の色を「今のフレームの周りの画素の色の範囲」の中へ押し込める。範囲から大きく外れた古い色は捨てられる
7. 霧：半透明の板は自分のシェーダで同じ霧を掛けているので、後から全画面の霧を掛けると二重になる。TAA：板は「どう動いたか」が取れないので、TAA に通すとマズルフラッシュに光の尾が出る
8. `Draw` は「GPU への命令を積む」だけで、すぐ戻る。GPU が実際に実行するのは後。GPU の時間は、GPU 側の時刻を問い合わせる仕組み（`ID3D11Query` のタイムスタンプ）で測り、結果は何フレームか後に読む

</details>
