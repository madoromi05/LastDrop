# 課題：ミニレンダラ（ゼロから書く小さな D3D11 プログラム）

この教材の柱。ゲームとは別の新しいプロジェクトに、**AI を使わず**、D3D11 のプログラムを 1 段ずつ書いていく。
終わったとき、「ウィンドウから影とディファードまで、自分で書いた」と言える物が手元に残る。

## 決まり

- ゲームのリポジトリの**外**に、新しいソリューションを作る（例：`C:\Users\mador\source\repos\MiniRenderer`）。Visual Studio の「空のプロジェクト」から。Windows デスクトップウィザードのひな形は使わない
- GameLib は使わない。D3D11 の API を直接呼ぶ
- AI にコードを書かせない（README の 3 つの約束）
- 段ごとに git でコミットする。前の段へ戻れるように
- 自分のゲームのコードは、横に開いて見てよい（各段の「詰まったら」に場所がある）。貼り付けはしない
- 使ってよい物：
  - `Microsoft::WRL::ComPtr`（`<wrl/client.h>`）。COM のスマートポインタ。GameLib は手で `Release` しているが、こちらが今の普通の書き方
  - DirectXMath（`<DirectXMath.h>`）。行列とベクトル。行ベクトル・左手系の決まりは 04 章の表を見る
  - 標準ライブラリ
- 1 つの `main.cpp` に全部書いて始めてよい。M4 あたりで長くなったら、自分で考えてクラスに分ける（これも課題のうち。分けた理由を言えること）
- 必ず Debug ビルドでデバッグレイヤーを付ける（`D3D11_CREATE_DEVICE_DEBUG`）。出力ウィンドウの `D3D11 WARNING` を 0 件に保つ

## M0：ウィンドウ

**目標**：800 × 600 のウィンドウが出る。×ボタンと Esc で終わる。

**やること**
- `wWinMain` を書く
- `WNDCLASSEXW` を埋めて `RegisterClassExW`
- `AdjustWindowRect` で、描く所（クライアント領域）がちょうど 800 × 600 になる外枠の大きさを求めてから `CreateWindowExW`
- `ShowWindow`
- `PeekMessageW` のループ。`WM_QUIT` で抜ける
- ウィンドウプロシージャ：`WM_DESTROY` で `PostQuitMessage( 0 )`、`WM_KEYDOWN` の `VK_ESCAPE` で `DestroyWindow`、それ以外は `DefWindowProcW`

**確かめ方**：ウィンドウが出る。×で閉じると、プロセスも終わる（タスクマネージャーに残らない）。

**詰まったら**：`GameLib/src/WindowCreator/WindowCreator.cpp` の `_tWinMain`・`MyRegisterClass`・`InitInstance`・`WndProc`

**よくある失敗**
- `DefWindowProcW` を呼び忘れて、ウィンドウが動かせない・出ない
- プロジェクトのサブシステムが「コンソール」のままで、`wWinMain` が見つからないと言われる（リンカー → システム → サブシステムを Windows に）

## M1：画面を塗る

**目標**：ウィンドウが青（好きな色）で塗られる。時間で色が変わるとなお良い。

**やること**
- `d3d11.lib`・`dxgi.lib`・`d3dcompiler.lib` をリンクする（`#pragma comment( lib, "d3d11.lib" )` でよい）
- `DXGI_SWAP_CHAIN_DESC` を埋める
- `D3D11CreateDeviceAndSwapChain`（Debug ではデバッグレイヤーのフラグを付ける）
- スワップチェーンの `GetBuffer` → `CreateRenderTargetView`
- 毎フレーム：`OMSetRenderTargets` → `ClearRenderTargetView` → `Present( 1, 0 )`

**確かめ方**：塗られる。出力ウィンドウに `D3D11 ERROR`・`WARNING` が無い。終了時に「live object」の報告が出ない。

**詰まったら**：`GameLib/src/Graphics/ManagerImpl.h` のコンストラクタの先頭〜`createRTVandDSV`・`beginDraw`・`endDraw`

**発展**
- ウィンドウの大きさを変えられるようにし（`WS_OVERLAPPEDWINDOW`）、`WM_SIZE` で `ResizeBuffers` して RTV を作り直す。作り直す前に何を手放さないといけないか（`fitBackBufferToWindow`）
- スワップチェーンを、新しい作り方（`DXGI_SWAP_EFFECT_FLIP_DISCARD`・`BufferCount = 2`）に変える。何が違うかを調べて 3 行で書く

## M2：三角形

**目標**：色の付いた三角形が 1 枚出る（3 つの頂点が赤・緑・青で、間がなめらかに混ざる）。

**やること**
- 頂点の構造体（位置 `float[ 3 ]`・色 `float[ 4 ]`）
- HLSL を 1 つのファイルに書く（`shader.hlsl`。`VSMain` と `PSMain`）。位置はそのまま `SV_Position` へ（w は 1）、色はそのまま渡す
- `D3DCompileFromFile` を 2 回（`vs_5_0`・`ps_5_0`）。失敗したら、エラーの文章を `OutputDebugStringA` で出す
- `CreateVertexShader`・`CreatePixelShader`
- `D3D11_INPUT_ELEMENT_DESC` を 2 つ書いて `CreateInputLayout`
- 頂点バッファを `D3D11_USAGE_IMMUTABLE` で、初期データを渡して作る
- ビューポートを付ける（`RSSetViewports`）
- 毎フレーム：`IASetInputLayout`・`IASetVertexBuffers`・`IASetPrimitiveTopology`・`VSSetShader`・`PSSetShader`・`Draw( 3, 0 )`

**確かめ方**：三角形が出る。頂点の位置を変えると形が変わる。

**詰まったら**：03 章の「絵が出ないときに疑う順」。`ManagerImpl.h` のシェーダと入力レイアウトの所、`VertexBufferImpl.h`、`ShaderImpl.h` の `compile`

**よくある失敗**
- 三角形が裏向きで捨てられている（D3D11 の既定は「時計回りが表」。自分のゲームは逆なので、ゲームの頂点の順を真似ると出ない）
- ビューポートを付けていない
- HLSL のファイルが実行時の作業フォルダに無くて、コンパイルに失敗している（エラーを出していないと気付かない）
- 入力レイアウトのオフセットが構造体と合っていない（`offsetof` を使う）

## M3：回る三角形

**目標**：三角形が、画面の中心のまわりを回る。

**やること**
- HLSL に `cbuffer` を足す（`float4x4 gWorld;`）。頂点シェーダで位置に掛ける
- C++ 側に同じ並びの構造体（`XMFLOAT4X4`）
- 定数バッファを `D3D11_USAGE_DYNAMIC`・`D3D11_CPU_ACCESS_WRITE` で作る
- 毎フレーム：経過時間から `XMMatrixRotationZ` → `Map`（`WRITE_DISCARD`）→ 書く → `Unmap` → `VSSetConstantBuffers`

**確かめ方**：回る。ウィンドウが横長なので、回ると三角形が伸び縮みして見える（次の M4 で射影を入れると直る。なぜ伸び縮みするかを先に考える）。

**詰まったら**：`ConstantBufferImpl.h`、`ManagerImpl.h` の `sendMatrices`・`flushConstantBuffers`

**よくある失敗**
- 行列を転置せずに渡して、回り方がおかしい・消える（DirectXMath は行ベクトル。HLSL の既定の並びと合わせるには `XMMatrixTranspose` してから入れるか、HLSL 側で `mul( 位置, 行列 )` の順と `row_major` を揃える。どちらかに決めて、理由を書く）
- 定数バッファの大きさが 16 の倍数でなくて作れない

## M4：カメラと立方体

**目標**：6 面で色の違う立方体が回る。奥の面が手前の面に隠れる。

**やること**
- 立方体の頂点（面ごとに色を変えるので 24 頂点）とインデックス（36 個・16 ビット）
- インデックスバッファを作り、`IASetIndexBuffer`・`DrawIndexed`
- 深度のテクスチャ（`D32_FLOAT`）と DSV を作り、`OMSetRenderTargets` に付ける。毎フレーム `ClearDepthStencilView`
- 定数バッファを「ワールド・ビュー・射影」の 3 つ（か、掛けた 1 つ）にする。`XMMatrixLookAtLH`・`XMMatrixPerspectiveFovLH`
- キーでカメラを動かす（発展。`GetAsyncKeyState` でよい）

**確かめ方**：正しい立方体に見える。深度を付け忘れると、後から描いた面が手前に出ておかしく見える（わざと外して見ておく）。

**詰まったら**：`ManagerImpl.h` の `createRTVandDSV`（深度）・`setIndexBuffer`・`drawIndexed`、`Matrix34.cpp` の `setViewTransform`、`Matrix44.cpp` の `setPerspectiveTransform`

**ここでクラスに分ける**：`main.cpp` が 400 行を超えてくる。何をどう分けるかを自分で決める。
分けた後、「このクラスの責任は何か」を 1 文で言えるか（「〜と〜」になったら分け足りない）。自分の規約 `C:\AIResorce\GameDev\設計思想.md` の物差しを、自分の手で使う最初の機会。

## M5：テクスチャと半透明

**目標**：立方体に市松模様が貼られる。その手前に、半透明の四角が浮かぶ。

**やること**
- 頂点に UV を足す（入力レイアウトも）
- 市松模様のテクスチャを**コードで**作る（64 × 64 の `uint32_t` の配列を自分で埋めて `CreateTexture2D` に初期データで渡す。画像ファイルの読み込みは今は要らない）
- `CreateShaderResourceView`、`CreateSamplerState`、`PSSetShaderResources`、`PSSetSamplers`
- ピクセルシェーダで `gTexture.Sample( gSampler, uv )`
- ブレンドステートを 2 つ（不透明・半透明）、深度ステンシルステートを 2 つ（書く・書かない）作る
- 不透明な立方体 → 半透明の四角、の順に描く

**確かめ方**：模様が貼られる。サンプラを点と線形で切り替えると、近づいたときの見え方が変わる。四角の向こうに立方体が透けて見える。

**詰まったら**：`ManagerImpl.h` のステートを作っている所・`apply〜State`、`TextureImpl.h`

**発展**：ミップマップを付ける（`D3D11_RESOURCE_MISC_GENERATE_MIPS` と `GenerateMips`）。遠くの模様のちらつきがどう変わるか。画像ファイルを読むなら DirectXTK の `WICTextureLoader`・`DDSTextureLoader` を使ってよい。

## M6：ライティング

**目標**：立方体（と、できれば球と床）に、点光源 1 つの光が当たる。光源を動かすと明るい面が変わり、つやのハイライトが動く。

**やること**
- 頂点に法線を足す
- 頂点シェーダ：位置と法線をワールドへ変換して、ピクセルシェーダへ渡す（法線は 04 章の逆行列の転置。まず回転だけなら 3×3 でよい）
- ピクセルシェーダ用の定数バッファ（光の位置・光の色・目の位置）
- ピクセルシェーダ：`normalize` し直した法線で、環境光＋ランバート＋ブリン・フォンを書く。距離の 2 乗で弱くする

**確かめ方**：光源の位置に小さな立方体を描いて、それを動かす。光源に向いた面が明るく、裏は環境光だけになる。

**詰まったら**：`PixelLightingVsHlsl.h`・`PixelLightingPsHlsl.h`、`Resource/Shader/Lighting.hlsli` の `lightSurface`

**よくある失敗**
- 法線を補間した後に `normalize` していない
- 光の向きを「光 → 面」で計算していて、内積が負になり真っ暗
- ピクセルシェーダの定数バッファを `VSSetConstantBuffers` にだけ付けている（段ごとに別）

## M7：テクスチャへ描いて、全画面で加工する

**目標**：M6 の絵が、白黒（か、色を反転・モザイクなど）になって画面に出る。キーで元の絵と切り替えられる。

**やること**
- 画面と同じ大きさのテクスチャを `D3D11_BIND_RENDER_TARGET | D3D11_BIND_SHADER_RESOURCE` で作り、RTV と SRV を作る
- 1 パス目：描画先をそのテクスチャ（と深度）にして、M6 のシーンを描く
- 2 パス目：描画先をバックバッファに戻し、**頂点バッファ無し**で全画面の三角形を描く。頂点シェーダは `SV_VertexID` から位置と UV を作る。ピクセルシェーダは 1 パス目のテクスチャを読んで加工する
- 2 パス目の前に、深度テストを切る
- 次のフレームの 1 パス目の前に、テクスチャを SRV から外す（`PSSetShaderResources` に nullptr）。外さないとデバッグレイヤーが何と言うかを見ておく

**確かめ方**：加工された絵が出る。RenderDoc で、ドローコールが「シーンの分」と「頂点 3 つの 1 回」に分かれているのを見る。

**詰まったら**：`RenderTargetImpl.h`、`ManagerImpl.h` の `setRenderTargets`・`drawFullScreen`、`Resource/Shader/Common.hlsli` の `fullScreenVertex`

**これができれば**：ブルーム（課題 09-3）・トーンマップ・FXAA は、全部この形の繰り返し。

## M8：影

**目標**：床の上の立方体が、スポットライト（か平行光）の影を床に落とす。

**やること**
- 影のマップ用の深度テクスチャ（1024 × 1024）。`R32_TYPELESS` で作り、DSV は `D32_FLOAT`、SRV は `R32_FLOAT`
- 光から見たビュー行列と射影行列を作る
- 1 パス目：描画先を「色なし・影のマップの DSV だけ」にし、ビューポートを 1024 × 1024 にして、光の行列でシーンを描く（ピクセルシェーダは無し＝nullptr でよい）
- 2 パス目：普通に描く。ピクセルシェーダで、ワールドの位置を光の行列で変換 → w で割る → uv にする → 影のマップの深度と比べる
- まず普通の `Sample` と自分の比較で書く。にきびが出るのを見る。バイアスを足す
- 比較サンプラ（`D3D11_FILTER_COMPARISON_MIN_MAG_LINEAR_MIP_POINT`・`D3D11_COMPARISON_LESS_EQUAL`）と `SampleCmpLevelZero` に書き換える
- 3 × 3 の PCF にする

**確かめ方**：影が落ちる。立方体を動かすと影も動く。影のマップそのものを画面の隅に表示して、光から見た絵になっているか見る（M7 の全画面のパスの応用）。

**詰まったら**：`GameSrc/src/Render/Shadow/ShadowMap.cpp`、`Resource/Shader/LightList.hlsli` の `shadowVisibility`、`DepthTargetImpl.h`、`ManagerImpl.h` の `shadowDesc`

**よくある失敗**
- uv の y を反転していない（影が上下逆に落ちる）
- 影のマップを SRV に付けたまま、次のフレームで DSV に付けようとしている
- ビューポートを戻していない（2 パス目が左上に小さく描かれる）

## M9：G-Buffer とディファード

**目標**：M6 と同じ見た目の絵を、ディファードで出す。光を 8 個に増やしても、同じ仕組みで動く。キーで G-Buffer の中身（色・法線・深度）を表示できる。

**やること**
- 描画先を 2 枚作る（色 `R8G8B8A8_UNORM_SRGB`、法線 `R16G16B16A16_FLOAT`）。深度は SRV からも読める形（M8 と同じ）
- 1 パス目：`OMSetRenderTargets( 2, ... )`。ピクセルシェーダは構造体で `SV_Target0`（色）と `SV_Target1`（法線）を返す。ライティングはしない
- 2 パス目：全画面の三角形。色・法線・深度を読む。深度と uv から、射影ビューの逆行列でワールドの位置を戻す。M6 と同じ式でライティングする
- 光の配列（位置と色を 8 個）を定数バッファで渡し、ループで足す
- 深度が 1 の画素（何も描かれていない）は背景の色にする

**確かめ方**：M6 の絵と並べて同じに見える。「戻したワールドの位置」を色として表示して、床の上で色がなめらかに変わるか見る（ここが一番間違えやすい）。

**詰まったら**：`GameSrc/src/Render/Lighting/GBuffer.cpp`、`Resource/Shader/GBuffer.hlsli`・`DeferredLighting.hlsl`・`DepthPosition.hlsli`

**発展**：M5 の半透明の四角を足す。G-Buffer には書けないので、ライティングの後にフォワードで描く。自分のゲームの `SceneRenderer::render` と同じ順番になることを確かめる。

## M10：2 本の骨で曲がる腕

**目標**：縦長の箱（腕）が、真ん中の関節でなめらかに曲がる。

**やること**
- 縦に細かく分割した箱のメッシュを**コードで**作る（高さ 2、縦に 10 段くらい）
- 骨は 2 本。骨 0 は根元（原点）、骨 1 は真ん中（高さ 1）
- 頂点に「骨の番号 4 つ（`uint8_t[ 4 ]`）」と「重み 4 つ（`float[ 4 ]`）」を足す。高さで重みを決める（下は骨 0 に 1、上は骨 1 に 1、関節の近くは混ぜる）
- 各骨の bindInverse（バインドポーズの行列の逆行列）を作る
- 毎フレーム：骨 1 を時間で回す。スキン行列 = 今の姿勢 × bindInverse（DirectXMath の掛ける順に注意）を 2 つ、定数バッファで送る
- 頂点シェーダで、4 本の重み付きで位置と法線を変形する
- 先に課題 07-1（CPU 版）をやっておくと、間違いを切り分けやすい

**確かめ方**：骨 1 を回していないとき、箱が元の形のまま（スキン行列が単位行列になっている）。回すと関節でなめらかに曲がる。重みを 0 か 1 だけにすると、関節が折れた箱になる。

**詰まったら**：`GameSrc/src/Render/SkinnedMesh/SkinnedMeshData.cpp` の `computeSkinMatrices`、`SkinningPipeline.cpp`、`Resource/Shader/Skinning.hlsli`

**よくある失敗**
- 入力レイアウトで、骨の番号を `R8G8B8A8_UINT` にしていない（`UNORM` だと 0〜1 の小数になってしまう）
- bindInverse を掛け忘れて、関節より上が飛んで行く
