# 03 D3D11 の初期化と三角形

DirectX11 の勉強で一番大事な章。ここで出てくる物（デバイス・スワップチェーン・ビュー・シェーダ・頂点バッファ）は、
この先の全部の章で、形を変えて何度も出てくる。**三角形 1 枚を何も見ずに出せる**ようになるまでやる。

## この章でできるようになること

- 空のウィンドウに、D3D11 で三角形を出すプログラムを自分で書ける
- デバイス・コンテキスト・スワップチェーン・ビューが、それぞれ何の役か言える
- 絵が出ないとき、どこから疑うかの順番を持っている

## 言葉の整理

| 言葉 | D3D11 の型 | 何の役か |
|---|---|---|
| デバイス | `ID3D11Device` | **作る**係。バッファ・テクスチャ・シェーダ・ステートは全部ここから作る（`Create〜`） |
| デバイスコンテキスト | `ID3D11DeviceContext` | **使う**係。作った物をパイプラインに付けて（`〜Set〜`）、描く（`Draw`） |
| スワップチェーン | `IDXGISwapChain` | ウィンドウに出す絵（バックバッファ）の持ち主。`Present` で画面に出す |
| バックバッファ | `ID3D11Texture2D` | 描いている最中の絵。スワップチェーンが持っている |
| ビュー | `ID3D11RenderTargetView` など | テクスチャを「何として使うか」の札。描く先として使うなら RTV、深度なら DSV、シェーダから読むなら SRV |
| 入力レイアウト | `ID3D11InputLayout` | 頂点バッファの中身の並び（何バイト目が位置で、何バイト目が色か）を頂点シェーダへ教える表 |

### パイプラインの段と API の頭文字

```
頂点バッファ → [IA 入力アセンブラ] → [VS 頂点シェーダ] → [RS ラスタライザ] → [PS ピクセルシェーダ] → [OM 出力マージャ] → 描画先
                 IASet〜              VSSet〜              RSSet〜              PSSet〜                OMSet〜
```

- IA：頂点バッファから頂点を取り出し、三角形に組む
- VS：頂点 1 つごとに走る。位置を画面の座標（クリップ空間）へ変換する
- RS：三角形を画素に切り分ける。裏面を捨てる・画面の外を切る・ビューポートへ合わせる
- PS：画素 1 つごとに走る。色を決める
- OM：深度テストとブレンドをして、描画先へ書く

> このコードのコメントに出てくる「固定パイプライン」は、D3D11 の機能ではない（D3D11 にはシェーダ無しで描く仕組みは無い）。
> GameLib が最初から持っている内蔵のシェーダ（`NoLightingVsHlsl.h` など）のこと。自分でファイルから読むシェーダ（`Resource/Shader/*.hlsl`）と区別してそう呼んでいる。

## 自分のコードのどこか

ほとんどが [ManagerImpl.h](../GameLib/src/Graphics/ManagerImpl.h) の `ManagerImpl` のコンストラクタにある。上から順に読む。

| やること | 名前（`ManagerImpl.h` の中） |
|---|---|
| スワップチェーンの設定を書く | コンストラクタの `DXGI_SWAP_CHAIN_DESC scDesc` |
| デバイス・コンテキスト・スワップチェーンを作る | `D3D11CreateDeviceAndSwapChain` |
| バックバッファの RTV と、深度の DSV を作る | `createRTVandDSV` |
| シェーダをコンパイルして作る | `compileShader`（`D3DCompile`）→ `CreateVertexShader`・`CreatePixelShader` |
| 入力レイアウトを作る | `D3D11_INPUT_ELEMENT_DESC layout[]` → `CreateInputLayout` |

## 読むときの問い

### デバイスとスワップチェーン

1. `scDesc` の `BufferDesc.Format`・`BufferUsage`・`OutputWindow`・`SampleDesc.Count`・`Windowed` は、それぞれ何を決めているか
2. `featureLevels[]` に 3 つ並べて渡し、`actualLevel` を受け取っている。これは何をしているか
3. `createFlags |= D3D11_CREATE_DEVICE_DEBUG;` は `#ifdef _DEBUG` の中にある。これを付けると何が嬉しいか。Release で付けないのはなぜか
4. `createRTVandDSV` で、`mSwapChain->GetBuffer` で取った `backBuffer` を、RTV を作った直後に `backBuffer->Release()` している。まだ使っているのに、なぜ手放してよいのか
5. 深度のテクスチャは自分で `CreateTexture2D` しているのに、色のバックバッファは作っていない。なぜか
6. `fitBackBufferToWindow` は、`ResizeBuffers` の前に `OMSetRenderTargets( 0, nullptr, nullptr )` と `destroyRTVandDSV()` を呼んでいる。呼ばないとどうなるか

<details><summary>答え</summary>

1. `Format`：バックバッファの 1 画素の形（R・G・B・A が 8 ビットずつ、0〜1 として読む）。`BufferUsage`：描く先として使う。`OutputWindow`：どのウィンドウに出すか。`SampleDesc.Count`：1 画素あたりのサンプル数（1 = MSAA なし）。`Windowed`：ウィンドウで始める（排他フルスクリーンではない）
2. 「この GPU で使える一番上の機能レベルを選んで」と頼んでいる。11_0 が使えればそれ、だめなら 10_1、10_0。実際に選ばれた物が `actualLevel` に入る（`logAdapter` が出力ウィンドウへ出している）
3. D3D11 の呼び方の間違い（付けていない物を使った・型が合わない・解放し忘れ）を、出力ウィンドウに文章で教えてくれる。調べる分だけ遅くなるのと、開発用の部品（Graphics Tools）が入っていない PC では作成に失敗するので、Release では付けない
4. COM のオブジェクトは「参照カウント」で生きている。`GetBuffer` はカウントを 1 増やして返す。`CreateRenderTargetView` で作った RTV が、中でバックバッファを 1 つ参照する。だから自分の分を返しても、RTV が持っている間は消えない。返さないと、カウントが 1 余って最後まで解放されない
5. 色のバックバッファはスワップチェーンが作って持っている（`GetBuffer` で借りるだけ）。深度はスワップチェーンに付いてこないので、同じ大きさの物を自分で作る
6. バックバッファを指すビューが 1 つでも残っていると、`ResizeBuffers` は失敗する。作り直す物への参照を、先に全部手放す必要がある

</details>

### シェーダと入力レイアウト

1. `compileShader` は `D3DCompile` に HLSL の**文字列**を渡している。HLSL はいつコンパイルされているか。失敗するとどうなるか
2. `"vs_4_0"`・`"ps_4_0"`（内蔵）と `"vs_5_0"`・`"ps_5_0"`（`ShaderImpl.h`）は何の指定か
3. `CreateInputLayout` には、`layout[]` のほかに `vsBlob->GetBufferPointer()`（頂点シェーダのバイトコード）を渡している。なぜ頂点シェーダが要るのか
4. `layout[]` の `0, 16, 28, 32` という数は何か。[Vertex.h](../GameLib/include/GameLib/Graphics/Vertex.h) の `Vertex` と見比べて確かめる。1 頂点は何バイトか
5. `"POSITION"`・`"NORMAL"` という文字列は、HLSL のどこと対応するか（[NoLightingVsHlsl.h](../GameLib/src/Graphics/NoLightingVsHlsl.h) か [Common.hlsli](../Resource/Shader/Common.hlsli) の `StandardVertex`）
6. `ShaderImpl.h` の `compile` は、コンパイルした結果を `compiledShaders()` に覚えている。何のためか

<details><summary>答え</summary>

1. ゲームの起動中（実行時）。失敗すると `HALT` でエラーの文章（何行目の何が悪いか）を出して止まる。ファイルから読む方（`ShaderImpl.h`）は止まらず、`mError` に理由を残して、直して保存すれば読み直す（ホットリロード）
2. シェーダの種類（vs 頂点・ps ピクセル）と、シェーダモデルの版。5_0 が D3D11 の標準。4_0 は D3D10 相当で、機能レベル 10_0 の GPU でも動く
3. 入力レイアウトは「頂点バッファの並び」と「頂点シェーダが受け取りたい入力」をつなぐ表。作るときに、シェーダの入力（セマンティクスと型）と合っているかを D3D11 が確かめる。合わなければここで失敗する
4. 頂点の先頭から、その要素が始まるまでのバイト数。位置 `Vector4` が 16 バイト（0〜15）、法線 `Vector3` が 12 バイト（16〜27）、色 `unsigned` が 4 バイト（28〜31）、UV `Vector2` が 8 バイト（32〜39）。1 頂点は 40 バイト
5. HLSL の頂点シェーダの入力の、`: POSITION`・`: NORMAL` という「セマンティクス」。名前で対応を取るので、C++ 側の構造体のメンバー名と HLSL 側の変数名は違ってよい
6. 出撃のたびにシーンが同じシェーダを作り直すので、2 回目からコンパイルを飛ばすため。ロードの時間の半分がコンパイルだった（`ShaderImpl.h` のコメント）

</details>

### 頂点バッファと描画

1. [VertexBufferImpl.h](../GameLib/src/Graphics/VertexBufferImpl.h) の `createDxObject` は `D3D11_USAGE_DYNAMIC` と `D3D11_CPU_ACCESS_WRITE` で作り、`lock` は `Map( ..., D3D11_MAP_WRITE_DISCARD, ... )` している。これはどういう使い方のための設定か。一度作ったら変えない建物のメッシュなら、何が向いているか
2. `drawFromVertex` は `Draw` の前に、`sendMatrices`・`flushConstantBuffers`・`IASetPrimitiveTopology` を呼んでいる。`Draw` を呼んだ瞬間に、GPU は何を使って描くか
3. コンストラクタのラスタライザステートは `FrontCounterClockwise = TRUE`。これは何を決めているか。D3D11 の既定はどちらか
4. `endDraw` の `Present( mVSync ? 1 : 0, 0 )` の 1 と 0 は何が違うか

<details><summary>答え</summary>

1. CPU から何度も書き換える物のための設定。`WRITE_DISCARD` は「前の中身は要らない。全部書き直す」という約束で、GPU が前の中身を使い終わるのを待たずに書ける。変えない物なら `D3D11_USAGE_IMMUTABLE`（か `DEFAULT`）で、`CreateBuffer` に初期データを渡して作るのが向いている。GameLib は全部の頂点バッファを DYNAMIC で作っている（元のライブラリの作りを引き継いでいる）。直すなら、この教材を終えた後の良い題材
2. その時点でコンテキストに「付いている物」全部。入力レイアウト・頂点バッファ・シェーダ・定数バッファ・テクスチャ・サンプラ・各ステート・描画先。D3D11 は状態機械で、`Draw` は「今の状態で描け」という合図でしかない。だから 1 つ付け忘れると、前に付けた物のまま描かれる
3. 頂点が画面で反時計回りに並ぶ面を表にする。D3D11 の既定は FALSE（時計回りが表）。公式のチュートリアルとは逆なので、M2 を書くとき、三角形が出なければ頂点の順を疑う
4. 1 は垂直同期を待つ（モニターの更新に合わせる。ティアリングが出ない）。0 は待たずにすぐ出す

</details>

## 絵が出ないときに疑う順

三角形を初めて書くと、ほぼ必ず真っ黒（か消した色のまま）になる。上から順に確かめる。

1. **出力ウィンドウ**に `D3D11 ERROR` か `D3D11 WARNING` が出ていないか（デバッグレイヤーを付けて作っているか）
2. どの `Create〜` も `HRESULT` を確かめているか（`FAILED( hr )`）。失敗した物は nullptr のまま
3. 描画先を付けたか（`OMSetRenderTargets`）。ビューポートを付けたか（`RSSetViewports`。付けないと幅 0 で何も出ない）
4. 三角形は画面の中か。クリップ空間は x・y が −1〜1、z が 0〜1。w は 1 か
5. 裏面カリングで捨てられていないか（頂点の順を逆にするか、試しに `CullMode = D3D11_CULL_NONE`）
6. ピクセルシェーダは見える色を返しているか（試しに `return float4( 1, 0, 0, 1 );`）
7. `Present` を呼んでいるか
8. それでも出なければ RenderDoc で 1 フレームを撮り、`Draw` の行を選んで、Mesh Viewer（頂点シェーダの出力）と Pipeline State を見る
