# 07 スキニングとアニメーション

キャラクターを骨で動かす。行列の掛け算が何段も重なるので、04 章（行列）が手に馴染んでからやる。
式は 1 行だが、「どの空間からどの空間への行列か」を取り違えやすい。

## この章でできるようになること

- 骨・バインドポーズ・bindInverse・スキン行列が、それぞれ何か言える
- 頂点シェーダで、4 本の骨の重み付きの変形を書ける
- アニメのポーズを作る所と、頂点を変形する所を分けて考えられる

## 式

```
スキン行列[ b ] = 置き場所 × 骨 b の今の姿勢 × 骨 b の bindInverse

変形後の位置 = Σ（ 重み[ i ] × スキン行列[ 骨の番号[ i ] ] × 元の位置 ）     i = 0〜3
```

右から読む。

1. **bindInverse**：頂点を「モデルの空間」から「その骨から見た空間」へ移す。モデルを作ったときの姿勢（バインドポーズ・レスト姿勢）での骨の行列の、逆行列
2. **骨の今の姿勢**：骨から見た空間の点を、アニメで動いた後の骨に付いて行かせて、モデルの空間へ戻す
3. **置き場所**：キャラを世界のどこに・どの向きで置くか

骨がバインドポーズのまま動いていなければ、2 と 1 が打ち消し合って単位行列になる（頂点は動かない）。これが確かめ方にもなる。

## データの流れ

```
アニメのファイル ─▶ AnimationPlayer ─▶ ポーズ（骨ごとの行列。モデルの空間）
                                          │ BonePoseModifier が書き換える（背骨を曲げる・腕を置き直す）
                                          ▼
                    computeSkinMatrices ─▶ スキン行列（骨ごと。置き場所 × 姿勢 × bindInverse）
                                          │ SkinningPipeline::begin が定数バッファ b1 へ
                                          ▼
頂点バッファ（全員で共有・レスト姿勢）─▶ VSMain ─▶ 変形後の頂点
```

頂点バッファは 1 体ぶんを全キャラで共有し、**骨の行列だけ**を体ごとに送る。ゾンビが 50 体いても頂点は 1 体ぶん。

## 読むときの問い

### 式と行列

1. `computeSkinMatrices` は `skinMatrices[ b ].setMul( root, bonePose[ b ] ); skinMatrices[ b ] *= mBones[ b ].mBindInverse;` と書いている。頂点に最初に効くのはどれか。04 章の「列ベクトル」の決まりで確かめる
2. bindInverse は、ロードのときに 1 回だけ作っている。毎フレーム作らなくてよいのはなぜか
3. `SkinnedMeshData::draw` は、ワールド行列を単位行列にしている（`world.setIdentity()`）。キャラの置き場所はどこへ行ったか
4. `SkinnedMeshInstance::boneMatrix`（手に持った銃を置くのに使う）は `rootMatrix() × mShownPose[ boneIndex ]` で、bindInverse を掛けていない。なぜスキン行列と違うのか

<details><summary>答え</summary>

1. bindInverse。式は `置き場所 × 姿勢 × bindInverse × 頂点` で、右に書いた物が先に効く
2. バインドポーズ（モデルを作ったときの骨の姿勢）はモデルごとに決まっていて、変わらないから。アニメで変わるのは「今の姿勢」だけ
3. スキン行列の中に入っている（`root`）。頂点シェーダは骨の行列を掛けただけでワールドの位置になるので、もう一度ワールド行列を掛けると二重になる。`Skinning.hlsli` のコメント「gTransform = 射影×ビュー」
4. スキン行列は「レスト姿勢の頂点」を動かすための物なので、先に骨の空間へ移す bindInverse が要る。`boneMatrix` は「骨そのものが今、世界のどこにどの向きであるか」が欲しいだけ。骨の空間の原点に物を置けば手に付いて行く

</details>

### 頂点シェーダと定数バッファ

1. `cbuffer BonePalette` は `float4 gBoneRows[ MAX_BONES * 3 ]`。骨 1 本を 4×4 ではなく 3 行（3×4）で送っている。なぜか。128 本で何バイトか
2. `skinPoint` と `skinVector` は何が違うか。法線に `skinPoint` を使うと何が起きるか
3. 頂点の `bones` は `uint4`（`DXGI_FORMAT_R8G8B8A8_UINT`）、`weights` は `float4`。骨の番号が 8 ビットだと、骨は最大いくつか。`MAX_BONES` が 128 なのは別の理由。何か
4. 4 つの重みの合計が 1 でないと、頂点はどうなるか。骨が 1 本しか効かない頂点は、残りの 3 つの重みをどうしておくか
5. `VSMain` の `[unroll]` は何の指定か
6. `SkinningPipeline::begin` は、パス（色・G-Buffer・影）ごとに違うシェーダを選んでいる（`currentShader`）。3 つのシェーダで共通なのはどこで、違うのはどこか（`SkinnedMesh.hlsl`・`SkinnedMeshGBuffer.hlsl`・`SkinnedMeshShadow.hlsl` はどれも数行しか無い）

<details><summary>答え</summary>

1. 骨の行列は回転・拡大・平行移動だけで、4 行目はいつも `( 0, 0, 0, 1 )`。送るだけ無駄。3 行なら 48 バイト × 128 本 = 6144 バイト。4 行だと 8192 バイト
2. `skinPoint` は位置用で、平行移動も掛ける（`float4` の w = 1 と内積）。`skinVector` は向き用で、3×3 の部分だけ掛ける。法線に平行移動を足すと、向きではなくなる
3. 番号は 0〜255 まで表せる。128 は「定数バッファの大きさ」と「1 体のモデルの骨の数」の兼ね合いで決めた上限（`SkinningPipeline.h` の `kMaxBones` と揃える）。超えたら `ASSERT` で止まる
4. 合計が 1 より小さいと頂点が原点の方へ縮み、大きいと外へ膨らむ（行列の重み付きの和なので）。効かない骨は重み 0 にしておく（番号は何でもよい。0 を掛けるので）
5. ループを展開して、4 回ぶんをそのまま並べたコードにする指定。回数が決まっている短いループは、展開した方が速い
6. 共通なのは頂点シェーダ（`Skinning.hlsli` の `VSMain`）。違うのはピクセルシェーダだけ。「変形は 1 か所に書き、出す先だけ差し替える」形

</details>

### アニメと 1 体ぶん

1. `SkinnedMeshInstance::draw` は `mSkinStale` が true のときだけ `computeSkinMatrices` を呼ぶ。1 フレームに同じ体を何回描くことがあるか。この工夫で何が減るか
2. `SkinnedMeshInstance::update` は、アニメのポーズ（`mPlayer.pose()`）を直接書き換えず、`mBodyPose`・`mShownPose` へ写してから書き換えている。直接書き換えると何が起きるか（コメントにある）
3. クロスフェード（歩き → 走りなどの切り替え）で、行列の成分をそのまま線形に混ぜず、四元数の slerp を使う理由は（`MatrixBlend.cpp`）
4. アニメは 60 ティック／秒の `update` で進む。144Hz で描いたとき、キャラの動きは何 Hz で変わるか（02 章の話）

<details><summary>答え</summary>

1. G-Buffer に 1 回と、影のマップに最大 4 回（懐中電灯 1 枚＋月の 3 枚）。ポーズが同じなら骨の行列も同じなので、作るのは 1 回で済む
2. クロスフェードの混ぜ元に書き換えた後のポーズが入り込み、混ぜた後にもう一度書き換えが掛かって二重になる
3. 回転行列どうしを成分ごとに混ぜると、途中の行列は回転行列でなくなる（軸が直交しなくなり、縮む）。回転は四元数にして球面上で混ぜれば、途中も正しい回転のまま・一定の速さで回る
4. 60Hz。描画の補間をしていないので、描く回数が増えても動きは細かくならない

</details>

D3D11 を使わず、コンソールで。

- 骨 A は原点、骨 B は `( 0, 1, 0 )`（A の子）。頂点は `( 0, 0.5, 0 )`・`( 0, 1.0, 0 )`・`( 0, 1.5, 0 )` の 3 つ
